# 内容运营操作手册

## 先看这里：内容运营实际只做什么

正常情况下，内容运营只需要完成以下动作：

1. 第一次建立项目时，提供项目基础信息、客户资料路径和Obsidian路径。
2. 每周提交文章关键词、标题、大纲和其他要求。
3. 查看`10_待提交资料清单与就绪检查.md`，只提交Codex点名的PDF/PPT Markdown稿、网页Web Clipper稿或音视频转写稿。
4. 查看`15_提取范围与处理样本确认.md`，一次确认资料范围、官网覆盖和代表处理样本。
5. 查看`20_文章前知识审核.md`，只处理其中列出的缺口、冲突、企业事实或公开风险。
6. 把`30_文章写作输入.md`交给写文章Skill，写完后提交最终文章和引用率。

其余扫描、附件检查、资料处理、外部调研、独立审核、归类、正式知识沉淀、引用记录和月度汇总由Codex完成。内容运营不需要反复打开后台证据文件，也不需要决定知识最终放在哪个目录。

## 正常操作顺序

### 1. 第一次建立项目

直接提供：

```text
请建立知识库项目。
项目中文名称：
项目英文名称：
运营组：
内容运营负责人：
官网：
行业：（可以留空，由Codex根据官网填写）
客户源文件材料路径：
Obsidian项目路径：
```

除行业外，其余字段都需要填写。行业留空时，Codex会根据官网内容填写并标明判断依据；官网不足以判断时会标记为“未确认”，不会自行编造。

收到信息后，Codex会自动扫描，不再询问“是否扫描”或让你选择浅扫描、深扫描。扫描完成后会生成源文件总表、内容导航和不打分的项目基础情况，列明七个知识模块现有什么、缺什么，以及哪些材料可以向客户索取。

客户源文件和客户官网都是可信的客户一手来源，二者并列，官网不会自动高于或覆盖源文件。来源可信不等于允许公开；涉及保密、客户名称、价格、认证、效果或承诺时，仍会单独检查公开风险。

Codex会检查Word、PPT、Excel中的嵌入附件和关键图片。纯装饰图不会进入知识正文；附件图标、关键截图、流程图、复杂表格和图表即使没有连续文字也会登记并判断，避免漏掉真正承载内容的图片或内嵌文件。

### 2. 每周提交单篇或多篇文章需求

```text
请准备本周文章。
关键词：
标题：
大纲：
其他要求：
```

其他要求可以填写目标语言、受众、页面类型、语气、禁写内容等。

一次提交多篇时，按文章逐项填写，例如：

```text
请准备本周以下文章。

文章1
关键词：
标题：
大纲：
其他要求：

文章2
关键词：
标题：
大纲：
其他要求：
```

Codex会为每篇分配独立文章ID并建立独立任务，不把多篇文章合并成一个写作输入。批次状态统一汇总到项目的`01_工作台/20_当前待办.md`；相同源文件、网页或调研只处理一次，再由相关文章分别引用。

互不依赖的文章可以同时准备。一篇文章缺资料时，只暂停该篇和依赖同一资料的文章，不影响其他文章。多个文章需要确认同类事项时，Codex可以集中展示，但你仍需按文章或具体范围分别确认。

Codex会依次查找：

1. 已经沉淀的正式知识；
2. 客户源文件和客户官网中尚未提取的相关内容；
3. 已有但尚未正式沉淀的外部调研；
4. 仍有真实缺口时才开展新的外部调研。

文章大纲用于判断相关性和覆盖需求，不能代替源文件自身的提取范围。

## 四类Agent在后台分别做什么

| 角色 | 负责内容 | 内容运营通常是否直接沟通 |
|---|---|---|
| 主Agent | 接收文章需求、查找资料、列待提交清单、调度其他Agent、汇总审核、生成写作输入和正式落库 | 是。正常只与主Agent沟通 |
| 资料处理Agent | 对照客户原文件、官网和运营提交稿，完成提取、翻译、表格与结构整理 | 否。发现异常后由主Agent统一说明 |
| 调研Agent | 只在本地资料处理后仍有真实公开知识缺口时调研，并保存网页/文章原文和整理稿 | 否。开始调研前由主Agent通知 |
| 审核Agent | 独立检查漏页、内嵌附件、官网第二页或隐藏内容、复杂图表误读、来源冲突和大纲覆盖 | 否。需要人工决定时由主Agent统一提出 |

多个Agent意见一致不代表内容一定正确。范围完整性、代表样本和高风险内容仍以原文件证据和规定的人工确认为准。

### 3. 按清单补齐待提交资料

Codex会把清单保存到文章任务的`10_待提交资料清单与就绪检查.md`，只列出本篇必须由内容运营提交的项目。例如：

```text
请提供：
1. 产品手册PDF的Markdown提取稿（推荐MinerU）；
2. 案例PPT及其内嵌PDF的Markdown提取稿；
3. 指定动态网页的Web Clipper稿；
4. 访谈视频的带时间码转写稿。

请放到：
[具体目录]
```

本篇范围内的PDF和PPT都需要内容运营提交Markdown提取稿，推荐使用MinerU；同一文件同一版本的合格稿可以复用，不必为每篇文章重复生成。Codex会结合原文件核验页码、结构、数字、表格、图片和明显错漏。网页只有在Codex无法稳定取得、动态内容容易丢失或需要固定证据时才会点名要求Web Clipper稿，不要求你为整个官网逐页制作。进入知识库后只显示`Codex提取`和`运营提交`，不会出现单独的MinerU目录。

提交时注意：

- PDF/PPT原文件和Markdown稿都要保留，不能只交Markdown稿；
- Markdown稿名称应能对应原文件，建议使用`原文件名_提取稿.md`；
- 同一文件有新版本时要说明版本或日期，不能用旧稿静默对应新文件；
- Word等文件内嵌的PDF/PPT会作为独立子资料列出，也需要各自的Markdown稿；
- Web Clipper只提交清单点名的具体页面，并保留页面标题和原始URL；
- 不要先自行润色、概括或删减原始提取稿。

提供后可以直接回复：

```text
文章ID：[文章ID]
清单中的资料已提交。
新增文件：
1. 
2. 
版本或特殊说明：
```

你不需要自己从全部资料中判断还缺哪些文件。Codex核验后会明确回复“已就绪”或指出哪一项仍不对应、不完整或不可用。

### 4. 确认提取范围与处理样本

阅读文章任务中的`15_提取范围与处理样本确认.md`，重点检查：

- 是否选对文件或网页；
- 是否选对章节、页码、PPT页、工作表、时间段或网页区块；
- 网页是否附有页面标题和可以直接打开的具体页面链接；
- 范围说明是否符合原文实际内容；
- 有没有漏掉明显相关部分；
- 有没有不应该处理或不允许公开的内容；
- 官网类别数量、第二页、加载更多、标签页或折叠内容是否列全；
- Word等文件的内嵌附件是否已经列出；
- 每类复杂表格、流程图、图表或关键截图的代表处理样本是否解读正确。

内容运营在这一步一次确认“范围是否完整”和“代表样本的处理方法是否正确”，不需要逐页复核后续同结构内容，也不需要决定知识最终存放在哪个文件夹。

回复确认或指出具体修改。确认后，资料处理Agent批量完成批准范围内的提取、核验、翻译和结构整理，审核Agent独立查漏查错；如仍有真实公开知识缺口，Codex会先告诉你准备调研什么，再由调研Agent继续。不会增加独立的派生处理确认或沉淀位置确认。

全部确认时可以回复：

```text
文章ID：[文章ID]
确认提取范围和代表处理样本，可以继续。
```

需要修改时不要只回复“不对”，请指出具体对象：

```text
文章ID：[文章ID]
修改后确认：
1. 官网产品类别漏了[类别名称/页面]；
2. [样本组ID]中的流程箭头应解释为……；
3. [资料ID]第X页不应提取，原因是……。
其余范围和样本确认。
```

### 5. 收到外部调研通知时怎么处理

只有正式知识、客户源文件、客户官网和已有外部调研仍不能覆盖文章主张时，Codex才会开始新的外部调研。开始前，主Agent会一次说明：

- 缺的是哪部分知识；
- 为什么现有资料无法覆盖；
- 调研Agent准备查什么、优先查哪些类型的来源；
- 哪些结果只能作为行业知识，不能用来证明客户自身能力。

这是进度通知，不是逐链接审批。正常公开调研时，内容运营不需要回复，Codex会继续处理。

以下情况才需要回复或补充材料：

- 调研会实质改变文章大纲或核心主张；
- 缺的是客户自身参数、能力、案例、认证或承诺，外部来源不能代替；
- 页面需要登录、付费或公司授权访问；
- 权威来源冲突会改变文章结论；
- 来源可靠性、时效性或公开边界无法确定。

外部调研不是只保留Codex总结。每个采用的网页或文章分别保存：

```text
10_网页或文章原文.md
20_调研整理与核验.md
```

前者保存当前授权下能够取得的可见原文、直达URL、机构、日期和未取得范围；后者才保存Codex整理、翻译、可支持结论和使用限制。只能取得摘要或片段时会标记“原文不完整”，不能扩写成完整结论。

### 6. 做文章前知识审核

Codex完成资料处理后，阅读文章任务中的`20_文章前知识审核.md`，重点处理：

- 大纲各部分是否真的有知识支持；
- 客户资料中没有来源的企业事实；
- 参数、日期、型号、单位、版本或案例冲突；
- 客户名称、案例、价格、认证、效果、承诺等公开风险；
- 外部来源不可靠或已经过期；
- 无来源推断以及需要删除或修改的大纲主张。

审核结论只使用：

- 可以进入写作；
- 处理指定问题后可以进入写作；
- 暂不能进入写作。

处理完受影响问题后，只重新审核受影响部分，不从头重跑全部流程。审核通过后，Codex生成`30_文章写作输入.md`。

### 7. 把写作输入交给写文章Skill

在写文章Skill中另行填写关键词、标题、大纲、语气和其他写作要求，然后只上传：

```text
30_文章写作输入.md
```

它是只服务当前文章的知识库附件，包含本篇获准使用的目标语言知识、来源定位、数据日期和必要使用边界。

有翻译时，默认只放经过核验的目标语言版本，不重复放中文原文。复杂参数表或对比表保留为目标语言Markdown表格，并附不增加新事实的简短写作说明；数字、型号、单位、限定条件和对应关系不得丢失。

源文件、中文原文、完整原表、Codex提取、运营提交稿、整理稿、正式知识和审核记录继续留在后台用于追溯与返工，不需要逐个上传给写文章Skill。

### 8. 完成文章后提交终稿

```text
最终文章标题：
最终文章正文：
该篇文章引用率：
发布URL：（如有）
```

提交最终标题、完整正文和引用率后，会自动触发文章引用清单、知识块使用记录、引用率明细、知识沉淀和月度数据更新，不需要再说“请沉淀”或“请更新使用情况”。

多篇终稿可以在同一条消息中提交，但每篇必须标明文章ID，并分别提供完整正文和该篇引用率。Codex会逐篇闭环；某一篇处理失败时，不会把整批标记为完成。

### 9. 查看自动闭环结果

正常情况下，只需查看文章任务中的`40_最终文章与引用率.md`。其中的“Codex自动闭环结果”会明确列出：

- 文章引用清单是否生成；
- 知识块使用记录是否更新；
- 引用率是否登记；
- 新建或更新了哪些正式知识；
- 是否有外部知识待决定；
- 是否有企业知识异常；
- 文章任务是否已经关闭。

已有正式知识被本篇文章使用时，只记录使用情况，不重复生成正式知识文件。只有出现可追溯、可复用并且脱离本篇文章仍然成立的新知识，才会新建或更新正式知识。没有新增正式知识是正常结果，不代表沉淀失败。

正式知识按稳定公司主题、SPU/型号、解决方案、案例、政策或行业主题维护，不按文章标题、本篇选品组合、提取批次或单个网页任务建文件。价格、库存、阶梯价等时效性数据进入动态快照，不混入稳定正式知识。

## 平时去哪里查看

内容运营日常主要查看：

- 缺资料时查看当前文章任务中的`10_待提交资料清单与就绪检查.md`；
- 当前文章任务中的`15_提取范围与处理样本确认.md`；
- 当前文章任务中的`20_文章前知识审核.md`；
- 交给写文章Skill的`30_文章写作输入.md`；
- 提交终稿后的`40_最终文章与引用率.md`；
- `05_数据与审核/01_检查入口/`中的当前待办和异常。

如需查看正式知识，从`02_正式知识/01_正式知识目录/01_正式知识目录.md`进入。它是唯一正式知识入口。

来源证据、翻译整理稿、项目资料稿、CSV使用明细和沉淀记录主要由Codex、知识库专员和月度审核使用。没有异常时，内容运营不需要逐个打开或人工核对这些后台文件。

## 哪些事情不需要内容运营做

- 不需要遍历全部客户资料判断应该提交什么；
- 不需要为所有PDF/PPT逐页人工复核，只需提交Markdown稿并确认代表样本；
- 不需要为整个官网制作Web Clipper，只提交Codex点名的具体页面；
- 不需要逐个批准外部调研链接；
- 不需要判断知识应沉淀到正式知识的哪个模块；
- 不需要在派生处理后再次确认一次；
- 不需要手动更新引用清单、知识块使用记录或月度统计；
- 不需要因为本篇没有新增正式知识而返工。

## 月底做什么

Codex自动生成月度维护简报并保存到`05_数据与审核/50_月度维护/`。内容运营只需要查看问题和未闭环行动。简报不打分，发现几项问题就记录几项。

## 换负责人时做什么

告诉Codex原负责人、新负责人和生效日期。Codex在`05_数据与审核/60_项目交接审核/`生成交接审核，双方确认项目路径、当前文章任务、缺少的提取稿、待处理异常和最近维护问题即可，不重新审核全部历史知识。

## 哪些情况会额外找内容运营

只有异常导致Codex无法安全继续时，才会增加临时人工处理：

- 文件无法读取，或运营提交稿、转写稿与原文件不对应；
- 网页登录、付费、反爬或正文无法可靠提取，需要Web Clipper；
- 官网数量无法闭合、关键交互无法确认，或出现未覆盖的新结构；
- 复杂图表/流程关系存在多种合理解读，代表样本无法定案；
- 企业事实没有客户来源；
- 权威来源或客户来源之间存在实质冲突；
- 动态数据已经过期；
- 内容公开权限不明；
- 最终文章无法匹配文章任务，或引用率格式错误。

Codex必须说明具体文件或页面、受影响范围、原因以及内容运营需要提供什么，不得只说“请人工确认”。
