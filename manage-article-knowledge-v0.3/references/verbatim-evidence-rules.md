## 1. 目标与内容类型

在不改动客户原始文件的前提下，生成能够逐段回到原文件核对的证据。适用于PDF、PPT、Word、Excel、图片、视频、音频、客户官网、外部网页、微信公众号和运营提交稿。

| 类型 | 含义 | 能否称为客户原话 |
|---|---|---|
| `verbatim` | 可靠文本层直接复制，未改写 | 可以 |
| `ocr-verbatim` | OCR结果，保留识别误差风险 | 完成必要核验后可以 |
| `source-original-english` | 来源本身的英文原文 | 可以 |
| `source-normalized-english` | 对客户英文源文作不改变含义的拼写、语法、标点或措辞规范化，并逐项映射原文 | 不可以 |
| `table-structure-preserved` | 保留原始行列关系的表格副本 | 核验后可以作为结构化原文 |
| `cleaned-transcript` | 基于原始逐句稿的清理版 | 不可以 |
| `translation` | 原文忠实翻译 | 不可以 |
| `table-translation` | 表格忠实翻译 | 不可以 |
| `structured-source-derivative` | 可逐字段回溯的机械结构化稿 | 不可以 |
| `summary` | 摘要或归纳 | 不可以 |
| `inference` | 根据资料作出的推断 | 不可以 |

不得用“忠于原意”“大意如下”等说法把改写结果冒充原话。

## 2. 原始资料保护

- 原文件保留在用户指定的稳定源文件路径，不原地编辑、另存覆盖或改变格式。
- 登记资料ID、显示名称、原始文件名、相对路径、大小、修改时间和SHA-256或等效指纹。
- 转换稿、OCR稿、Markdown证据、转写稿和翻译稿使用独立路径并指回资料ID。
- 同名不同内容按版本管理，不自行删除旧版。
- 密码、损坏、缺页或版本不明先登记异常，不声称已经完整提取。
- `已登记`、`已提取`、`已核验`和`可公开使用`是不同状态，不得互相代替。

客户明确禁止使用的内容不得复制到Obsidian的来源稿、派生稿、写作输入或正式知识。只记录不含敏感正文的排除状态、来源范围和需要清理的位置；发现已存在正文时立即停止使用并报告，不擅自删除。

## 3. 最小完整语义块与标题子树

按能够独立理解、引用和核对的最小完整语义块提取，不按固定字数切断句子、条件、步骤、表格或上下文。

有明确标题时，默认提取所选最小有意义标题的完整“标题子树”：

- 从所选标题开始；
- 包含其下全部相关下级标题和正文；
- 到下一个同级或更高级标题之前结束；
- 保留原标题、原顺序和父子层级；
- 不把四级、五级标题拆成互不关联的小稿；
- 不擅自提升、压平或重新挂接标题。

技术容器需要增加文件总标题时，可以让整棵标题子树等量下移，但必须记录原始标题路径和原始级别。确需单独提取下级标题时，必须保证它语义完整，并保留完整父级路径和必要上下文。

没有标题时，至少提取一个完整段落；同一意思跨越多个连续段落时共同组成一个证据单元。结构化资料使用：

- 表格：表名或所属标题、完整表头、相关完整行、单位和脚注；
- FAQ：问题和完整回答；
- 列表：所属标题、必要引导句和完整列表项；
- PPT：幻灯片标题和相关完整内容块；
- 网页字段：页面或产品名称、上级栏目、字段名和字段值；
- 视频/音频：表达完整意思的连续时间段、说话人和时间码。

只有独立定义、独立条款、完整参数、术语字段、原生列表项或客户独立答复，才允许单句或字段级提取。即使使用例外，也保留对象、适用条件、上级标题和精确位置。

## 4. 证据单元字段

```markdown
### EV-0001｜[人能看懂的证据标题]

- 资料ID：
- 资料显示名称：
- 原始文件名：
- 原始资料相对路径或URL：
- 文件版本/指纹：
- 精确位置：
- 原始标题路径：
- 原始标题级别：
- 提取单元：标题子树 / 连续段落 / 完整表格行 / 其他
- 范围结束：
- 内容类型：
- 原始语言：
- 提取工具与版本：
- 提取方式：
- 核验状态：
- 公开状态：

[保留原始标题、顺序、正文、列表或表格。]
```

必要时增加上下文、OCR置信和人工修订说明、型号、单位、冲突、适用文章及单句/字段例外理由。疑似原文错误写在证据正文之外，不在引用块中修正语法、标点、单位或营销表述。逐字内容含`%%`、Wikilink、HTML标签或其他可能触发Obsidian/Markdown解析的控制语法时，改用`text`围栏代码块原样保存；不得把裸露的`%%`放在普通段落、引用块或表格中。

## 5. 不同资料类型的定位

| 类型 | 必填定位 |
|---|---|
| PDF | 资料ID、文件名、相对路径、PDF文件页码；有印刷页码时同时记录并区分 |
| PPT | 资料ID、文件名、相对路径、幻灯片编号和页面标题 |
| Word | 资料ID、文件名、相对路径、可见标题起止范围或开头文字 |
| Excel/CSV | 资料ID、文件名、相对路径、Sheet、单元格范围和表头路径 |
| 含文字图片 | 资料ID、文件名、相对路径、图片编号或文字区域 |
| 网页/微信文章 | 页面标题、发布主体、URL、发布/获取日期和正文小节 |
| 视频/音频 | 资料ID、文件名、起止时间、说话人；有配套PPT时增加幻灯片 |

Word程序段落序号不得称为页码。它只可作为后台辅助定位，并标记`非Word页码，仅供Codex复查`。只有固定渲染版本后才能写`渲染页码`，同时记录渲染文件或日期。

## 6. 表格、图表与图片

### 表格

- 原表或原页面始终是权威证据。
- 简单表格可生成Markdown副本，但保留页码或单元格范围。
- 多层表头、合并单元格、超宽表和参数矩阵不得只转成长段文字。
- 标准化时重复上层表头，使每个数值拥有完整的“对象—字段—数值—单位”路径。
- 解释性文字标记为`summary`，不能替代原表。

### 图表

- 保留标题、图例、坐标轴、单位、数据标签和来源位置。
- 无法可靠读取具体数值时，只记录可以视觉确认的关系并标记待核验。
- 不根据曲线、柱形或趋势自行补出精确数值、因果或结论。

### 图片

- 图片先分类为装饰图、附件图标、信息截图或复杂图示。纯装饰图不建立正文证据，只保留排除结论；附件图标必须追查并登记其嵌入子文件。
- 信息截图以及含文字、参数、表格、流程、图表、空间关系或证书内容的复杂图示进入证据处理；即使没有连续文字也不能直接跳过。
- OCR只提取实际可见文字；流程箭头、图例、坐标、颜色映射、行列关系和空间关系另行记录为`视觉关系`，不得伪装成逐字原文。
- 每类复杂结构先保存一个代表样本的原图定位、转写结果和关系说明，人工确认后才向同结构同版本复用。
- 人物身份、地点、图片含义和公开权限不明时分别标记，不凭画面猜测。

## 7. 质量核验与抽样

必查：

- 文件、版本和范围正确；
- 标题子树、段落、列表和表格完整；
- 没有漏行、乱序、跨栏串行或字段错位；
- 数字、型号、单位、小数点和脚注一致；
- OCR没有混淆相似字符；
- 来源可以实际打开并定位；
- 逐字内容中的Obsidian/Markdown控制语法已放入围栏代码块，不会把后续正文误解析成注释、链接或HTML；
- 异常记录中的保存原文证据、原始来源和现场截图/原页链接可以实际打开，并定位到记录所引用的逐字原文或原始结构；
- 原文、翻译、摘要和推断标签正确；
- 失败范围没有被标记为完成。

抽样规则：

- 普通文本至少检查开头、中部、结尾和所有高风险事实；
- 参数、型号、表格或OCR密集时提高抽查比例，关键参数逐项核对；
- 发现系统性错误时停止扩大范围，先更换方法并重新验证样例；
- 不用“看起来通顺”代替与原文件核对。

失败范围标记`不完整，不作为当前可用原文`。可靠的独立部分可以继续，失败部分不得进入正式知识候选、写作输入、正式知识或文章前审核。

进入源文与事实异常台账时，失败范围仍保存实际取得的逐字文本或原始结构及必要上下文，并明确标记证据完整性；不得把残缺证据改写成完整句。异常记录只复制足以复核问题的最小完整现场，权威原文仍保存在证据层。若问题依赖表格、公式、版面、颜色、箭头、截图或其他视觉关系，必须链接原页或现场图。客户明确禁止保存的正文除外，此时只记录不含敏感正文的排除状态、精确位置和禁用依据。

## 8. 运营提交稿与音视频稿

运营提交的Markdown、Web Clipper稿、人工复制稿、逐句稿、MinerU稿或其他工具输出统一归入`运营提交`并先原样保存，不得原地清理，不按工具名称另建目录。记录：

- 原文件或URL；
- 提供者；
- 工具、版本和方法；
- 覆盖范围；
- 运营初检状态；
- Codex是否取得原始来源；
- Codex核验状态。

未完成必要核验时标记`operator-supplied-unverified`。只有能回到来源并核验后，相关片段才升级为`verbatim`或`ocr-verbatim`。

视频/音频原始稿保留句序、字幕行、时间码和不确定标记。删除口头语、合并重复、调整残句或修正识别错误后的版本另存为`cleaned-transcript`；重要修订记录原句、修订、时间码和依据。

## 9. 允许和禁止的转换

允许：

- 增加资料ID、来源属性和定位标题；
- 在原文之外生成翻译、摘要和说明；
- 在含义唯一时生成独立`source-normalized-english`，并保留逐项原文映射与修正记录；
- 生成可回溯的表格或结构化副本；
- 修复OCR结果，但保留修订和核验记录；
- 建立独立的`cleaned-transcript`。

禁止：

- 把润色稿覆盖到证据正文；
- 静默补齐缺字、单位、参数或句子；
- 把不自然的客户英文直接认定为机器翻译，或假定存在未取得的中文原文；
- 在规范化英文中修复事实、补单位、重建公式、补齐残缺法规或裁决冲突；
- 把翻译或清理稿称为客户原话；
- 为降低“AI度”伪造客户表述；
- 只保留AI改写版而删除原始证据；
- 无法核对时声称“逐字准确”。

## 10. 完成标准

高保真提取完成必须同时满足：

1. 原始文件存在并登记指纹；
2. 提取范围已经在固定人工节点4确认；
3. 证据单元符合最小完整语义块和标题子树规则；
4. 类型、工具、版本、方式和定位已记录；
5. 数字、型号、表格、OCR及高风险事实完成必要核验；
6. 失败、冲突、低置信和未处理范围已列出；
7. 原始稿、字段统一稿和派生稿没有互相覆盖；
8. 运营提交稿记录提供者、来源、范围和核验状态；
9. 客户禁用内容未复制到知识库处理层；
10. 残缺结果没有被标记为完成。
11. 实质异常具有可点击原文现场证据、逐字/原样摘录、精确位置、必要上下文和证据完整性；视觉/结构异常另有原页或截图。
