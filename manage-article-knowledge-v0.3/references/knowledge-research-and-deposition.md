## 1. 固定检索优先级

每篇文章按以下顺序查找：

1. 正式知识；
2. 客户源文件与客户官网中尚未提取的相关部分；
3. 已有但未正式沉淀的外部调研；
4. 新的外部调研。

客户源文件与客户官网同属可信的客户一手来源，二者并列，官网没有更高的默认优先级。按内容相关性、版本日期、详细程度和适用场景选用；发生冲突时并列记录依据、日期和差异，不自动用官网覆盖源文件。来源可信性与内容公开权限分开判断。

前一层能够满足需求时，不为同一事实重复处理下一层。已有外部调研再次使用前检查来源、日期、适用范围和与客户资料的冲突。

## 2. 真正缺口判断

以下情况不是知识缺失：

- 相关客户文件尚未处理；
- Codex尚未完成可靠提取，或必要的运营提交稿尚未提供；
- 已定位页面尚未按确认范围提取；
- 已有外部调研尚未重新核验。

只有本地候选完成必要处理后仍不能支持文章主张，才标记真实缺口。把缺口区分为：

- 客户专属事实：只能向客户源文件、客户官网或客户确认获取；
- 公开行业知识：可以外部调研；
- 可删除或改写的文章主张：不必为了大纲形式强行补知识。

## 3. 自动外部调研

真实缺口出现后，主Agent先按文章或批次向用户发送一次可见的非阻塞通知，至少说明：

- 哪些大纲主张仍有真实缺口；
- 为什么正式知识、客户资料、客户官网和已有外部调研不能覆盖；
- 调研Agent准备回答的问题、优先来源类型和时间范围；
- 调研结果只支持公开行业知识，不能替代客户来源证明企业事实。

通知后正常公开调研继续执行，不需要用户逐链接批准。只有调研会实质改变大纲、涉及企业专属事实、需要登录/付费授权、权威来源冲突、来源可靠性不足或公开边界不明时，才暂停受影响部分请求决定。

随后由调研Agent：

1. 搜索原始机构、官方标准、政府、研究机构、权威行业组织、原始企业页面或可靠专业媒体；
2. 打开真实直达页面；
3. 记录页面身份、发布/更新日期、访问日期和能支持的具体内容；
4. 自动提取依法且在当前授权下可取得的可见正文；
5. 分别保存原文证据稿和研究整理稿，禁止只保存Codex总结；
6. 对动态信息标记数据日期；
7. 把相关结果纳入文章前知识审核。

不要求内容运营逐链接选择是否纳入。登录、付费墙、反爬、脚本渲染失败、页面损坏或正文无法可靠取得时，请运营使用Web Clipper、下载文件或复制其有权访问的可见正文，并给出明确提交位置。

每个调研来源按稳定调研ID保存两层文件：

```text
04_资料与证据/50_外部调研/[调研ID]/
├── 10_网页或文章原文.md
└── 20_调研整理与核验.md
```

`10_网页或文章原文.md`至少记录页面标题、发布机构、直达URL、发布/更新日期、访问日期与时间、获取方式、语言、访问限制、内容指纹、已取得可见正文和未取得范围。正文按来源顺序原样保存，不在该文件内清理、翻译、总结或补齐。只能取得摘要或片段时标记`原文不完整`，不得把摘要扩展为全文结论。

`20_调研整理与核验.md`记录来源可支持和不能支持的主张、数据日期、冲突、使用限制、清理/翻译/结构化过程及最终去向。整理稿中的每项结论必须定位到原文证据；原文证据缺失时只能保留为未核验候选，不能进入写作输入或正式知识。

## 4. 来源质量与事实边界

- 来源优先顺序通常为：原始官方页面或文件；政府、标准机构、研究机构；权威行业组织；能够定位作者、日期和原始依据的专业媒体。后一层不能无说明地替代可取得的前一层。
- 每个实质性来源记录页面或文件名称、发布机构、发布或更新日期、直达URL、访问日期、它能够支持的结论和不能支持的范围。
- 网页或文章原文证据与Codex整理稿必须分开保存；链接、标题或摘要不能替代取得的正文证据。
- 搜索结果页、聚合页、无署名转载、AI回答和无法定位原文的摘要不能作为正式知识来源。
- 不绕过登录或付费限制；只能取得公开摘要时，明确记录信息不完整，不把摘要扩写成全文结论。
- 对价格、市场规模、政策、法规、趋势等动态信息优先使用较新来源；使用较旧材料时记录原因和数据日期。
- 高相关但被排除的候选来源，如果会影响审核判断，应记录排除原因，避免后续重复调查。
- 外部来源可以支持行业背景，不能证明客户自身能力、参数、案例、认证、价格或承诺。
- 与企业自身有关但没有客户来源的主张，不得写成企业知识。
- 无可靠来源或只是AI推断的内容不沉淀。
- 权威来源冲突时并列记录来源、日期和差异，不自行合并成一个确定事实。
- 动态数据可以沉淀，但必须标明数据日期和复核条件。

## 5. 知识沉淀矩阵

| 内容 | 写作后处理 |
|---|---|
| 客户来源、可追溯、脱离当前文章仍可复用的企业知识 | 按稳定业务对象或稳定主题自动进入对应正式模块 |
| 已有正式知识被文章再次使用 | 只更新集中使用数据，不重复创建或复制正文 |
| 产品稳定属性 | 按SPU/型号固定知识ID，更新产品主数据或既有重点产品卡 |
| 本篇文章临时选品组合或对比角度 | 留在文章任务，不按文章主题建立正式产品文件 |
| 价格、库存、阶梯价、国家化预计送达时间 | 进入带日期的动态数据快照，不进入稳定产品正文 |
| 配送、退货、税务等动态政策 | 更新按适用范围组织的单一当前政策文件，旧版进入历史 |
| 企业提供的行业知识 | 自动进入`行业知识与洞察/10_企业提供/` |
| 最终文章实际使用、来源可靠、可复用的外部行业知识 | 自动进入`行业知识与洞察/20_Codex外部调研/` |
| 已调研但最终文章未使用 | 留在`05_数据与审核/30_异常与待决定/20_外部知识待决定/` |
| 只服务当前文章、复用价值低 | 留在文章任务及其来源记录 |
| 无可靠来源或只有AI推断 | 不沉淀 |
| 文章新增但无客户来源的企业事实 | 进入`05_数据与审核/30_异常与待决定/10_企业知识异常待处理/`，不沉淀 |
| 客户明确禁止使用的内容 | 不进入知识正文，只记录不含敏感正文的排除状态 |

## 6. 行业知识来源分区

企业提供和外部调研的行业知识不能混在同一文件。文件名和元数据都标明来源类型：

```text
02_正式知识/50_行业知识与洞察/
├── 10_企业提供/
│   └── 欧洲时尚零售与消费者偏好（企业资料）.md
└── 20_Codex外部调研/
    └── 欧洲时尚零售与消费者偏好（外部调研）.md
```

正式知识中的外部调研文件至少记录：

```yaml
source_type: Codex外部调研
source_urls:
data_date:
research_date:
verification_status:
last_updated:
```

结论旁保留来源和日期，不能只在文件顶部放一组无法对应到正文的链接。

正式知识文件是可复用结论层，不替代`04_资料与证据/50_外部调研/`中的原文证据和调研整理稿；沉淀后仍需保留回链。

## 7. 自动沉淀执行

满足规则时，不再询问内容运营“是否沉淀”或“放在哪里”。Codex自动：

1. 把原文或结构稿拆成最小可独立判断的知识候选，并逐条写入`知识候选分流`；
2. 判断内容是否能脱离当前文章独立复用；
3. 确定唯一主归属模块和必要的关联模块；相关模块只链接引用，不复制维护正文；
4. 确定稳定实体键或主题键，例如公司主题、SPU/型号、解决方案、案例、政策主题或行业主题；
5. 按稳定键查找同主题正式知识，禁止按文章标题、选品组合、提取批次、单个网页任务或抓取日期新建正式文件；
6. 判断新增、补充、冲突、动态数据或历史版本；
7. 合并可复用内容并保留来源映射，不覆盖仍有效的冲突版本；
8. 更新正式知识目录和`05_数据与审核/10_知识沉淀与分流/20_知识沉淀记录.md`；
9. 更新正式知识文件的来源、日期和必要更新条件，不在正文维护文章使用次数或不断增长的文章列表；
10. 更新项目资料稿、待办和项目更新日志；
11. 在文章引用清单中记录最终去向；
12. 在`40_正式知识沉淀记录.csv`追加一行，记录日期、知识ID、动作、正式文件、标题位置、来源、关联文章和状态。

文章终稿是沉淀触发器和使用证据，不是企业事实来源。知识正文必须回溯到客户材料或可靠外部原始来源。

候选尚未实际写入、来源映射未完成或集中数据尚未同步时，不得标记为`已沉淀`。正常沉淀不再为每个知识块创建单独回执文件；只有沉淀失败、来源冲突或需要人工决定时才生成独立处理文件。

## 8. 异常与待决定

正常知识自动沉淀，只把以下项目留给人工：

- 企业事实没有客户来源；
- 权威来源互相冲突且会改变文章结论；
- 外部来源可靠性不足；
- 动态数据已经过期或日期不明；
- 客户公开权限不明；
- 无法确定是否具有长期复用价值且最终文章未使用。

未决定外部知识保留到月度维护，由知识库专员处理。不得因为等待正式沉淀决定而删除原始调研或阻止已通过文章前审核的当前文章使用。
