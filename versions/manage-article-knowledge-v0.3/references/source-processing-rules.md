## 1. 两阶段处理

把文件处理明确分成：

1. **项目初始化扫描**：登记文件信息、语言、结构和每页/章节大意，不全量提取正文。
2. **文章定向提取**：收到文章需求后，只处理当前文章相关的完整语义范围。

不使用“浅扫描”“深扫描”名称，不让内容运营选择扫描方式。

## 2. 初始化扫描

收到稳定源文件路径后自动递归扫描。保持只读并记录：

- 文件名、相对路径、格式、大小、修改时间和指纹；
- 完全重复、同名不同内容、疑似新旧版本和损坏文件；
- 主要语言；
- PDF页数、PPT页数、Word可见标题、表格工作表、视频时长等可可靠取得的结构；
- 是否能正常读取；
- 是否存在对应提取稿；
- 可能支持的正式知识模块；
- 内容导航状态。

对DOCX、PPTX、XLSX及压缩包递归检查嵌入对象、附件、媒体、图表、关系文件和外部链接。每个子文件分配子资料ID，记录父资料ID、父文件内位置、原始文件名、识别格式、载荷指纹、是否需要单独提取稿和当前状态。未识别或无法安全读取的对象进入源资料处理待办，不能因父文件正文可读就宣称全部扫描完成。

重复与版本关系只使用：`主文件 / 完全重复副本→[资料ID] / 疑似旧版→[资料ID] / 疑似新版→[资料ID] / 版本关系未确认→[资料ID] / 内容部分重合→[资料ID] / 独立资料`。机器只按内容指纹完全相同认定完全重复；指纹不同即使同名或相似也分别登记。完全重复组优先选择已有合格稿或已被使用的资料ID为主资料，否则选择最早登记的资料ID；主资料确定后不因新增副本随意更换。全部原路径保留，只为主资料生成一套当前内容导航、提取稿、清理稿和知识候选。疑似版本或部分重合无法确认时建立`MAT`，比较版本/修改日期、适用型号、地区、章节和事实差异后再判断。

图片先分为`装饰图`、`附件图标`、`信息截图`和`复杂图示`。附件图标触发嵌入子文件检查；信息截图及流程图、复杂表格、图表、组织结构图等复杂图示即使没有连续文字也必须登记、查看并判断与文章的关系。纯装饰图不进入知识正文，但保留排除结论；不能仅用“没有可识别文字”作为跳过依据。

为可能支持企业知识或文章的文件建立内容导航。PDF/PPT尽量逐页记录“这一页有什么”；Word按标题路径和连续段落；Excel按工作表、表区和字段；视频按时间段；网页按页面区块。

不能可靠判断的字段写`未确认`并说明原因，不猜测。导航不是提取稿，不需要复制正文。

## 3. 待提交资料与就绪检查

文章需求确定后，Codex根据实际相关资料生成提取输入清单。状态只使用：

- `已就绪`；
- `需要运营提供`；
- `Codex可直接处理`；
- `异常待处理`；
- `本篇不需要`。

内容运营不负责从全部文件中判断缺什么。Codex先复用已有合格稿并自动取得可处理资料；全部就绪时只在后台更新检查文件，不向内容运营展示或等待确认。只有自动取得失败、质量不合格或需要授权时，Codex才写明具体原文件或网页、稿件类型、原因、嵌入子文件和内容运营的简短操作步骤。运营只需把生成的`.md`直接发给Codex，不改名，不选择Obsidian目录，不自行登记。

运营提交的原始Markdown、转写稿、网页稿或其他提取稿原样保存在项目级`04_资料与证据/20_原文提取/20_运营提交/`。Codex自行生成的原文证据保存在项目级`10_Codex提取/`。不得按文章ID复制来源稿，也不得先清理再保存。每份运营提交稿记录提供者、工具、日期、对应原文件、版本/指纹、人工初检状态和关联文章；关联文章统一写入`01_运营提交文件用途登记.md`。

Codex生成的证据文件按来源身份命名，不按首次使用它的文章命名。网页使用稳定页面身份或商品SPU/型号，例如`WEB-PROD-56106_商品页原文.md`；本地文件使用稳定资料ID。相同URL或资料被新文章复用时链接现有证据，不再生成带新文章ID的副本。来源发生变化时更新当前证据并把旧版移入`90_归档/20_项目运行历史/`，保留获取日期和内容指纹。

## 4. PDF与PPT

当前文章确认范围内的PDF/PPT先复用同一原文件、同一版本的合格Markdown稿。不存在时，Codex优先运行`scripts/run_mineru.py extract --project-root <当前项目根目录> --source-id <资料ID> --input <原文件>`；脚本只从当前进程的`MINERU_API_TOKEN`读取凭证，直接调用MinerU官方API完成上传、轮询和结果下载，不查找本地MinerU安装路径，不要求内容运营安装CLI或MCP。自动稿先在系统临时目录解压并通过基础检查，之后只将主Markdown和必要引用附件归入`Codex提取`。MinerU返回的调试JSON、布局PDF、缓存和其他中间产物不进入Obsidian，不建立MinerU目录。Token不得写入Skill、项目文件、日志、命令参数或对话。

Token缺失或过期、API连接/额度/上传/解析/下载失败、结果不完整或质量不合格时，Codex先判断是否可安全重试；仍失败才请内容运营用MinerU处理点名原文件，导出Markdown后不删改、不重新排版、不改名，直接把`.md`发给Codex。Codex自行核对、按稳定资料ID命名、归入`运营提交`并登记运营发来时的原文件名、生成工具、提交日期、原文件指纹、页数/幻灯片数和稿件版本。始终保留原PDF/PPT作为版式、页码、表格、公式、图片和结构核验依据。

固定采用“源文件与运营Markdown并行核对”：先用原文件确认版本、总页数、标题结构和复杂内容位置，再评估Markdown质量。Markdown的段落、标题、表格、公式和顺序合格时，直接以Markdown作为主要文字输入；发现断行、漏字、错序、表格错位、公式或标题结构损失时，才针对受影响页段使用原文件直接提取、OCR、版面解析或其他方法补核，并在处理记录中写明差异与修正依据。不得把逐行文字堆积、表格消失或结构丢失的文本当作合格结果。

Codex：

1. 检查提取结果或运营提交稿能否对应原文件和版本；
2. 记录覆盖页数、遗漏页、乱序、乱码和表格异常；
3. 合格的Codex自动稿或运营稿直接作为主要文本输入；只对异常页段使用原生读取、OCR或其他工具补正；
4. 只对当前文章相关页面定向查看原文件；
5. 对数字、型号、单位、表格、图注和视觉关系进行原文件复核；
6. 不因为任何工具稿件存在就声称所有页面已准确提取。

如果Word、PPT、Excel或压缩包中嵌有PDF/PPT，子文件同样适用本节要求；父文件就绪不代表子文件就绪。

页码必须说明是PDF文件页码、印刷页码还是PPT页码。二者不一致时同时记录。

每份源文件只维护一份当前`清理与字段统一稿`。清理稿可以只覆盖文章已确认范围，但必须达到可直接复用的质量：自然段落、连续标题层级、Markdown表格、必要公式、来源页码映射、确认范围、未处理范围和差异记录。页码只作为定位提示，正文仍按源文件真实章节和语义结构组织。不得另建文章话题稿，也不得把多份PDF全部合并为一个清理稿。

## 5. Word、表格、图片、音视频、压缩包和网页

### Word

按可见标题路径、起止标题和开头文字定位。只有固定渲染版本后才能使用`渲染页码`。不得把程序段落序号称为Word页码。必须同时检查内嵌文件、对象图标、关系文件和关键图片；为父文件与各子文件分别记录处理状态。

Word内图片记录父资料ID、所在标题路径、附近段落/题注、关系文件或内部媒体路径、图片类型和载荷指纹。图片与正文共同表达含义时，内容导航和处理稿必须保留两者关系，不能只抽取文字后丢失图片语义。附件图标按嵌入子文件追查，不当作普通图片；同一图片载荷在Word内多次出现或也存在独立文件时保留全部出现位置，只生成一套派生处理。损坏、无法导出、格式不支持或无法判断是否承载信息时建立`MAT`。

审阅意见DOCX、由PDF派生的行业知识DOCX、由官网派生的产品知识DOCX和文章大纲DOCX默认只作导航、范围或要求参考，不作为正式正文或产品事实来源。正式处理分别回到对应PDF、官网具体页面或文章要求；只有用户明确确认某DOCX本身是权威源文件时才改变该来源身份。

### Excel、CSV和表格

记录工作表、表区、表头、单位、合并单元格和公式/显示值差异。保持行列关系；需要文字化时另建派生稿，不替代原表格证据。

### 图片和扫描件

建立图片清单，至少记录图片ID、来源和位置、附近标题、图片类型、可见文字或视觉关系、与大纲的关系、处理决定/排除理由和代表样本ID。装饰图不进入知识正文；附件图标必须追查载荷；信息截图和复杂图示必须视觉核验。OCR不确定结果必须标记并回看原图，流程、箭头、坐标、图例、颜色映射和空间关系不能只靠OCR推断。

复杂表格、流程图、图表和关键截图按`处理结构 + 版本`分组，每组选择一个代表样本，在`15_提取范围与处理样本确认.md`中并列展示原稿定位、拟转写结果、关系解释和不确定点。确认后只向同结构同版本复用；发现新布局、新交互或关系语义变化时重新取样确认。

文章或项目确认“PDF图片全部不处理”时，把该限制记录在范围确认中，并排除图片OCR、图片转写和图示推断；仍需登记图片位置和排除结论，以证明没有把图片内容误当作已处理正文。

### 视频和音频

初始化只登记资料ID、原文件名、相对路径、格式、大小、修改时间、指纹、能可靠取得的时长、原始标题、`仅据文件名初判`、疑似配套文字稿和处理状态。文件名推测不得写成确认标题；AI知识库专员查看实际内容后另填`确认内容标题`，不覆盖原文件名。

内容运营不负责提取字幕、音轨、转写、标题核验或准确性审核。视频/音频默认进入`03_源资料处理待办.md`，由AI知识库专员在月度维护中决定`提取已有字幕 / 提取音轨后转写 / 字幕或转写加关键画面与屏幕文字核验 / 只处理指定时间范围 / 暂不处理 / 等待工具、权限或材料 / 无法处理，保留登记`。当前文章明确依赖、疑似包含重大事实/冲突/承诺或是唯一知识来源时立即判断，不等月末。

文件名、同目录、时间接近、产品型号、主题或时间码只能用于发现疑似配套文字稿。视频和文字稿双向登记资料ID，关系只使用`疑似配套稿，待核验 / 已确认原始字幕稿 / 已确认原始转写稿 / 已确认处理稿 / 仅覆盖部分视频 / 关系未确认 / 已确认不匹配`。确认至少抽查开头、中段、结尾以及型号、数字、单位和术语；有时间码时核对相应时间点，没有时间码时不得伪造。内容运营转交现成稿件时只需说明对应资料ID或原视频名，Codex负责保存、登记和核验。

原视频是最终原始证据；原始字幕/转写稿原样保存；删除口头语、合并重复或修正识别错误后的版本另存为`cleaned-transcript`。核验后的处理稿是后续检索和知识提取的主要入口，但关键事实仍须能回到原视频时间码；一份视频同一版本只保留一份当前处理稿。

### ZIP、RAR、7z及外部解压目录

压缩包先作为父资料登记，记录格式、大小、修改时间、指纹、是否加密/损坏、声明文件数与解压大小、目录层级、嵌套压缩包和扫描状态。先只读列目录；需要处理的子文件只解压到系统临时目录，拒绝绝对路径、`..`路径穿越和写出临时根目录的条目，不执行包内程序、脚本或宏，不把全量解压副本、缓存或中间文件放进客户目录或Obsidian。RAR/7z仅在本机已有获准工具时只读列目录和安全解压；缺少工具、加密、损坏、文件名编码异常、声明规模/压缩率异常或嵌套过深时停止自动展开并建立`MAT`，不得尝试破解密码。

每个包内子文件分配资料ID，父文件内位置固定写`[压缩包相对路径]!/[包内完整路径]`，并登记子文件大小、指纹、识别格式、处理状态和重复/版本关系。父压缩包就绪不代表子文件就绪；单个子文件失败不影响其他可独立处理的子文件。

压缩包旁存在同名或疑似已解压目录时，名称只建立候选关系。逐项比较包内路径、外部相对路径、文件数量、大小和实际内容指纹后，整体关系只使用`已确认完整解压副本 / 已确认部分解压 / 解压后有修改 / 解压目录含额外文件 / 疑似对应，关系未确认 / 已确认不对应`。指纹相同的包内与外部文件优先使用外部已解压文件作为处理入口，包内位置登记为完全重复副本并保留来源映射；指纹不同或外部新增的文件分别登记，不自动认定新版。部分解压时复用外部相同文件，只按需临时解压包内剩余文件，不写回客户目录。

### 客户官网

已知官网、产品名或页面类型时自动定位官网页面。正式处理前必须生成可核对的提取范围，列出入口URL、导航路径、页面类型/产品类别、发现数量与网站显示总数、分页/下一页/加载更多/无限滚动、标签页/折叠/弹窗/悬停内容、语言/地区/移动端差异、拟提取字段、排除项与代表页面。页面数量或类别范围无法闭合时不得进入批量处理。

能够稳定取得正文时由Codex保存原文证据；无法稳定取得、动态内容容易丢失或需要固定可复核证据时，Codex明确点名具体页面，请内容运营提交Web Clipper稿。不是所有官网页面都要求运营提交Web Clipper，也不让运营自行判断哪些页面需要提交。

具体产品页的标题下斜体介绍属于产品正文，必须与页面其他可见正文和表格一起检查；这条规则适用于所有产品页，不能只修复用户点名的单页。产品事实必须回到具体产品页。表格保留型号、数值、单位、表头和限定条件；分类页总数无法闭合时写`未确认`，不推算产品总数。

### 外部网页

自动查找和提取可访问页面。搜索结果页、聚合摘要和AI回答不能作为正式来源。受限页面按第9节交接。

网页来源统一进入`01_源文件总表.md`和相应内容导航。文章引用清单记录本篇实际使用的网页证据；不得再为单篇文章或单批商品页生成重复的“网页证据索引”。

## 6. 提取范围与处理样本

正文提取前生成`15_提取范围与处理样本确认.md`。每项必须包含：

- 资料ID和业务名称；
- 原文件、提取稿及版本；
- 网页来源的页面标题和Markdown格式直达链接，链接必须指向实际待确认页面，不能只给官网首页或搜索结果；
- 当前可用状态；
- 原始语言；
- 页码、PPT页、标题路径、工作表、时间码或网页区块；
- 拟提取主题和字段；
- 最小完整语义块边界；
- 表格、图示、FAQ和特殊结构处理；
- 父子资料关系、嵌入对象状态和图片清单；
- 网站覆盖闭合字段；
- 处理结构分组、代表样本、拟处理结果和不确定点；
- 排除范围；
- 输出文件和位置。

范围大纲必须来自真实文档结构。文章大纲只能说明为什么相关，不能替代源文件标题、页码和字段。

网页只提取部分区块时，同时写明网页区块、起止标题或起止识别文字，使内容运营可以打开链接后直接定位确认。

客户源文件是可信的一手来源，在已确认范围内默认可以直接提取，不要求先用官网或外部网页证明同一内容。原文件可读、自动提取与核验合格且无未决风险时，由`manage-article-knowledge` Skill自动确认范围。来源可信性不等于允许公开；保密、未发布或公开范围不明的内容仍在文章前审核中单独处理。

范围自动确认或必要时人工确认后，Codex可以自动完成原文提取、翻译、结构整理、去重、项目资料稿更新和合格知识沉淀，不再增加派生处理确认。只在需要运营补交指定PDF/PPT/网页的原样`.md`，或范围、代表样本、公开权限、来源冲突或高风险内容不能由可回溯证据自行确认时，才要求人工确认受影响部分。触发人工确认时，Agent一致意见不能替代人工决定。

## 7. 原文证据

凡标记为`原文证据`、`原始提取稿`或`verbatim`的内容必须：

- 按原文顺序保存；
- 不总结、不润色、不改写、不补齐；
- 不把不同位置拼成一句；
- 保留标题、父子层级、列表、表格和字段关系；
- 记录原文件、版本、位置和提取方式；
- 把无法确认的字符或结构显式标出。

默认提取最小完整语义块。选择一个标题时，保留该标题及其下属内容，直到下一个同级或更高级标题。确需只提取下级标题时，记录完整父级路径。

翻译、摘要、层级修正、表格文字化和知识归纳必须另存，不能覆盖原文证据。

## 8. 自动派生处理

提取范围确认后可自动执行：

- 来源属性统一；
- 标题层级映射；
- 精确去重；
- 忠实翻译；
- 表格保真稿和文字化稿；
- FAQ、参数和列表结构化；
- 项目资料稿更新；
- 正式知识候选判断。

默认把修复后的段落、标题、表格和公式直接保存在该来源唯一的`清理与字段统一稿`中。只有翻译需要独立复用，或复杂表格/结构无法在清理稿中清楚表达时，才新建独立翻译稿或表格与结构稿；不得为了填满目录机械生成空文件或重复正文。处理结果、异常、差异和旧结构稿统一进入`90_处理记录/`。

每种派生稿记录输入、处理方法、输出、来源映射和核验状态。结构异常时保留原始结构，并在派生稿中给出修正版；不得静默修正证据层。

单个文件内部或不同文件之间的完全重复段落、页面和表格在原始证据层按实际位置全部保留。只允许在清理稿和正式知识层精确去重，并记录保留位置、去重位置、判定依据和每个来源映射；相似、条件不同、适用对象不同、新旧版本和冲突内容不得自动删除。不得使用语义相似度触发删除、覆盖、合并或替换。

处理完成后向运营展示：

- 已处理范围；
- 生成文件；
- 识别为正式知识候选、动态快照和项目资料稿的内容；
- 未处理范围；
- 需要在文章前审核解决的异常。

## 9. 源文质量分类与修正边界

资料处理Agent逐项判断问题属于哪一类，不因文字不自然就推断客户资料经过机器翻译，也不假设存在未取得的中文原文：

| 类型 | 判定 | 自动处理 | 长期记录 |
|---|---|---|---|
| `提取错误` | 原文件正确，运营稿、OCR、转写或解析结果错误 | 对照原文件修正提取/清理稿，保留差异和依据 | 汇总到该资料的源文件级处理记录 |
| `英文源文表面问题` | 客户提供的英文存在拼写、语法、标点或措辞问题，但上下文只有一种合理含义 | 原英文不变；可生成`source-normalized-english`派生稿 | 零散修正汇总记录；出现语义风险则升级异常 |
| `确定性规范化` | 格式、日期、单位表示或数值换算有唯一规则，且原值、对象和维度均可确认 | 同时保留原值、规范值、规则和复算过程 | 汇总到源文件级处理记录 |
| `语义不确定或事实风险` | 存在多种合理含义，或单位缺失/含混、公式损坏、法规正文残缺、参数对应不明 | 不补写、不选答案；隔离受影响主张 | 分配异常ID并进入集中异常台账 |
| `来源冲突` | 两个可追溯来源对同一适用范围给出不兼容陈述 | 并列保留版本、日期、范围和来源，不静默裁决 | 分配异常ID并进入集中异常台账 |

只有不改变事实、范围、确定程度、参数、因果、承诺和公开边界的修正才可自动生成派生稿。任何“看起来更合理”的事实修复都不属于语言修正。精确换算必须可逆或可复算；无法确认原单位、量纲、对象或舍入规则时归入事实风险。

同一资料中的零散拼写、语法、标点和确定性格式修正合并为一份源文件级记录，保存到`04_资料与证据/30_整理与翻译稿/90_处理记录/[资料ID]_[资料名称]_源文质量与规范化记录.md`，不得为每个错字建立长期异常。会影响可用事实、知识沉淀、写作输入或公开使用的项目，登记到`05_数据与审核/30_异常与待决定/10_企业知识异常待处理/02_源文与事实异常台账.md`；可靠的独立部分继续处理，只有受影响`CLAIM`进入`异常待处理`。

登记实质异常时，主表先用通俗字段说明问题和当前动作，详情开头依次回答“发生了什么、为什么有风险、现在怎么处理、为什么本轮结束或还在等什么”，然后建立原文现场证据包：使用可点击链接指向保存原文证据和精确标题/区块；原始文件或网页仍可访问时同时提供原始来源链接；逐字/原样保存实际取得的异常文本、原表、原公式或冲突版本及必要上下文。逐字内容含`%%`、Wikilink、HTML标签或其他Obsidian/Markdown控制语法时必须放入`text`围栏代码块，不得裸放在普通段落、引用块或表格中。表格、公式、版面、OCR错位等不能仅靠转述判断的问题，必须附原页、截图、原表或公式现场链接。异常记录中的“经核验仍可使用的原文或原始结构”必须逐字/原样保存并单独定位，没有则明确写`无`。不得用问题说明代替证据，也不得把异常台账本身当作唯一完成证据。

## 10. 质量异常与人工交接

出现以下情况时暂停受影响范围：

- 文件损坏、加密、缺页或版本无法对应；
- MinerU/OCR/转写漏段、乱序、改写、乱码或表格严重失真；
- 无法访问网页正文；
- 数字、型号、单位或日期无法核对；
- 来源冲突会影响文章事实；
- 无法满足逐字、顺序、结构或定位要求。

上述情况如果本质是“资料存在但当前无法正常处理、需要决定工具/范围/方法”，分配`[项目ID]-MAT-001`并进入`03_源资料处理待办.md`；处理后发现事实、语义、公开使用或知识沉淀风险时再关联`ANM`，确需客户提供密码、清晰原片、正式字幕或新文件时经知识库专员判断后关联`CUS`，通用Skill缺陷关联`SKFB`。

交接信息必须写清：

1. 具体文件和受影响范围；
2. 已尝试方法；
3. 可靠部分；
4. 结果差距；
5. 运营需要提供的具体材料；
6. Codex归档时使用的稳定文件名和存放位置（不要求内容运营改名或放入目录）；
7. 异常ID、受影响`CLAIM`、当前安全处理和重开条件；
8. 是否已有客户材料请求，客户事项当前阶段和异常当前阶段各自为何。

失败范围标记`不完整，不作为当前可用原文`。可靠的独立部分可以继续，失败部分不得进入写作输入或正式知识。
