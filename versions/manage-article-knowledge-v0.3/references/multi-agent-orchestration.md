# 多Agent分工与独立审核

## 1. 固定角色

每次文章处理由一个主Agent和三个职责隔离的子Agent组成：

| 角色 | 只负责 | 不负责 |
|---|---|---|
| 主Agent | 读取文章需求、执行四级资料路由、列出运营待提交材料、调度任务、合并冲突、向用户说明进度与异常、唯一写入正式知识和集中控制文件 | 不把子Agent一致意见当作证据，不跳过人工确认 |
| 调研Agent | 只在主Agent确认真实公开知识缺口后开展外部调研，保存网页/文章原文证据和独立整理稿，报告来源冲突与限制 | 不处理客户原文件，不证明或“修复”企业专属事实，不用公开资料替客户资料选择答案，不写正式知识 |
| 资料处理Agent | 对照客户原文件、官网、运营提交稿和已确认代表样本，完成提取、翻译、结构化、资料稿和候选分流；分类提取错误、源文表面问题、确定性规范化、事实风险和来源冲突；生成有逐项映射的修正版或派生稿 | 不静默改变客户原文，不把不自然英文认定为机器翻译，不自动补单位、参数、公式或法规正文，不审核自己的结果，不写正式知识 |
| 审核Agent | 只读对照原文件、运营提交稿、网站范围、原文证据、修正记录和处理结果，主动寻找遗漏、语义漂移、静默改动、冲突与反例 | 不修改处理稿，不替资料处理Agent生成修正，不补写证据，不参与生产，不批准自己的工作 |

知识库专员、优化师和内容运营是人工职责，不属于三个子Agent：知识库专员审核是否确实需要客户补充并确认对客话术；主Agent在审核通过后生成话术草稿；优化师负责实际发送、记录渠道和带回可点击回复证据；内容运营只作为文章需求或问题发现来源，不默认承担知识审核或对客沟通。

## 2. 调度顺序

1. 主Agent读取关键词、标题、大纲和要求，按`正式知识 → 客户源文件/客户官网 → 已有外部调研 → 新外部调研`路由资料。
2. 主Agent复用已有合格稿，调度MinerU与网页自动提取，并生成`10_待提交资料清单与就绪检查.md`。全部就绪时后台自动继续；只在自动失败、结果不合格或需要授权时，请内容运营把明确点名的PDF/PPT Markdown稿、网页Web Clipper稿或其他输入直接发给Codex。
3. 资料处理Agent读取原文件与运营提交稿，生成`15_提取范围与处理样本确认.md`的候选内容；主Agent检查格式后交给人工确认。
4. 人工确认范围与代表样本后，资料处理Agent批量派生处理。
5. 若本地资料处理后仍有真实公开知识缺口，主Agent先向用户发送一次非阻塞调研通知，再调度调研Agent。
6. 审核Agent在资料处理和必要调研完成后独立审核。主Agent只合并有来源定位的审核结果。
7. 只有主Agent可以生成最终文章前审核、写作输入草稿、正式知识和集中数据更新。
8. 主Agent生成写作输入草稿后，审核Agent逐个来源块对照确认范围和当前证据执行保真复核；主Agent只在复核通过后更新审核状态、交付写作输入并迁移到等待终稿。

## 3. 输入与输出隔离

- 调研Agent不能看到资料处理Agent的预期结论，只接收缺口问题、允许的来源边界和时间范围，避免迎合已有答案。
- 审核Agent接收原文件/原文证据、运营提交稿、已确认范围与样本、处理结果和文章大纲，但不接收“应该通过”的结论性提示。
- 子Agent默认只向主Agent返回结构化结果，不直接创建Obsidian过程文件。确需保存原文证据或清理稿时，由主Agent预先指定唯一目标文件；正式知识、集中CSV、当前待办、状态迁移和用户可见决定始终由主Agent串行写入。
- 每个子Agent必须报告实际读取的文件/页面、定位范围、未读取内容、使用方法、发现的问题和不确定点。
- 子Agent无法使用时，主Agent按相同清单顺序执行并明确记录`未形成独立Agent隔离`；不得把顺序自审说成独立审核。

每次子Agent返回必须使用同一交付契约：

| 字段 | 要求 |
|---|---|
| 任务与文章ID | 明确本次只处理什么 |
| 实际读取 | 文件/URL、版本、页码或区块 |
| 未读取与排除 | 未覆盖内容及原因 |
| 产出或发现 | 逐项列出，不只写结论 |
| 证据定位 | 每项问题对应一个最有用的来源位置 |
| 提取稿异常 | 分开列出提取/OCR/转写错误、原文依据和修正结果；没有则写`无` |
| 客户源文质量问题 | 分开列出表面语言问题、确定性规范化、语义/事实风险和来源冲突；不得推断机器翻译或缺失中文原文 |
| 已自动修复项 | 逐项记录原文/原值、修正版/规范值、规则、来源映射和是否改变事实；没有则写`无` |
| 未解决事实风险 | 记录异常ID、受影响`CLAIM`、当前安全处理、阻塞范围和下一步；没有则写`无` |
| 异常原文现场 | 提供可点击保存原文证据、原始来源（可取得时）、精确位置、证据完整性、实际取得的逐字原文/原始结构、必要上下文和现场截图/原页；没有异常则写`不适用` |
| 写作输入迁入核对 | 逐块记录采用范围、未迁入内容及理由、完整正文/表格/公式保留情况；非写作输入任务写`不适用` |
| 不确定点 | 是否阻塞及建议返回节点 |
| 建议状态 | 只能使用该角色允许的状态 |

主Agent合并前检查交付契约完整性。缺少实际读取范围、证据定位或未读取说明的子Agent结果不得用于通过审核或写入正式知识。

## 4. 审核Agent最低检查

审核Agent必须主动验证，而不是复述处理结果：

- PDF/PPT：原文件页数与Codex自动稿或运营稿覆盖是否一致，是否有漏页、乱序、复杂表格/图表/流程关系误读；
- Word/Office容器：是否存在未登记的内嵌PDF/PPT、对象图标、关系文件、关键截图或其他子资料；
- 网站：产品类别、列表数量、第二页、下一页、加载更多、无限滚动、标签页、折叠、弹窗、悬停、语言/地区版本是否覆盖或明确排除；
- 图片与复杂结构：代表样本能否覆盖同组资料，后续项是否出现新结构或新版本；
- 外部调研：每项结论是否有独立保存的原文证据，是否只剩摘要、转述或AI推断；
- 大纲覆盖：每个可保留主张是否有对应证据，企业事实是否仅由客户来源支持；
- 反例检查：主动寻找能推翻或限制当前解读的原文位置，不能只确认已有判断。
- 源文修正检查：提取错误是否确实能由原文件纠正；`source-normalized-english`是否逐项映射原文且没有改变事实、范围、确定程度或公开边界；单位、公式、参数、法规和来源冲突是否被错误地当作语言问题自动修复；
- 异常证据检查：实际打开异常记录中的保存原文证据、原始来源和现场链接，核对逐字原文/原始结构、必要上下文、精确位置和证据完整性；不得用异常结论或资料ID代替现场证据；
- 写作输入保真：是否从确认范围中筛选完整语义块并按大纲重排；选中段落的解释、条件、例子和例外是否保留；表格、公式、脚注、数字和单位是否完整；未迁入内容是否逐项说明理由；是否把来源正文压缩为知识点卡、摘要或多来源AI综合正文；
- 产物检查：写作输入是否按大纲组织、不同来源是否分别成块、审核是否只在状态字段链接写作输入而未把它当来源、正式知识是否误用文章或AI总结、当前稿是否唯一；
- 结构检查：Markdown表格列数、标题层级、公式与表格保留声明、未替换变量、旧电脑路径、断链和旧状态路径；
- 状态检查：任务目录、文章总览、工作台、完成列表和集中数据是否一致。

审核Agent不得只复述“有证据通过”。它必须返回已读清单、未读清单、逐项检查结果和反例查找结果。写作输入保真复核必须以清理稿、官网原文、外部原文证据或正式知识为对照，不能用文章前审核中的概括替代正文对照。异常进入`已解决`或`已完成处置（原文未修复）`前，必须注明实际打开了哪些原文和现场链接、记录摘录是否逐字、上下文是否足以判断，并核对通俗结论与技术证据一致。主Agent在生成写作输入草稿前和交付前分别运行项目校验；机器校验失败、写作输入保真复核未通过或审核交付契约不完整时，不得通过。

## 5. 审核结论与人工升级

审核结论只允许：

- `有证据通过`：范围闭合，关键结论可定位，未发现影响使用的遗漏或冲突；
- `带明确排除通过`：已列出未处理范围、理由及其对文章的影响，剩余内容足以安全使用；
- `升级人工处理`：存在无法由证据消除的遗漏、图表解读、来源冲突、企业事实、访问授权或公开边界问题。

以下情况必须升级人工，不能由多个Agent投票决定：

- 网站范围数量无法闭合或关键交互无法验证；
- 复杂表格、流程图、图表或关键截图的代表样本存在多种合理解释；
- 新结构或新版本超出已确认代表样本；
- 原文件与运营提交稿在数字、顺序、表格或结论上有实质差异；
- 客户英文源文存在多种合理解释，或规范化可能改变事实、范围、确定程度、因果或承诺；
- 单位缺失或含混、公式损坏、法规正文残缺、参数对应不明，无法由同一来源确定恢复；
- 企业专属事实没有客户来源，或权威来源冲突会改变文章结论；
- 原文无法取得、只有摘要，或公开/保密边界不明。

Agent一致只说明它们可能共享了同一盲区，不构成事实证据、范围完整性证明或人工确认替代物。
