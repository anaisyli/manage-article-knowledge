# 文章知识工作流

## 1. 接收需求与检索

每个文章ID建立一个任务。保存已有标题、关键词、大纲、目标语言和限制；可选信息缺失不应阻断仍可完成的工作。多篇同时提交也不得合成一个任务。

文章需求提交是唯一正常启动信号。Codex在同一自动事务中先建立`10_文章知识需求.md`和当前待办，再连续执行并可见落盘`15_前五层检索 → 写作前缺口识别与登记 → 必要的新外部调研及候选Claim核验 → 20_文章前知识审核.md → 通过审核的正式知识沉淀 → 30_本篇知识库资料.md → 35_写作素材来源索引.md`。这些文件编号表示依赖顺序，不是人工触发点。除非出现本文件第4节规定的真实人工问题，或发生外部访问/工具失败、缺少不可替代材料，否则不得停下来询问“是否继续”，也不得把非阻塞任务留到下一次人工催办。

把需求拆成具体知识问题。先固定检索已有正式Claim、客户来源索引、客户官网、内容运营提交且企业关系已确认的其他企业相关网站、已有外部公共Claim五层；完成写作前缺口识别、登记和状态判定后，再决定是否执行第六层“新的外部调研”。

关键词重合不等于有用。只有资料主题、适用对象、时间、版本和范围能够回答当前知识问题时才算命中。检索记录只保留：知识问题、选中的Claim或来源、为什么相关、下一步是复用、核验、调研、省略或升级。每篇文章还必须在同一文件登记固定检索状态：已有正式Claim、客户源资料索引、客户官网、客户关联网站、已有外部公共Claim、新外部调研。每层都要写明确状态和结果/未查原因；没有已登记客户关联网站时直接写“无已登记站点”。网站没有相关页面、无法访问、关系待确认或按项目边界不适用时也要明确写出，不能用“检索完成”代替。

`15_检索与知识准备记录.md`的来源命中主表固定使用四列：`知识问题 | 命中Claim/资料名称与入口 | 相关理由 | 处理结果`。同批文章、同一阶段和同一来源类型必须复用这一个结构，不另建“官网产品页命中”等重复表。文章进入等待终稿、等待Faithfulness或已完成状态前，六层固定检索状态必须完整，且不得仍为待检索。

每篇文章的`15_检索与知识准备记录.md`还必须写明`- MAT依赖处理：无 / 待决定 / 已决定`，并保留“MAT依赖与资料选择”表。只要命中的资料在来源台账中关联开放MAT，先写`待决定`并列出全部候选；决定前不得从候选建立Claim、写入`30/35`或进行面向交付的整理。视觉核验类可仅为判定目的调用MinerU并对照原始PDF/PPT，不能把该技术解析稿当作已完成提取。人工或Codex决定后，Codex必须在同一事务中把状态改为`已决定`，写明选取/排除范围、依据和决定方，再对已决定的资料集合统一提取、回源核验和沉淀，不得边等待边随机整理部分文件。

MAT决定方按文章阻塞顺序处理：完全相同副本由Codex自动处理；视觉核验类MAT先由Codex按需调用MinerU并结合原始PDF/PPT对照，可自行决定并留痕。若视觉核验后仍无法唯一判断，或候选涉及版本冲突、范围不明、数字型号单位歧义或可能改变Claim含义，才把固定处理单交内容运营处理。内容运营明确表示处理不了时，退回项目负责人（用户），由项目负责人决定是否指定AI知识库专员；只有用户指定后，AI知识库专员才处理剩余复杂事项。

    ## MAT依赖与资料选择

    | MAT ID | 候选SRC ID | 文件名与稳定路径 | 关系/处理问题 | 决定 | 选取或排除范围 | 决定依据 | 决定方 | 当前状态 |
    |---|---|---|---|---|---|---|---|---|
    | 无 | 无 | 无 | 无 | 无 | 无 | 无 | Codex自动处理 | 不适用 |

`决定`只使用：`指定代表/当前版本`、`全部比对后使用`、`仅使用明确范围`、`排除候选`、`暂不处理`、`待决定`；`决定方`只使用`内容运营`、`项目负责人（用户）`、`AI知识库专员`、`Codex自动处理`、`待定`、`无`；`当前状态`只使用`待决定`、`已决定`、`不适用`。候选最终排除也必须保留排除依据。

不要为正常命中建立候选文件审批、页码范围确认、样本确认或单独的资料就绪会议。但发现疑似重复/版本候选且文章问题依赖候选之间的选择时，必须先按来源台账关系门禁复用或建立一个归组MAT；不得随机选文件继续提取。视觉核验类候选先由Codex按需调用MinerU并结合原始PDF/PPT对照；若仍无法唯一判断，才暂停该文章的资料选择步骤，在文章目录的`文章前问题与处理单.md`使用“疑似重复/版本候选处理”固定提示模板并同步当前待办，先交内容运营处理；内容运营明确无法处理后退回项目负责人，由其决定是否指定AI知识库专员，以及代表版本、当前版本、全部比对或暂不处理。

### 命中资料的重复与版本选择

文章检索命中来源后，先检查来源台账的`重复/版本关系`、SHA-256和MAT列，再决定是否回源提取：

- 完全相同的SHA-256：复用台账中稳定代表资料的索引，记录代表`SRC`和其余重复路径，不建立MAT、不重复提取。
- 疑似跨格式、部分重合或新旧版本关系且SHA-256不同：文章依赖该组时先复用或建立一个MAT，详情列出全部候选`SRC`、关系信号、文章影响和待决定事项；决定前不得从任意候选建立Claim或`30`素材。
- 关系明确：按来源权威性、版本/日期、适用范围和当前知识问题选择，并在四列表的“处理结果”写明选取和排除理由。

任何“命中后直接取第一个文件”“按目录顺序选文件”“先整理一个文件再等决定”或未写选择依据的处理，均视为流程错误。候选组后续被其他文章命中时复用同一MAT并追加文章ID，不重复建项；每篇文章仍须在自己的15中记录本次依赖决定和最终资料集合。

人工提示只保留在处理单一个入口：MAT详情保存完整技术背景，`20_文章前知识审核.md`写`MAT ID + 处理单链接 + 是否阻塞`，当前待办写人话事项、责任人和处理单直达链接。人工回复后，Codex把决定同步回MAT详情、来源台账、处理单、20和当前待办，再从指定步骤自动恢复，不要求再次回复“继续”。

### 中途新增与随文文件

内容运营在项目运行中或随文章提交文件时，Codex先在`10_文章知识需求.md`的“随文章提交文件分类”表记录文件名、原始路径、SHA-256、文件性质、使用范围和处理结果，再自动分类：

- 项目长期事实资料：登记到来源台账，默认`项目级通用（默认）`、`全部文章（默认）`；只有文章命中时才提取正式Claim。
- 仅本篇事实资料：登记到来源台账，并写明特定文章ID和提交人给出的限制；只提取本篇实际命中的最小Claim。Claim仍按稳定主题存放，不按文章建文件或建立新ID类型。
- 写作要求、SEO/GEO、风格、结构或非事实参考：只保留在`10`，不进入来源正文索引、Formal Claim、`30`证据或Faithfulness上下文。
- 明确禁止提取正文：只登记文件身份，并写入`source-index-exclusions.json`；不得索引正文、建立Claim或进入`30`。

未明确限制的事实资料一律按项目级通用处理，不得因为它随某篇文章提交就自动限制为仅本篇。`30/35`交付前新增并命中的资料可在当前文章版本内吸收；交付后新增或事实输入改变时，先归档完整当前任务、递增文章版本并重建受影响步骤。文章已有终稿或Faithfulness后，普通新增资料不自动重开旧文章；只有客户更正、来源冲突或高风险事实确实影响旧文时才按版本合同重开。

## 2. Claim提取与核验

只有当前文章、客户澄清、异常解决或明确复用场景确实需要时才建立正式Claim。按稳定产品、政策或主题组织，不按文章建库，也不要求一个Claim一个文件。

管理字段用中文；最小原文证据保留来源语言。每条Claim必须有稳定Claim ID、Claim正文、适用范围、来源类型、来源链接、精确位置、最小原文证据、日期或版本、使用边界和状态。

索引片段、AI摘要、翻译或未确认OCR不能独立授权Claim。弱材料可以省略；如果文章核心依赖它，则进入MAT、CUS或ANM。

项目级竞品限制同时适用于客户来源和外部来源的写作输入：任何具体竞品品牌、型号、特殊产品、参数、价格、案例、排名或比较结论都不得进入Claim、`30/35`或文章事实附件。来源偶然包含此类内容时，若通用结论不能脱离该特定内容独立成立，整段排除并只记录不含名称的排除原因。

遇到客户源文拼写、语法或单位问题时，Claim核验必须区分原文值和规范化值。确定性修正可在Claim中使用，但要附修正记录；数值、单位、型号或语义存在不确定时只能受限使用或等待人工确认，不能凭外部知识替换客户事实。

目标文章不是中文时，只对本篇资料包中实际使用的Claim和必要上下文生成经过核对的目标语言表达，不翻译整份来源。译文必须保持型号、数值、单位、专名、否定和适用边界，并与原文证据同时保留。译文不能冒充客户原话。

## 3. 外部调研

前五层完成后，先按标题、主问题和一级/二级主要大纲识别稳定公共知识问题，并在唯一知识缺口CSV登记`gap_key`、当前文章和触发依据。核心章节或高风险公共事实首次、以及普通公共问题在第二篇不同文章出现时进入`待外部调研`；普通公共问题首次只进入`观察中`。

只有缺口状态已经是`待外部调研`且本篇没有禁止新外部调研时，才在文章前审核之前自动开展第六层调研。`允许`只是权限，不是触发条件；不得让`观察中`因本篇允许调研而提前研究。调研按稳定问题和最小Claim范围执行，不把整个主题重新研究一遍。内容运营可以限制：

- 本篇不开展新的外部调研：已有外部Claim仍可用；
- 本篇不使用任何外部来源：已有和新外部来源都排除。

禁止调研时优先缩小或删除无支持内容；只有核心大纲因此无法完成时才请内容运营做业务决定。

调研开始前在`15_检索与知识准备记录.md`写明`gap_key`、问题、范围和`已开展`；未达到触发门槛时写`新外部调研：未触发（观察中）`，禁止时写`本篇禁止`。写作模型自行联网搜索不属于本流程，不得事后补记成知识库已完成的外部调研。

外部调研只能支持去品牌化的行业概念、公共法规、公共标准、一般技术或市场背景，不能证明客户专属规格、产能、认证、案例、MOQ、价格或承诺，也不能保留竞品品牌、型号、特殊产品、参数、价格、案例、排名或比较结论。不得以竞品名称、型号、特殊产品或比较页为检索目标；偶然命中的竞品特定内容只记录“竞品特定信息，未采用”及类别，不保存可识别名称、链接或原文。只有脱离具体品牌/型号仍能独立支持通用结论的连续原文，才可去品牌化保留。

外部调研的来源优先级、原文与核验记录、失败路径、冲突/时效/排除规则和沉淀门禁，统一按[外部调研执行与沉淀合同](external-research-contract.md)执行。每个`RES-ID`固定分开保存`10_来源原文证据.md`和`20_调研核验记录.md`；普通来源只保留最小必要内容，动态、高风险、冲突、关键或难恢复来源把`10_来源原文证据.md`作为固定件。登录、付费墙、反爬、页面损坏或正文无法可靠取得时，记录失败和可授权替代材料，不把摘要或AI总结作为证据。

调研结果只要回答具体且可复用的公共知识问题，原文证据完整，支持/不支持范围、适用范围、数据日期和复核条件明确，不涉及客户专属事实，且通过文章前知识审核和项目校验，就立即沉淀到`03_正式知识/20_外部公共知识/50_行业知识与洞察/[稳定主题].md`。正式Claim回链`RES-ID`；对应`gap_key`从`待外部调研`改为`已解决`，并在项目运行账本记录沉淀事务。不等待终稿或Faithfulness。

## 4. 文章前知识审核

Claim准备和允许的外部调研完成后，每篇文章都自动审核：

- 拟写事实均有可用Claim或已明确排除；
- Claim范围、时间和版本适配文章；
- 客户来源和外部来源没有混淆；
- 冲突版本、事实异常和公开限制已处理；
- 当前文章依赖的MAT或CUS清晰可见；
- 最终文章、摘要和索引片段未被当作证据。

审核时完整执行[知识缺口与CUS/ANM检测协议](governance-detection-and-lifecycle.md)。前五层完成后形成初次覆盖判断并登记缺口；允许且必要的第六层调研完成后，再把标题、主问题及一级/二级主要大纲的最终覆盖状态写入`20`。`部分覆盖/未覆盖`必须关联既有`gap_key`、CUS、MAT或ANM，或者说明为什么只是结构、过渡、CTA或不可复用内容。公共知识缺口在调研前、写作前即登记，不等待终稿或Faithfulness；文章仍可按排除、缩小或中性改写继续，不设置覆盖率或Faithfulness门槛。

CUS与ANM不能只在“明显发现”后顺手登记。每篇文章都要在`20`固定写出两行检测结果：CUS候选检测必须记录客户专属事实的六层检索及MAT/公共缺口/ANM/可删除要求排除；ANM异常检测必须记录版本、定位、提取、数字/型号/单位/OCR、来源冲突、残缺证据和危险外推检查。来源处理阶段已发现的事项在此复用原ID；未触发也写清实际检查范围，不能只写“已检查”。

结论只用：自动通过、带明确排除通过、等待内容运营处理、等待项目负责人决定、等待知识库专员处理。

前两类只保存文章ID、日期、Claim数量、来源类型、排除项和非阻断问题，不通知内容运营确认。结论为后两类时，必须在同一文章目录生成唯一`文章前问题与处理单.md`，把错误、冲突或待决定事项按同一责任人和解决条件归组，用普通话写清发生了什么、对文章有什么影响、Codex已经自动处理了什么、还需要谁决定或提供什么、可选方案、推荐依据、决定后自动返回哪一步。文章阻塞事项先指定内容运营；内容运营明确无法处理后，处理单才将责任升级为项目负责人，由项目负责人决定是否指定AI知识库专员。不能只在聊天中说有问题，也不能只给ANM/CUS/MAT编号；处理单应链接对应台账、证据和原文件位置，并由`20_文章前知识审核.md`和当前待办双向链接。

能由原始证据和固定规则唯一修复的提取、链接、格式、确定性规范化或状态错误由Codex自动修复，不生成处理单。来源冲突、事实含义不确定、公开边界不明、不可替代客户事实缺失等无法自动决定且会影响文章的事项，才进入处理单。处理单状态只用`等待人工处理 / 已处理，待自动复核 / 已关闭`。人工给出决定或材料后，Codex自动从处理单记录的返回步骤继续，更新审核并推进到成对生成`30_本篇知识库资料.md`和`35_写作素材来源索引.md`；不得再次要求人工说“继续”。

处理单是文章级聚合入口，不替代项目治理台账：缺少或待确认客户事实写入CUS，复杂资料/工具处理写入MAT，源文错误、来源冲突和事实风险写入ANM；处理单链接这些事项的人话详情。开放处理单必须进入当前待办，并由月度审核和交接逐篇列出文章ID、文章标题、处理单文件名、当前状态和直达链接，再汇总未关闭治理事项与文章任务；不能只写处理单ID或四类台账总入口。问题关闭后同步审核、当前待办、相关台账和最近一次月度/交接记录，并保留关闭后的历史链接。普通事项阶段变化不写版本入口，只有流程回退、结构迁移或其他项目级变更才写项目变更。

## 5. 写作素材包与来源索引

写作视图固定写入`30_本篇知识库资料.md`，标题为“本篇写作素材包”。它是唯一交给写作Codex或作者的知识附件，固定包含六节：可直接用于正文的事实、可直接采用的英文表达、可使用的数据表、按大纲使用、仅供生成控制（不得写入正文）、缺少资料的章节及建议处理方式。第一至第三节按事实块或数据块保留连续来源正文，或经核验的目标语言忠实翻译；允许筛选、重排并给出便于成文的表达，但不得仅用AI总结替代证据正文。

`30`只保留经核验且适合成文的信息，不显示Formal Claim ID、来源URL、精确位置或详细审计理由；但每个可审计事实必须显示不带审计元数据的“证据正文”。英文来源保留选中的英文连续语义块；非英文来源保留经核验的目标语言忠实翻译；表格保留表头、数值、单位、条件和脚注。第五节只写简短控制规则，并明确不得把`not supported`、`no evidence`、`cannot determine`、`does not provide`、`requires separate verification`等审核语言写进文章。第六节用“删除小节、缩小范围、中性改写”等动作描述资料缺口，不把缺口解释扩写成正文素材。

内部追溯视图固定写入`35_写作素材来源索引.md`。它只保存当前`30`的SHA-256、明确标记的“证据正文”1基行范围、Formal Claim ID、可读Claim标题、正式知识文件与原始来源精确位置。它不复制Claim正文、完整证据、使用边界、排除项或审核推理，不进入写作上下文。完整Claim和原文证据仍以正式知识文件为唯一当前入口。

标准v0.5写作流程只交付一个事实附件：`30_本篇知识库资料.md`。随文章提交的事实文件必须先进入来源层、最小Formal Claim和`30/35`，不能作为平行附件直接交给写作模型。写作要求、风格和SEO/GEO文件不属于事实附件，也不进入Faithfulness。

需求、大纲、来源或Claim变化时，先按[当前版本与历史归档合同](version-and-archive-contract.md)把修改前的完整任务目录归档，再递增文章版本并成对重建`30/35`；当前任务只链接一个现行文件对。生成`30`后计算SHA-256写回`35`，再校验映射行号、文章ID和文章版本。不得只更新其中一个文件，也不得只归档`30`而丢失它对应的需求、审核和`35`。

进入`20_等待终稿`前必须同时满足：`10/15/20/30/35`存在且文章ID一致；`35`记录的素材哈希等于当前`30`；六层检索均为确定状态；审核结论为`自动通过`或`带明确排除通过`；若曾生成问题处理单，其状态已为`已关闭`；项目及文章状态门禁无错误。只有全部满足时才原子移动整个任务目录，并通知内容运营只使用`30_本篇知识库资料.md`写文章。

## 6. 终稿与后续

内容运营或其写作流程提供`40_最终文章.md`，至少含文章ID、文章版本、完成日期和正文。不再提交旧RAG或平台引用率。

保存文章SHA-256，使用`scripts/create_faithfulness_record.py`立即创建`50_文章知识使用与Faithfulness记录.md`并把状态写为`等待Faithfulness结果`，随后转入`30_等待Faithfulness`。`50`同时记录终稿、`30`、`35`及外部审核目录的入口；内容运营可以提交审核结果文件，也可以只登记一个已完成的受管结果目录供Codex读取。Codex不得扫描未指定的宽泛目录猜测对应结果。

外部审核必须针对实际交给写作Codex的当前`30`。`35`、Formal Claim、原始来源和写作要求都不进入审核上下文。任何终稿修改都先归档修改前的完整文章版本，再递增文章版本并产生重审要求；旧Faithfulness保留为历史并标记`superseded`，不由本Skill猜测修改是否影响事实。

外部结果导入后，只有文章和实际写作素材包版本匹配、`30/35`机器映射仍有效、分数与计数已记录、可确定的Claim支撑关系已导入、项目级Claim支撑总表已按不同文章ID重算、必要后续已登记且校验通过，知识任务才能关闭。`50`只把这种关系称为“正式知识对文章事实的事后支撑”，不得声称模型实际调用了Claim。Faithfulness是“实际交付事实附件的支持率”，不是SEO/GEO文章质量、可发布性或是否允许模型自由完成文章的总分；不设置100%通过线，也不得因为普通自由发挥项未被附件支持而自动退回写作。知识库Skill不据此要求改写文章；它只把事实性或可复用的未覆盖问题送入对应知识治理入口，纯写作内容才只在本篇记录排除理由。

unsupported只表示给写作Codex的知识上下文没有支持该文章事实，不自动等于事实错误，也不要求重写或阻塞交付。但知识治理分类仍要区分：纯结构、过渡、CTA、修辞、不可复用观点或其他非事实内容可以归为`writing_only`；一般原理、行业常识、技术解释、方法判断或采购建议只要可以判断真假或跨文章复用，就必须继续判断为公共知识缺口、资料包覆盖遗漏或其他治理类别，不能因为文章可以自由补充而排除。终稿不是证据，不能反向建立Formal Claim。

导入后，Codex必须按[知识缺口与CUS/ANM检测协议](governance-detection-and-lifecycle.md)把全部unsupported claim_id恰好归组一次，而不是逐条原子事实建事项。优先复用文章前的稳定问题；已有知识但漏入`30`记为资料包覆盖遗漏；客户专属事实进入CUS；相关本地资料尚未处理进入MAT；来源冲突、危险外推或事实风险进入ANM；只有纯过渡、结构、CTA、修辞、不可复用观点和其他非事实写作才可归为`writing_only`。任何事实性或可复用内容不得用该类别排除，混合组必须拆开。公共知识候选完成前五层复查后仍未覆盖时，写入`05_数据与审核/20_知识库覆盖与缺口/10_知识缺口记录.csv`，同一`gap_key`内按不同文章ID去重。`50`必须把分类、依据、事项入口、当前处理和下一步拆列显示，不能继续输出统一的“单篇观察，不自动处理”。

公共知识缺口满足以下任一项，首次即标为`待外部调研`：

- 它是文章标题、主问题或一级/二级主要章节不可缺少的回答，删去后该承诺无法完成（`核心章节首次`）；
- 它涉及法规、标准、认证、安全、限值、检测有效性、采购选型或随地区、时间变化的公共事实（`高风险事实首次`）。

其余首次出现的公共知识记为`观察中`（`首篇普通缺口`）。相同`gap_key`在第二个不同文章ID出现时，自动升级为`待外部调研`（`重复文章`）；同一文章的多条未覆盖事实或新版本不能增加出现文章数。Faithfulness导入和缺口登记完成后，新增`待外部调研`项在本篇未禁止新调研时作为独立知识维护事务执行；`观察中`不执行。调研完成并形成可用外部Claim后标`已解决`，更新RES证据、正式知识、缺口、覆盖视图、运行账本和`50`中的治理状态/回链；不得改变原Faithfulness判断、分数、哈希或当前`30/40`，不自动改写或重审当前文章。用户明确要求修订当前文章时，才归档旧版本并重建写作附件、终稿和Faithfulness。确认不再需要或不能在允许范围内处理时标`已关闭`并写关闭依据。

不要把终稿变成证据，不要从终稿反向建立正式Claim，也不要自动改写已完成或已发布文章。
