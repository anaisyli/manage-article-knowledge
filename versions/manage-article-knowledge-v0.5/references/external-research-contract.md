# 外部调研执行与沉淀合同

本合同只约束 Codex 外部公共知识调研。它不恢复 v0.4 的固定人工节点、逐链接批准或强制多Agent。外部调研仍按一个具体公共知识问题执行，不能替代客户来源证明企业专属事实。

## 0. 竞品信息排除门禁

项目级竞品限制默认开启，文章只能继承或进一步收紧，不能放宽。检索词、检索目标和来源筛选不得指向具体竞品品牌、型号、特殊产品、价格、案例、排名或比较页。偶然命中的竞品页面或含竞品特定表达的内容不得保存为RES证据、正式Claim、`30/35`或报告；只在调研核验记录或项目运行记录中写“竞品特定信息，未采用”及类别，不保留可识别名称、链接或原文。

普通行业来源若顺带出现具体品牌/型号，只有不依赖该特定对象、脱离后仍能独立支持通用结论的连续原文才可保留；应排除涉及特定对象的句子，并在核验记录中说明“已去品牌化，通用结论独立成立”。不得把竞品宣传、产品页或对比表改写成通用行业事实，也不得通过来源标题、URL或引用片段间接保留其身份。

## 1. 调研触发与队列消费

外部调研有两个发现入口，但只有一个触发门槛：先完成已有正式Claim、客户源资料索引、客户官网、客户关联网站和已有外部公共Claim五层检索；仍存在的稳定公共知识问题必须先登记`gap_key`和文章，再根据规则得到`观察中`或`待外部调研`。只有状态已经是`待外部调研`且适用任务没有禁止新外部调研时，才消费队列。`允许`只代表权限，不是触发器；不得据此研究`观察中`缺口。

- **写作前入口**：标题、主问题或一级/二级主要大纲发现缺口后先登记；达到门槛的，在同一文章知识准备事务中、生成`20/30`前立即调研。开始前在`15_检索与知识准备记录.md`写明`gap_key`、问题、范围和`已开展`。
- **写作后入口**：Faithfulness的unsupported完成归组、前五层复查和缺口登记后，新增`待外部调研`项在导入完成后作为独立知识维护事务执行；更新关联`50`中的治理状态/回链、缺口记录和项目运行账本，但不得改变原Faithfulness判断、分数、哈希或当前`15/20/30/40`内容。
- **维护入口**：此前因禁止、失败或其他真实阻塞未完成的`待外部调研`项，在后续相关文章准备、维护处理或月度行动时继续消费；`观察中`只累计不同文章次数，不进入调研。

禁止新调研时保持缺口状态并记录限制，不伪造已研究结果。写作Agent自行联网搜索没有`gap_key`、`RES-ID`、原文证据和核验记录，不属于本Skill外部调研，也不得事后补记成写作前证据。

## 2. 来源优先级

通常按以下顺序选择来源：

1. 原始官方页面或文件；
2. 政府、标准机构或研究机构；
3. 权威行业组织；
4. 能定位作者、日期和原始依据的专业媒体。

后一层不能无说明地替代仍可取得的前一层。搜索结果页、聚合页、无署名转载、AI回答和无法定位原文的摘要不是正式来源。

## 3. 证据记录形态

每次调研使用一个`RES-ID`目录，把原文证据和调研结论分开保存。普通来源的两份文件都只保留最小必要内容，不为每个普通网页建立厚重档案；动态、高风险、冲突、关键或难恢复来源才扩展原文证据文件为可靠固定件。

```text
02_源资料/50_外部调研证据/[RES-ID]_[稳定主题]/
  10_来源原文证据.md
  20_调研核验记录.md
```

`10_来源原文证据.md`只保存来源身份、原文证据和取得范围，不写AI结论、翻译或补齐内容。动态、高风险、关键、来源冲突、难以恢复或普通页面无法稳定复现时，使用可靠固定件并记录内容指纹；只能取得摘要或片段时必须标记`原文不完整`，不得扩展成完整结论。

## 4. 失败路径

登录、付费墙、反爬、脚本渲染失败、页面损坏或正文无法可靠取得时，记录失败URL、失败层级、时间、已取得范围和原因；不绕过限制，不把搜索摘要当证据。优先请求有权取得的HTML、PDF或可见主正文；只有关键登录态或交互状态不能用其他材料替代时才使用Web Clipper。失败来源不能形成可用Claim，状态保持`失败待补材料`或进入对应异常事项。

## 5. 形成正式知识的门禁

外部调研满足以下条件后，立即进入正式知识沉淀，不等待文章终稿或Faithfulness：

- 回答一个具体且可复用的公共知识问题；
- 原文证据已取得并可精确定位；
- 已明确来源支持什么、不能支持什么、适用范围、数据日期和使用前复核条件；
- 没有把外部知识外推为客户专属规格、产能、认证、案例、MOQ、价格或承诺；
- 已通过竞品信息排除门禁：Claim和证据不含可识别竞品品牌、型号、特殊产品、参数、价格、案例、排名或比较结论，且通用结论不依赖被排除的特定对象；
- `20_文章前知识审核.md`已完成，Formal Claim和项目校验通过。

沉淀到：

```text
03_正式知识/20_外部公共知识/50_行业知识与洞察/[稳定主题].md
```

正式知识只保存可复用的Claim、最小原文证据和边界，并回链`RES-ID`的`10_来源原文证据.md`与`20_调研核验记录.md`；完整来源原文仍留在`02_源资料/50_外部调研证据/`。写入完成后，把对应缺口从`待外部调研`改为`已解决`，在`related_governance_ref`关联`RES-ID`和正式知识文件，并在项目运行账本记录沉淀事务。

外部公共Claim统一使用`CLM-EXT-[项目]-[主题]-NNN`编号；客户Claim使用`CLM-[项目]-[主题]-NNN`编号，两个命名空间分别计数。新增外部Claim只在同一`CLM-EXT-[项目]-[主题]-`前缀下取下一个连续编号，不得读取客户Claim编号，也不得跳号。每条外部Claim必须在自身区块内写出`### 最小原文证据`连续引用块；缺少该区块即使有`RES-ID`回链也不能形成正式知识。

## 6. 动态、冲突与不采用

- 价格、市场规模、政策、法规和趋势等动态事实必须写数据日期；旧来源须说明原因；需要长期复核的内容写复核条件，不当作无期限稳定事实。
- 权威来源冲突时并列记录来源、日期和差异，不自动合并；会改变文章结论时进入人工处理或保持缺口未解决。
- 高相关但被排除的来源记录排除原因，避免下次重复调查。
- 只有当前文章有用、来源不可靠、原文不完整、无法确定适用范围或只是AI推断的内容，不沉淀为正式知识。
