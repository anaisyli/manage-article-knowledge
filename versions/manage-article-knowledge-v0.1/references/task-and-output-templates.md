# 任务与输出模板

所有面向人工的材料、任务、缺口、冲突、确认项和选项统一使用`编号｜人能看懂的业务标题`。编号只用于检索，不能单独作为显示内容；不得让运营根据`SRC-0008`、`GAP-C03`、`T-002`或“第2项”猜测对象。确认步骤使用“外部候选来源选择”“本批材料处理总纲确认”“派生处理执行确认”“文章写作放行确认”“正式知识沉淀确认”等真实名称，不输出`确认G6`或只显示其他内部代码。

阶段文件不设置固定的“下一步”区块。文件交付完成后，在当前聊天中简短说明当前步骤、运营现在要做什么、确认后Codex会做什么，以及如何退回修改；当前动作最多三项，没有人工动作时明确说“无需操作”。

```markdown
## 客户沟通卡

客户专属事实不放入上面的大宽表。每个独立问题按`article-material-output-template.md`的“需要客户资料或确认”生成一张卡，至少包含：

## 在线研究候选

- 来源类型、质量分和时效判断；
- 能支持的具体内容；
- 不能支持或不能外推的内容；
```

```markdown

status: pending

  - A-001

---

补齐文章A-001所需的产品A应用场景。

## 输入

- 资料ID：SRC-001
- 权威原始路径：客户原始资料路径/产品案例PPT.pptx
- 范围：幻灯片10—18
- 批次或结构分组：单份 / 同类第X组
- 代表性样例：不适用 / 本任务为样例 / 已批准样例T-XXX

- 使用的产品或方案；

2. 客户原话描述的问题

- 无法确认的客户名称；
- PPT中未明确提供的效果推断。

高风险事实和参数紧邻记录PPT文件名及幻灯片编号；同一页面支撑一组普通描述时可在段落或小节末统一记录。
```
