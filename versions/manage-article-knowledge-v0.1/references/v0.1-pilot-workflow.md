## 1. 试用目标

用一个真实客户完成至少一轮：

```text
项目初始化
→ 资料登记与轻量扫描
→ 2—3篇文章资料准备计划
→ 收集并定向处理候选资料
→ 人工确认
→ 文章就绪审核
→ 正式知识沉淀
```

v0.1不以整理全部资料、部署多人同步或自动写完文章为目标。

## 2. 开始前准备

运营提供：

| 输入 | 必填 | 说明 |
| --- | --- | --- |
| 客户名称 | 是 | 中文名；英文名未知可待确认 |
| 官网 | 是 | 没有或无法访问时说明 |
| 服务类型 | 是 | SEO、GEO或其他 |
| 项目状态 | 是 | 未开始、进行中、暂停或结束 |
| 负责人/小组 | 是 | 当前主要运营 |
| 行业 | 是 | 现有分类；没有统一分类时保留原值 |
| 目标市场/语言 | 建议 | 不清楚时标记待确认 |
| 客户原始资料路径 | 是 | 必须是精确文件夹或文件范围 |
| Obsidian项目路径 | 是 | Codex允许写入的位置 |
| 本周文章计划 | 第二阶段必填 | 2—3个关键词、标题或大纲 |
| 公开限制 | 建议 | 客户名称、案例、竞品、合作方、价格和内部信息等 |

RAG SEO尚未接入时：

- 生成稳定的本地项目ID，如`LOCAL-20260726-01`；
- 单独保留`ragseo_project_id: pending`；
- 后续获得平台ID时建立映射，不重命名已有资料ID。

## 3. 初始化项目

1. 显示客户资料路径和Obsidian目标路径。
2. 检查是否误指向其他客户项目。
3. 读取人工闸门，必要时确认写入范围。
4. 建立最小目录和以下控制文件：
   - 项目说明；
   - 资料索引；
   - 资料内容导航；
   - 知识地图；
   - 风险与待确认；
   - 更新日志。
5. 写入已知项目字段；未知字段写`pending`，不猜测。

项目根目录固定为`00_项目管理 / 01_资料处理 / 02_正式知识 / 03_文章任务 / 04_归档`。原文证据、翻译、结构稿和项目资料稿统一进入`01_资料处理`；文章任务只保存本篇要求、资料选择、审核和写作后记录。

初始化不读取全部原始资料正文。

## 4. 登记和扫描资料

### 稳定资料路径

客户文件已经位于长期保存的项目文件夹时：

- 原位登记；
- 不复制到Obsidian；
- 保留客户原目录层级；
- 计算内容指纹；
- 建立资料ID；
- 做轻量扫描；
- 对可搜索文件建立全文件结构导航；
- 更新资料索引和资料内容导航。

### 临时资料路径

资料位于下载、桌面、临时目录或个人随手目录时：

- 只读扫描；
- 提示运营选择长期保存位置；
- 不删除或移动；
- 未确认长期位置前标记`待确认存储`，不标记`已登记`。

### 扫描输出

输出：

- 文件和文件夹概况；
- 可直接读取、建议使用版面工具、需要OCR或暂时无法处理的资料；
- 完全重复、疑似新版本和异常；
- 对本周文章可能有用的资料；
- 不建议现在处理的资料。

## 5. 制定本周文章资料准备计划

运营提供2—3篇文章的：

- 关键词；
- 标题；
- 大纲；
- 目标产品；
- 目标市场和语言；
- 发布时间或优先级；
- 特殊要求。

Codex逐篇生成：

| 项目 | 内容 |
| --- | --- |
| 文章要求 | 关键词、语言、市场、品牌、视角和不得编造字段；外文大纲同时显示原文与中文理解 |
| 已有本地资料 | 资料ID、资料显示名称、原始文件名、原始相对路径及人工可读位置或待结构扫描 |
| 已有官网资料 | 具体URL或页面类型 |
| 文件处理建议 | 按格式、语言、表格、图片和提取质量选择方法 |
| 官网获取建议 | 默认Codex提取；无法可靠读取时由运营提供页面文件、复制原文或最后使用Web Clipper |
| 未覆盖内容 | 当前官网和本地资料没有找到的部分、来源类型及A/B/C等级 |
| 搜索准备 | 客户索取内容、关键词、来源方向及运营/Codex/客户分工 |
| 待运营选择 | 本周批准处理和暂不处理的范围 |

标题和大纲只用来确定资料范围，不在此阶段审核大纲质量。外文大纲逐级保留原文，并在同一条后增加中文理解；中文只帮助运营阅读，不替代或改写原文。不要输出“可以写”“有限度可写”或“暂不建议开始”。

遇到大量图片时，先报告页码、幻灯片或章节范围。只整理带明确文字、标签、图例或数据的图片；纯产品、展会、工厂、客户合影等图片标记`视觉素材，未整理`。

DOCX不得把程序段落序号写成页码，也不把它作为运营主要定位。默认使用可见标题路径、起止标题和开头文字；程序段落号只在Codex调试或复核时作为可选辅助字段。只有固定渲染版本后才能使用`渲染页码`。

## 6. 收集候选资料

运营根据准备计划选择：

- 选择本批准备采用的本地文件、网页和初步范围；
- Codex无法可靠读取登录、动态或平台受限页面时，由运营提供下载文件、页面原文或必要时使用Obsidian Web Clipper；
- 让Codex按指定缺口开展受控在线研究并生成研究Markdown；
- 自己搜索后优先把候选网页URL交给Codex；已经使用其他工具生成Markdown时，在生成本批总纲前把稿件一起交给Codex，并负责完成初步质量核对；
- 只有客户能确认且文章确实需要的资料，先生成单主题客户沟通卡，再交AI知识库专员或优化师/组长；
- 本周暂不处理低优先级内容。

处理缺口前先判断：

```text
现有资料待处理 / 客户专属事实 / 公开行业知识
→ A写作前必须补齐 / B质量补充 / C月末观察
→ 输出首选动作、客户索取字段、搜索关键词、研究方式和保存位置
```

Codex研究、运营Google搜索和运营微信公众号搜索最终都要形成可追溯的网页来源稿Markdown。Codex新找到的链接先生成`GAP-Rxx_候选来源与提取方案.md`，由运营确认哪些页面纳入本批；入选页面再进入总纲确认提取大纲。运营自己找到的页面通常只需提供真实URL。市场、趋势和竞争资料优先最近24个月；可以使用免费行业报告和付费报告的免费公开摘要页，但不得推断付费正文，四年以上资料一般不用于证明当前情况。

已知官网、SPU或产品名称时，Codex在资料准备阶段自动查找链接和扫描页面结构，不等待运营批准开始查找。新找到的页面先给出真实直达链接、页面身份、日期、能支持和不能支持的内容，由运营完成GR来源选择。材料收齐后，把确认纳入网页的拟提取栏目/字段、方法、排除范围、大纲和输出位置写入《本批待处理材料总纲》，等待GE确认。只有Codex不能可靠取得页面正文时，才建立运营交接任务，并按“运营提供下载文件/PDF或HTML → 复制可见原文 → Web Clipper”的顺序选择。实际查找后仍无法确认链接时标记`等待Codex继续查找`，并写明已尝试方式、`运营现在无需操作`及Codex下一步。

候选资料先进入当前文章资料清单或临时研究层。Codex原样接收运营外部提取稿；此时不改结构、不处理表格、不翻译，也不自动进入正式知识。

不论资料格式，提取稿只能保存原文，不允许总结、润色、改写或补全。运营使用外部工具生成的提取稿放入待核验目录，运营负责核对是否漏段、乱序或改写；没有原来源或未完成必要复核时不得标记为逐字原文。

## 7. 建立并处理Work任务

Codex新找到的外部链接完成GR来源选择、运营选定其余材料并提交自己已有的外部提取稿后，按周期和文章ID建立：

```text
03_文章任务/
└── 2026-W30/
    └── A-001_文章主题/
        ├── 00_任务与确认/
        │   ├── 文章要求.md
        │   ├── 文章大纲_中英文.md
        │   ├── 资料准备反馈.md
        │   ├── 本批待处理材料总纲.md
        │   ├── 本批派生处理执行单.md
        │   └── 候选来源方案/
        ├── 10_文章资料/
        │   ├── 来源清单.md
        │   ├── [文章ID]_文章资料选择表.md
        │   └── [文章ID]_文章写作资料包.md
        ├── 20_审核与问题/
        │   ├── [文章ID]_写作分析与对照稿.md
        │   ├── 风险与待确认.md
        │   └── [文章ID]_文章知识就绪报告.md
        └── 30_写作后记录/
            └── [文章ID]_文章引用清单.md
```

处理顺序：

1. 只读扫描资料结构、提取质量和相关范围；
2. 为Codex新找到的外部页面生成候选来源方案，由内容运营完成“外部候选来源选择”；
3. 原样接收运营已经获得的外部提取稿；
4. 生成覆盖全部材料的《本批待处理材料总纲》，写明范围、方法、大纲、语言、特殊结构、后续操作和输出；
5. 内容运营完成“本批材料处理总纲确认”；
6. Codex只处理批准的页码、章节、Sheet、URL或时间段；
7. 给原始稿副本统一标题和来源属性；
8. 核验原始提取稿的漏段、乱序、乱码、数字、型号、单位、表格和来源；
9. 根据实际提取稿生成《本批派生处理执行单》，展示文章大纲层级、表格/图表样例和翻译计划；
10. 内容运营逐项完成“派生处理执行确认”；
11. 按确认结果完成层级整理、表格、翻译、项目资料稿或最小改动审核，各类稿件分别保存；
12. 完成项目资料稿完整性检查，建立并确认文章资料选择表；
13. 运行文章就绪审核，由内容运营完成“文章写作放行确认”；
14. 放行后生成包含风险标签和使用提醒的文章写作资料包；
15. 必要时建议MinerU、Docling或OCR；发现视频时给运营逐句稿/字幕稿准备说明；
16. 使用外部API或付费工具前触发人工确认；
17. 把问题集中写入风险与待确认。

所有来源稿和原文证据都保留原材料措辞，统一放在项目`01_资料处理/`；不得在提取过程中总结、润色或改写。为了按文章逻辑组织内容，可以在文章`20_审核与问题/`中建立独立分析稿，但每个引用片段仍须逐字保留，并指回source_id、原始文件/页面标题、URL或原始位置。

## 8. 文章就绪审核

只有运营准备的候选资料已经进入Work，并完成当前需要的结构整理、表格处理、翻译和事实核对后，才运行本步骤。

输出唯一主结论：

- **可以写**：核心知识和证据足够；
- **有限度可写**：可以写，但必须遵守明确限制；
- **暂不建议开始**：核心缺口或风险尚未解决。

“有限度可写”和“暂不建议开始”触发人工选择：

- 向客户补资料；
- 进行受控在线研究；
- 缩小文章范围；
- 更换选题；
- 接受明确限制后继续。

未经选择，不自动绕过缺口。

## 9. 客户反馈

运营把客户答复交给Codex时，同时提供：

- 确认人；
- 日期；
- 沟通渠道；
- 客户原话或准确答复；
- 是否允许公开；
- 影响的产品或文章。

Codex：

- 更新风险与待确认；
- 更新文章就绪结论；
- 将新事实作为正式知识候选；
- 不把“客户没有反对”当成已确认。

## 10. 正式文章终稿与写作后回收

正式文章终稿提交后，Codex默认生成或更新该文章的引用清单，不需要运营另行提出。记录文章ID、版本、正文文件、内容指纹、文章位置、来源ID、来源位置、支持方式和核验状态；无法可靠对应来源的具体内容标记“未追踪”，不得跳过整份清单或猜测来源。

根据引用清单、文章资料选择表、任务日志和人工反馈更新有可靠证据的知识块指标。文章新增说法只能作为线索，不能反向成为知识来源；正式知识候选仍回到项目资料稿和原文证据核对。

## 11. 正式知识沉淀

文章处理完成后，Codex提出候选：

- 候选知识；
- 建议写入的正式知识文件和位置；
- 来源和证据；
- 是否与现有知识冲突；
- 后续复用价值；
- 公开状态。

人工批准后才更新正式知识、知识地图和更新日志。

经过核验、可追溯的企业自身信息不以本篇是否使用为沉淀条件。公开待确认、来源冲突、动态快照和限定范围内容保留风险标签，不自动排除；冲突版本并列保存。

不进入正式知识正文：

- 客户明确禁止使用的内容；
- 无法取得或核对可靠正文的内容；
- `summary`、`inference`和无来源AI说法；
- 已被正式知识完整覆盖的重复提取。

## 12. 试用复盘

完成一轮后记录：

- 哪一步最耗时间；
- 哪些文件无法可靠处理；
- 哪些人工确认最频繁；
- 运营是否看得懂输出；
- Work是否支持文章写作；
- 哪些知识值得复用；
- 哪些A/B/C知识缺口反复出现，应该由AI知识库专员集中审核客户沟通卡或统一研究；
- 是否需要安装外部工具；
- 是否值得进入多人同步试点；
- Skill需要修改什么。

v0.1验收至少满足：

1. 原文件未被修改或丢失；
2. 资料索引能定位原文件；
3. 至少一篇文章先完成资料准备计划，再完成Work和就绪审核；
4. 原文、翻译和整理没有混淆；
5. 人工确认有记录；
6. 至少一个正式知识候选完成批准或明确拒绝；
7. 未把试用结果冒充公司级同步、绩效或引用率系统。
