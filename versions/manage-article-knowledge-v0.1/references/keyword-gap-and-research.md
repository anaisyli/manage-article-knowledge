## 1. 目标

关键词有流量只说明“值得准备资料”，不说明知识库已经足够写。先回答：

> 围绕这个主题，现有官网和本地资料覆盖什么？还需要准备什么候选资料？

资料准备阶段只决定资料去哪里找、怎样取得和怎样处理，不评价大纲质量，也不运行文章就绪审核。

## 2. 关键词输入

尽量读取：

- 主关键词和相关词；
- 搜索量、趋势、难度或商业价值；
- 目标国家、语言和搜索引擎；
- 搜索意图；
- SERP特征或当前排名页面；
- 拟定标题、大纲和目标产品；
- 业务优先级和转化目标。

数据字段缺失时仍可分析，但必须说明没有使用哪些关键词指标。不要虚构搜索量、排名或竞争度。

## 3. 从关键词到资料需求

为每个关键词或文章建立：

| 字段 | 说明 |
| --- | --- |
| 搜索意图 | 信息、比较、选型、问题解决、交易等 |
| 资料覆盖点 | 为准备主题可能需要的产品、公司、案例、选型或行业内容 |
| 所需企业资料 | 客户自身产品、能力、案例和服务资料 |
| 所需行业资料 | 原理、分类、标准、趋势和通用问题资料 |
| 所需形式 | 参数表、客户原话、案例、文字型图片、数据或第三方来源 |
| 已有候选来源 | 正式知识、原始文件、官网页面或已保存网页 |
| 当前未覆盖 | 本地资料和官网没有找到的部分 |
| 获取方式 | 客户索取、原始资料提取、Codex网页提取、运营提供URL/页面文件、必要时Web Clipper或内部确认 |
| 资料状态 | 已有候选资料、待结构扫描、需要补充资料或待运营选择 |

这张表用于准备候选资料，不评价大纲是否合理，也不为了凑齐大纲让AI补写缺失事实。

## 4. 资料缺口状态

资料准备阶段只使用：

- **已有候选资料**：已定位相关正式知识、原始文件或官网页面；
- **待结构扫描**：可能存在相关资料，但尚未定位页码、章节或Sheet；
- **需要补充资料**：现有官网和本地资料没有覆盖；
- **待运营选择**：需要决定Codex研究、运营提供URL、生成客户沟通卡或暂不处理；Web Clipper只在Codex无法可靠读取页面时作为备用。

不要在这里输出“可以写”“有限度可写”或“暂不建议开始”。必要候选资料完成收集和Work处理后，再调用文章就绪规则。

## 5. 缺口来源与紧急程度

先判断缺口属于哪一种来源：

| 来源类型 | 判断 | 默认动作 |
| --- | --- | --- |
| 现有资料待处理 | 正式知识未覆盖，但本地文件、官网或已保存网页可能已有 | 先结构扫描和定向提取，不重复上网研究 |
| 客户专属事实 | 只有客户能确认的产品参数、能力、案例、反馈、公开范围、交付或经营数据 | 先判断文章是否必须使用，再生成单主题客户沟通卡；行业网页不能替代 |
| 公开行业知识 | 原理、分类、法规、市场、趋势、采购方法或公开竞品事实 | 运营批准后由Codex或运营在线研究 |

再按当前文章影响标记紧急程度：

| 等级 | 含义 | 默认动作 |
| --- | --- | --- |
| A 写作前必须补齐 | 缺失会使文章核心事实不成立、高概率写错或产生合规风险 | 停止受影响的写作分支，先提取、索取或研究 |
| B 质量补充 | 可以先处理其他部分，但缺失会使文章空泛、证据弱或无法给出具体判断 | 建立发布前补充任务；写作中发现时新增缺口记录 |
| C 月末观察 | 不影响当前核心内容，当前价值或复用价值尚不确定 | 记录到缺口台账，不为单次需求立即扩大研究 |

不要在v0.1预设“出现几次必须升级”的固定数字。记录首次发现、最近发现、影响文章数、关联文章、最近一次运营决定、候选资料状态、记录方式、复用范围和获取成本；同一缺口在同一篇文章中反复退回不重复计数。月末只汇总运营选择“纳入月末汇总”的缺口，合并同义项后再决定统一补充、建立行业知识、向客户集中索取或继续观察。

## 6. 缺口行动清单

每个缺口只给一个首选动作，并列出必要的替代方式。至少输出：

| 字段 | 要求 |
| --- | --- |
| 缺口ID与话题 | 用业务人员看得懂的名称 |
| 为什么需要 | 说明影响的文章部分，不把它写成大纲质量评价 |
| 来源类型 | 现有资料待处理 / 客户专属事实 / 公开行业知识 |
| 紧急程度 | A / B / C及简短理由 |
| 首选动作 | 定向提取 / 客户沟通卡 / Codex研究 / 运营研究 / 月末观察 |
| 客户资料或确认 | 一事一卡，提供可直接转发的问题、可接受证据、确认人、日期和公开权限；不只写“补充资料” |
| 搜索关键词 | 2—5组可直接使用的中英文词组 |
| 研究方式 | Codex公开网页研究 / 运营Google搜索后提供URL / 运营微信公众号搜索后提供URL或页面内容 |
| 预期交付 | 客户文件、书面确认、网页来源稿Markdown或Work证据 |
| 保存位置 | 当前文章候选目录、临时研究目录或缺口台账 |

不要把“材质一致性、颜色定制、负责任采购、限量权益、区域销量”等不同问题合并成一张卡，也不要把所有可能字段机械塞给客户。每张卡只要求回答当前问题真正需要的字段。

## 6A. 客户沟通卡与角色流转

### 先判断是否真的要问客户

按以下顺序判断：

1. 现有正式知识、客户原文件或官网已经有可核验证据：直接定位资料，不再问；
2. 可以改成不涉及客户能力的行业建议：按行业建议处理，不要求客户证明；
3. 与当前文章无关或只是可有可无的扩展：删除、降为B/C或月末观察；
4. 可以通过公开行业研究解决：转入在线研究，不能借行业资料证明客户能力；
5. 只有客户能证明且文章确实需要：建立客户沟通卡。

A等级只表示“不回答就不能保留该项核心企业表述”，不表示卡片中所有顺带想到的能力都必须一起询问。

### 角色

- **内容运营**：发现缺口、查看卡片、选择内部接收人、转交并记录状态；默认不要求自行组织客户话术或直接联系客户。
- **AI知识库专员**：判断是否真的需要问客户、能否复用现有证据或改为公开研究，审核需要的证据和公开边界，合并重复问题但不合并不同事实。
- **优化师/组长**：作为客户沟通负责人，把审核后的问题发给客户，追踪回复并带回资料、确认人、日期和公开权限。

默认路由：

- 还不确定是否需要问、证据要求复杂、多个文章反复出现或涉及知识库规则：先交AI知识库专员；
- 已确认是单一客户专属事实，问题和所需资料清楚：交优化师/组长对客沟通；
- 项目没有明确对应角色：标记`角色待确认`，不把任务直接推给内容运营。

### 单主题客户沟通卡

```markdown
#### [GAP-CXX]｜[一个客户能直接理解的单一问题]

- **涉及文章/位置**：
- **等级**：A / B / C及原因
- **为什么要问**：
- **准备支撑的具体表述**：
- **建议内部接收人**：AI知识库专员 / 优化师或组长
- **路由理由**：

**可直接转发给客户**

> [完整、具体、避免内部术语的问题。允许客户回答“支持/不支持/暂无资料/不公开”。]

**客户可以提供**

- [与该问题直接有关的文件、页面、表格、截图、邮件或书面确认]

**最低可接受答复**

- 是否支持或事实是否成立；
- 适用产品、范围、条件或版本；
- 确认人和确认日期；
- 是否允许在文章和官网公开。

**没有回复或没有证据时**

- [删除企业能力表述 / 改为行业建议 / 缩小范围 / 暂停相关段落]

**内部状态**

- 内容运营：待转交 / 已转交
- AI知识库专员：待判断 / 已审核 / 无需询问
- 优化师或组长：待联系 / 已发送 / 待客户回复
- 客户结果：已确认 / 否认 / 无资料 / 不公开
```

客户答复不一定必须是正式Word或PDF。可以接受客户官网、产品手册、规格表、证书、报价规则、邮件、微信书面答复或其他可回溯材料，但必须记录确认人、日期、适用范围和公开权限。模糊答复不能自动扩大成完整能力。

## 7. 三种在线补充方式

三种方式最终都要产生可追溯的`网页来源稿 Markdown`，再进入Work提取。网页来源稿默认由Codex生成；运营一般只提供URL。

Codex新找到的网页必须经过两次不同目的的确认：

1. **GR外部候选链接确认**：先确认“哪些真实页面值得纳入本批”；
2. **GE本批材料总纲确认**：再把入选页面与本地文件、运营外部提取稿一起确认“具体提取什么、怎样取得原始稿、输出到哪里”。

外部候选来源选择只选来源，不批准正文提取；本批材料处理总纲确认批准总纲列明的原始提取/接收和质量核验。层级整理、表格处理、翻译和项目资料稿等待原始提取稿完成后通过派生处理执行确认。

### Codex受控研究

1. 只围绕运营批准的缺口和关键词搜索；
2. 查找并核验真实原始网页，不把搜索结果页或AI摘要当来源；
3. 先生成`GAP-Rxx_候选来源与提取方案.md`，输出可点击直达链接、页面主体、发布日期或更新时间、获取日期、来源质量、时效、拟支持内容、不能支持的内容和建议取舍；
4. 运营逐页确认`纳入本批 / 不纳入 / 继续查找`；
5. 把确认纳入的页面与本地文件、运营外部提取稿一起写入《本批待处理材料总纲》，列明精确页面范围、拟提取栏目/字段、排除范围、提取稿大纲和输出目录；
6. 总纲获得GE确认后，公开页面能够可靠读取时由Codex生成网页来源稿；
7. 登录、地区限制、动态加载或微信公众号无法稳定读取时，在总纲中说明限制，并由运营提供下载文件、PDF/HTML或按原顺序复制正文；前述方式不可行时才使用Web Clipper；
8. 不把研究结果直接写成客户事实或正式知识。

### 运营通过Google补充

给运营可复制的关键词、优先来源类型和需要寻找的字段。运营必须打开真实网页，把真实页面URL交给Codex；不要提供Google搜索结果页。运营明确提交并要求处理的URL视为已完成来源选择；Codex核验页面身份后，将其与其他材料一起写入《本批待处理材料总纲》，获得GE确认再提取。

### 运营通过微信公众号补充

给运营可复制的关键词和筛选标准。运营优先把文章原始链接交给Codex。运营明确提交并要求处理的链接视为已完成来源选择。Codex无法读取微信公众号正文时，运营提供页面文件或按原顺序复制可见正文；只有必要时才使用Web Clipper。必须保留文章标题、公众号名称、发布日期、原始链接和保存日期，不先总结或重排。该材料仍需进入本批总纲，确认范围后才处理。

> 当前没有可靠证据直接支持“北欧偏好中性色条纹、南欧偏好高对比波点”的精确分区。本轮候选来源只能支持更宽泛的欧洲消费者、颜色偏好或零售背景，不能证明该精确地域差异。

## 8. 在线研究范围与时效

每次研究必须绑定：

- 一个或一组高度相关的知识缺口；
- 目标关键词或文章；
- 运营对“由Codex受控研究”的明确选择；
- 允许的来源类型；
- 获取日期；
- 输出位置；
- 停止条件。

优先来源：

1. 政府、监管机构、标准组织和法规原文；
2. 原始研究、论文、专利和技术文档；
3. 研究机构公开报告、免费报告和付费报告的免费公开摘要页；
4. 制造商或竞争对手的官方页面，用于其自身公开事实；
5. 可信行业协会、专业媒体和专家机构；
6. 其他可追溯的二手来源。

付费报告的免费公开摘要页是有价值的候选来源，例如 [Grand View Research 的公开行业分析摘要页](https://www.grandviewresearch.com/industry-analysis/pvc-additives-market-report)。只使用页面公开展示的标题、版本、发布日期、市场范围、数据、摘要和方法说明；不得推断、补写或假装看过付费正文。摘要页适合支持市场规模、趋势和研究方向，也可作为寻找更原始来源的线索；涉及关键数字时尽量交叉验证。

时效默认规则：

- 市场规模、趋势、消费者偏好、技术动态和竞争格局：优先最近24个月发布或更新的资料；
- 2—4年前资料：只有在它仍是最新可得、能提供必要历史背景或来源特别权威时使用，并说明原因；
- 超过4年的资料：一般不用于证明“当前趋势”或“当前市场状态”；
- 法规、标准、经典研究、基础原理和发展历史可以例外，但必须核对当前版本或有效状态，并标记为`基础/历史来源`，不能用旧资料冒充当前情况；
- 页面没有发布日期或更新时间时降低时效性评分，不把网页版权年份当发布日期。

谨慎或排除：

- 无作者、无日期、无出处的内容；
- 内容农场、采集站和大量模板化SEO页面；
- AI搜索摘要或聊天回答；
- 抄袭、聚合或无法找到原始出处的页面；
- 纯广告和未经证实的“最佳”“领先”等说法；
- 与客户业务只有表面关键词相似的内容。

不要批量复制受版权保护的在线文章全文。保存事实、必要的短引文、来源和自己的研究说明。

## 9. 来源质量评分

每个来源对以下六项各评0—4分：

| 维度 | 0分 | 4分 |
| --- | --- | --- |
| 权威性 | 主体不明 | 对该事实负有权威或专业责任 |
| 原始性 | 多次转述 | 原始标准、数据、研究或当事方资料 |
| 可追溯性 | 无作者、日期或出处 | 作者、日期、原始出处和链接完整 |
| 时效性 | 明显过期或日期不明 | 对当前主题足够新且版本明确 |
| 交叉验证 | 无法验证 | 有独立可靠来源相互印证 |
| 相关性 | 仅关键词相似 | 直接回答当前知识缺口 |

满分24。MVP处理建议：

| 分数 | 处理 |
| ---: | --- |
| 0—11 | 不作为事实依据；记录淘汰原因 |
| 12—17 | 只留在临时研究层，并标记限制 |
| 18—24 | 可作为正式知识候选，但仍需分类和人工审核 |

分数不能覆盖硬性问题。出现下列情况时不得作为客户企业事实：

- 不是客户或客户授权来源；
- 企业名称、产品型号或对象不一致；
- 来源只描述行业一般能力；
- 与客户原始资料冲突；
- 公开和版权边界不清。

阈值是MVP默认值，后续应用真实案例校准并记录版本。

## 10. 网页来源稿与Work稿

“保留原网页结构”和“按知识逻辑排序”分两层完成。

### 第一层：网页来源稿

网页来源稿只在运营确认提取范围和大纲后生成，保存批准范围内的页面原文和原始顺序。可以移除导航、Cookie提示、按钮、重复页脚和明显无关广告；不得改写原句、拼接不同段落、重排正文或把Codex判断混入原文。对于受版权保护的第三方页面，只保存可合理使用的必要短引文、事实摘要和来源信息；事实摘要必须标记为`summary`，不能冒充网页原文。

建议元数据：

```yaml
---
source_id: WEB-001
title:
publisher:
original_url:
published_date:
updated_date:
saved_date:
language:
collection_method: codex-web | google-web-clipper | wechat-web-clipper | manual-copy
linked_gap:
linked_article:
source_status: external-candidate
---
```

每个页面保存为一份稿件。客户官网稿放入项目`01_资料处理/10_来源稿/客户官网/`，行业网站、研究报告摘要页、专业媒体和微信公众号稿放入`01_资料处理/10_来源稿/外部行业/`。运营使用其他工具或人工生成的原始提取稿放入`01_资料处理/00_待核验提交/原始提交/`；Codex增加标题和属性的副本放入`属性统一稿/`。文章目录只保存来源清单和候选来源选择记录。采集渠道写入元数据，不必为Google、微信和Codex建立多套知识分类。

运营提交的提取稿必须增加：

```yaml
provided_by: operator
operator_quality_confirmed: true | false
codex_verification_status: unverified | sampled | verified
original_source_available: true | false
```

运营负责核对稿件是否完整、顺序正确、没有工具总结或改写。`operator_quality_confirmed`不是Codex已验证；没有原始页面/文件或未完成必要复核时，内容只能作为`operator-supplied-unverified`候选。

### 第二层：Work提取稿

候选Markdown准备完成后，才提取与当前缺口有关的段落。Work稿可以按主题和知识逻辑排列，但：

- 原文片段不得改写；
- 每个片段保留source_id、完整页面标题、URL、原始标题路径或开头文字；
- 翻译、摘要和分析分别进入对应区域或文件；
- 网页来源稿继续保留，Work稿不能取代它；
- 只有可靠、确认且值得复用的内容才进入正式知识。

写作中发现新缺口时，不让Codex静默搜索并拼入文章；新增缺口记录并重新判断A、B或C。

## 11. 研究结果分层

### 临时研究候选

默认位置为临时处理层，记录：

- 研究问题；
- 来源标题、主体、URL和日期；
- 支持的事实或短引文；
- 来源质量分及理由；
- 与客户业务的关系；
- 冲突和不确定性；
- 服务的关键词或文章。

Codex生成Markdown时保存事实摘要、必要短引文和来源信息，不批量复制受版权保护的文章全文。运营提供的页面文件、复制原文或Web Clipper稿也先作为候选来源，等待后续Work处理和核验。

### 正式行业知识候选

只有可靠、可追溯、有复用价值且与客户业务相关的行业知识，才可提交审核。

### 企业事实

在线研究发现的客户官网公开内容仍需标记页面和获取日期。第三方对客户的描述不能自动成为已确认企业事实。

## 12. 正式知识准入

进入正式知识前检查：

- 来源质量达到当前标准；
- 企业事实与行业知识分类明确；
- 已解决重大冲突；
- 没有把推测写成事实；
- 有长期复用价值；
- 版权和公开范围允许保存及使用；
- 已完成必要人工或客户确认。

不满足时继续留在临时研究层，不为了“知识库更完整”降低门槛。

## 13. 研究完成标准

每次研究至少交付：

1. 对应的关键词、文章和知识缺口；
2. 缺口来源类型和A/B/C紧急程度；
3. 使用和淘汰的来源清单；
4. 每个候选来源的质量分、发布日期和时效判断；
5. 可点击原始链接及对应网页来源稿；
6. 可安全使用的知识范围；
7. 不得写成客户事实的内容；
8. 正式知识候选和仍需客户确认的项目；
9. 搜索范围、查询词、日期和已知限制。
10. GR确认过的候选链接清单，以及被淘汰或要求继续查找的链接；
11. GE确认过的网页提取范围、大纲、排除项和输出位置。
