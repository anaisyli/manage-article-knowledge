## 1. 使用时机

内容运营已经：

1. 查看资料推荐与知识缺口；
2. 对Codex新找到的外部候选链接完成“外部候选来源选择”；
3. 选定本批准备使用的客户原始资料和网页；
4. 把自己通过其他工具、人工复制或外部平台获得的提取稿一起提交。

此时Codex只登记、扫描和保护材料，不正式提取、整理、翻译或改写。材料收齐后生成唯一的《本批待处理材料总纲》。

资料推荐页或知识库整理计划的确认只决定“选哪些材料”，不等于批准正文提取。

## 2. 固定流程

```text
资料推荐
→ 内容运营选择材料
→ Codex定位外部候选链接并生成GAP-Rxx候选来源与提取方案
→ 内容运营完成外部候选来源选择
→ 内容运营同时提交自己已有的外部提取稿
→ Codex只读扫描并汇总
→ 无法达到提取要求的材料先预警并列出运营需补内容
→ 生成《本批待处理材料总纲》
→ 内容运营完成本批材料处理总纲确认
→ Codex生成/接收原始稿
→ 在副本上统一标题和属性
→ 核验原始稿
→ 根据实际提取稿生成《本批派生处理执行单》
→ 内容运营完成派生处理执行确认
→ 按确认结果分别生成并核验英文翻译稿、表格稿、特殊结构稿及其他获批中间稿
→ 按知识主题生成或更新项目资料稿，分析稿另存
→ 内容运营确认项目资料稿后，建立文章资料选择表
→ 完成文章就绪审核和人工放行后，再自动生成文章写作资料包
```

总纲是处理说明书，不要求把不同来源合并成一个文件。

总纲中所有需要运营确认的材料、页面、大纲项、处理动作和输出文件都必须使用`编号｜人能看懂的标题`。编号只用于稳定检索，不得只写资料ID、稿件ID、GAP-ID或“第X项”让运营回头猜内容。

## 4. 标题与属性统一

属性统一只在原始提交稿的副本上进行。最低字段：

```yaml
source_id:
display_title:
original_title:
original_file_or_url:
source_type:
source_location:
language:
provided_by: codex | operator
extraction_method:
extraction_scope:
saved_date:
linked_articles:
linked_gaps:
operator_quality_confirmed:
codex_verification_status:
codex_access_status: accessible | restricted | unavailable
draft_stage: source-normalized
```

规则：

- `display_title`用于阅读，不能替代或改写`original_title`；
- 原始文件名、URL和路径逐字保留；
- 原始正文放在属性块之后，内容和顺序不变；
- 有原始标题时沿用；没有标题时可按“本批材料处理总纲确认”通过的大纲增加中性导航标题；
- 有层级标题时保留原标题路径、顺序和父子层级；外层容器导致Markdown级别移动时整棵子树等量移动并记录原始级别，不得压平或重挂；
- 中性导航标题只标识来源主题或位置，不替原文下结论；
- 只统一不可见空格、编码或明显的机械格式时记录`mechanical_cleanup`；
- 一旦删除、重排、归类、翻译或中性化表达，必须另存派生稿，`draft_stage`不能继续写`source-normalized`。

## 5. 确认与变更

- 总纲可以一次确认全部，也可以部分确认；未确认材料保持只读状态。
- 同一结构的一批资料可以共用已确认样例，但结构变化时重新确认。
- 新增资料、扩大页码/章节/Sheet/URL范围、改用外部服务、增加翻译、删除或重排内容时，更新总纲并重新确认受影响部分。
- “本批材料处理总纲确认”只批准本批原始提取/接收、来源属性和质量核验，不批准派生处理，也不等于文章写作放行或正式知识入库。
- 原始提取稿完成后，必须读取`article-usable-draft-rules.md`生成《本批派生处理执行单》，完成“派生处理执行确认”后才继续。
