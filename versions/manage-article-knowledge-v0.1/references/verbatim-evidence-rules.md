## 1. 目标与术语

高保真提取的目标是：

> 在不改动客户原始文件的前提下，生成可逐段回到原文件核对的原文证据。

本规则适用于PDF、PPT、Word、Excel、图片、视频、音频、客户官网、行业网页、微信公众号及运营提交的外部提取稿。无论什么材料，提取稿都必须“原文怎么写就怎么提取”，不能在提取过程中总结、润色、改写、补齐或混入Codex判断。

使用以下内容类型：

| 类型 | 含义 | 能否标记为客户原话 |
| --- | --- | --- |
| `verbatim` | 从可靠文本层直接复制，未改写 | 可以 |
| `ocr-verbatim` | 从扫描页或图片OCR得到，尚需考虑识别误差 | 核验后可以 |
| `cleaned-transcript` | 基于运营提供的原始逐句稿或字幕稿生成的清理版 | 不可以 |
| `translation` | 原文的翻译 | 不可以 |
| `summary` | 对原文的摘要或整理 | 不可以 |
| `inference` | 根据资料推导出的解释 | 不可以 |

不得用“忠于原意”“大意如下”等表述把改写结果当作原话。

## 1A. 提取前确认

资料推荐完成后，Codex新找到的外部链接先完成GR来源选择。内容运营再选定本批其余材料，并把自己已经获得的外部提取稿一起提交。Codex原样接收外部稿后，生成一份覆盖本批全部材料的《本批待处理材料总纲》。

生成任何正文提取稿或实质处理外部提交稿前，总纲中必须包含：

- 资料或页面及当前形态；
- 精确范围；
- Codex提取方法，或运营稿的接收、保护和核验方法；
- 拟提取主题、字段和顺序；
- 表格、图表、文字型图片或OCR的处理方式；视频另写运营需要准备逐句稿还是字幕稿；
- 明确排除的范围；
- 原始语言；
- 提取或处理大纲；
- 标题与来源属性统一方式；
- Codex对当前格式和范围的可访问性、预计提取质量、已知限制，以及失败时需要运营补充的材料；
- 后续格式、重排、去重、表格、翻译或审核操作；
- 原始稿、属性统一稿和派生稿的预计文件名与输出目录。

只有内容运营明确确认总纲或其中具体项目后才生成/接收原始提取稿并完成质量核验。确认资料推荐或选材不等于批准提取；批准一份资料也不等于批准同项目的全部资料。层级整理、重排、去重、表格/图表转换、翻译和项目资料稿必须在原始提取稿完成后另行通过派生处理执行确认。

## 2. 原始资料保护

- 把原始文件保存在原始资料层，不原地编辑、另存覆盖或改变格式。
- 在接收时记录资料ID、原始文件名、相对路径、文件大小、修改时间和SHA-256或等效内容指纹。
- 转换稿、OCR稿、Markdown证据稿和翻译稿使用独立路径，并指回原始资料ID。
- 同名不同内容按版本管理，不自行删除旧版。
- 客户提供的文件有密码、损坏、缺页或版本不明时，先登记异常，不声称已经完整提取。

“原始文件已保存”与“原文已可检索引用”是两个状态，必须分别记录。

## 3. 证据单元

按能够独立理解、引用和核对的“最小完整语义块”提取，不按固定字数切断句子、表格行、条件或步骤关系，也不因文章只需要一句话就把来源拆碎。

有明确标题时，默认把所选最小有意义标题及其下属完整内容作为一个“标题子树”：从所选标题开始，到下一个同级或更高层级标题之前结束。保留原标题文字、原顺序和父子层级。例如选择三级标题时，默认同时保留其下四级、五级标题及正文，不分别拆成孤立证据。

技术容器要求增加文件总标题时，可以让整棵标题子树等量移动，但必须记录原始标题路径和原始级别；不得压平、重新挂接或单独提升某个下级标题。确需只取某个下级标题时，必须确认它本身语义完整，并保留完整上级标题路径和必要上下文。

没有明确标题时，至少提取一个完整段落；若同一意思跨越多个连续段落，则共同构成一个证据单元。结构化内容使用以下完整单元：

- 表格：表名/所属标题、完整表头和相关完整行；
- FAQ：问题和完整回答；
- 列表：所属标题、必要引导句和相关完整列表项；
- PPT：幻灯片标题和相关完整内容块；
- 网页字段：页面或产品名称、上级栏目、字段名和字段值；
- 视频/音频：表达完整意思的连续时间段、说话人和时间码。

只有独立定义、独立条款、完整参数、独立列表项、术语字段或客户独立答复等原生原子信息，才允许单句或字段级提取。即使使用例外，也必须保留上级标题、对象、适用条件、完整字段名和精确位置。几个词只能作为名称、型号、术语或字段值登记，不能单独标记为完整原文证据。

每个证据单元至少包含：

```markdown
### EV-0001

- 资料ID：SRC-0001
- 资料显示名称：2026英文公司介绍
- 原始文件：Company Profile 2026.pdf
- 原始资料相对路径：现有知识库/Company Profile 2026.pdf
- 位置：P12—P13
- 原始标题路径：Company Profile → Manufacturing → Production Capacity
- 原始标题级别：三级标题及其下属四级、五级标题
- 提取单元：标题子树
- 范围结束：下一个三级标题“Quality Control”之前
- 内容类型：verbatim
- 提取方式：PDF文本层
- 核验状态：已抽样核验
- 公开状态：待确认

#### Production Capacity

> [保留该标题下的完整原文、下级标题、列表和相关表格。]
```

必要时增加：

- 上下文范围；
- 页内标题、完整上级标题路径和原始标题级别；
- 标题子树的起止标志；
- 单句或字段级例外及其理由；
- 型号、语言和单位；
- OCR置信或人工修订说明；
- 与其他证据的冲突；
- 可服务的关键词或文章。

不要在引用块中修正语法、标点、大小写、单位或营销表达。发现疑似原文错误时，在引用块外说明。

提取稿可以增加用于定位的外层标题、资料ID和来源字段，但新增标题不得总结或替换原材料含义。原材料的标题子树保持原标题、顺序和相对层级；需要修正异常层级或按文章逻辑重排时，另建派生稿或分析稿，原文证据仍保持逐字内容和可回溯位置。

## 4. 不同资料类型的定位

| 资料类型 | 必填定位 |
| --- | --- |
| PDF | 资料ID、资料显示名称、原始文件名、原始相对路径、PDF页码；有印刷页码时可同时记录 |
| PPT | 资料ID、资料显示名称、原始文件名、原始相对路径、幻灯片编号、页面标题 |
| Word | 资料ID、资料显示名称、原始文件名、原始相对路径、可见标题起止范围或开头文字；程序段落号默认不作为主要定位 |
| Excel/CSV | 资料ID、资料显示名称、原始文件名、原始相对路径、Sheet、单元格范围、表头路径 |
| 图片 | 资料ID、资料显示名称、原始文件名、原始相对路径、图片编号或区域说明 |
| 网页 | 页面标题、发布主体、URL、获取日期、页面小节 |
| 视频/音频 | 文件名、资料ID、起止时间；有配套PPT时增加幻灯片；运营提交稿另记提供者、方法和覆盖范围 |
| 微信文章 | 标题、发布主体、URL、发布日期或获取日期、正文小节 |

PDF页码必须说明是PDF文件页码还是印刷页码，避免二者错位。Word只有固定渲染版本后才能使用`渲染页码`，同时记录渲染文件或日期；不得把程序段落序号写成Word页码。程序段落号只在调试或复核需要时作为辅助字段，写明计数工具或方式，并标记`非Word页码，仅供Codex复查`。

## 5. 表格、图表与图片

### 表格

- 保留原始表格文件或页面作为权威证据。
- 简单表格可生成Markdown表格，同时记录来源页码或单元格范围。
- 多层表头、合并单元格、超宽表和参数矩阵不得只转成长段文字。
- 标准化时重复上层表头，使每个值都拥有完整的“对象—字段—数值—单位”路径。
- 生成解释性文字时标记为`summary`，不能代替原表或标记为原话。

### 图表

- 保留图表标题、图例、坐标轴、单位、数据标签及来源位置。
- 无法可靠读取具体数值时，只描述可以视觉确认的关系，并标记待核验。
- 不根据图形走势自行补出精确数值。

### 图片

- 产品、工厂、设备、证书和客户照片只保留在客户原始资料位置及资料索引中，不复制为知识正文。
- OCR只提取图片中实际可见文字。
- 图片含义、人物身份、拍摄地点和公开权限不明时分别标记，不凭画面猜测。

## 6. 提取方式与工具选择

按以下顺序选择：

1. 原文件的可靠文本层或结构化数据；
2. 文件格式专用解析器；
3. 版面解析工具；
4. OCR，或由内容运营按已批准方式完成的语音转写；
5. 视觉核验与人工复核。

可使用当前环境中经过验证的本地工具、开源项目或API，不把单一产品写成永久依赖。选择工具时记录：

- 工具及版本；
- 输入范围；
- 是否上传外部服务；
- 输出格式；
- 已知限制；
- 是否需要人工核验。

涉及客户保密资料时，在上传线上API前确认授权和数据处理边界。没有授权时优先本地处理。

如果结构扫描已经表明无法满足完整性、顺序、层级、表格或逐字要求，在提取正文前向运营发出“需要运营补充可核验原文”提示。说明受影响范围、已尝试方法、差距、可靠部分和需要补充的可搜索文件、清晰页面、网页正文、外部提取稿或逐句稿。执行中才发现问题时立即停止受影响范围，不等到最终交付才说明。

## 7. 质量核验

### 必查项目

- 文件和处理范围正确；
- 普通正文没有被拆成孤立句词；标题子树内容完整，原标题路径、顺序和父子层级可复核；
- 单句或字段级提取确属原生原子信息，并保留对象、条件、上级标题和定位；
- 段落没有漏行、乱序或跨栏串行；
- 数字、型号、单位和小数点一致；
- 表头与数值没有错位；
- OCR没有把相似字符混淆；
- 来源定位可以实际打开并复核；
- 原文、翻译、摘要和推断标签正确。
- 交付状态与真实质量一致；明显残缺、无法复核或与确认要求差距较大的结果没有被标成完成。

### 抽样

- 普通文本至少抽查开头、中部、结尾和所有高风险事实所在位置。
- 含大量参数、型号、表格或OCR页面时，提高抽查比例；关键参数逐项核对。
- 发现系统性错误时停止扩大处理范围，先更换提取方法并重新验证样例。

不要用“看起来通顺”代替与原文件逐字核对。

无法达到要求时，把失败范围标记为`不完整，不作为当前可用原文`并请求运营补充具体材料。可靠范围和失败范围分开记录；可靠的独立部分可以继续，失败部分不得进入项目资料稿、文章写作资料包、正式知识或就绪审核。不得通过补写、摘要、重排或猜测让结果看起来完整。

### 运营提交的外部提取稿

运营应在生成《本批待处理材料总纲》前，把本批已有的Web Clipper、其他提取工具、人工复制或外部平台稿件一起提交。Codex把原始提交稿放入`00_原始提交/`，不得原地编辑。必须记录：

- 原始页面URL或原始文件；
- 提供者；
- 提取工具或方法；
- 运营是否已核对完整性、顺序和原文一致性；
- Codex是否取得原始来源；
- Codex核验状态。

运营负责完成初步质量核对并明确回复是否存在漏段、乱序、乱码、表格错位或工具总结改写。Codex把这类稿件先标记为`operator-supplied-unverified`。只有能够回到原始来源且完成必要核验后，相关片段才可升级为`verbatim`或`ocr-verbatim`。运营确认不能替代Codex核验记录，Codex核验也不免除运营对其外部工具结果的初检责任。

总纲获批后，Codex可以在副本上增加统一标题和来源属性，保存到项目`01_资料处理/00_待核验提交/属性统一稿/`。属性块至少记录资料ID、显示标题、原始标题/文件名、原始URL/路径、语言、提供者、提取方法、范围、日期、关联文章/缺口和核验状态。属性统一稿的正文与原始提交稿保持相同内容和顺序；一旦删除、重排、翻译或改写，必须另存派生稿。

### 运营提交的视频逐句稿或字幕稿

- Codex发现视频后只提供准备说明，不默认替运营生成原始逐句稿或字幕稿；
- 运营负责选择逐句稿或字幕稿、确定范围、使用公司允许的方法提取，并完成初步质量检查；
- 原始提交稿保留句序、字幕行、时间码和不确定标记，不得为了通顺提前总结或改写；
- Codex收到稿件后先按`operator-supplied-unverified`登记，原始稿不可覆盖；
- 删除口头语、合并重复、调整残句、修正识别错误或逻辑整理后的版本必须另存并标记`cleaned-transcript`；
- 重要修订记录原句、修订内容、时间码和依据；无法回听核对时保留待确认；
- `cleaned-transcript`、翻译和摘要都不能标记为客户原话。

## 8. 允许与禁止的转换

允许：

- 为便于查找增加标题、资料ID和来源字段；
- 在原文之外增加摘要、翻译和说明；
- 对复杂表格生成结构化副本，同时保留权威原表；
- 修复OCR结果，但必须记录修订并完成核验。
- 基于运营原始逐句稿或字幕稿建立独立的`cleaned-transcript`，同时保留原始提交稿和重要修订记录。

禁止：

- 在《本批待处理材料总纲》确认前生成正文提取稿或实质处理运营提交稿；
- 把润色稿覆盖到引用块；
- 悄悄补全缺字、单位、参数或句子；
- 把翻译称为客户原话；
- 为降低“AI度”伪造客户表述；
- 只保留AI改写版而删除原始证据；
- 无法核对时声称“逐字准确”。

## 9. 完成标准

高保真提取完成必须同时满足：

1. 原始文件存在且内容指纹已记录；
2. 提取范围明确；
3. 每个证据单元符合最小完整语义块规则，并可定位；
4. 内容类型和提取方式已标记；
5. 关键数字、型号、表格和OCR已核验；
6. 失败、低置信、冲突和未处理范围已列出；
7. 转换稿没有替代原始文件。
8. 已保存内容运营确认过的提取范围和提取稿大纲。
9. 运营提交稿已记录提供者、原始来源、质量责任和核验状态。
10. 视频/音频任务已保留运营提交的原始逐句稿或字幕稿，后续清理版没有覆盖它。
11. 《本批待处理材料总纲》覆盖了本批全部材料，并记录GE确认。
12. 运营原始提交稿、属性统一稿和后续派生稿没有互相覆盖。
13. 如果生成了派生稿，已经保存《本批派生处理执行单》并记录GD确认。
14. 标题子树保留原标题、顺序和父子层级；层级异常或调整已经单独记录。
15. 无法可靠提取的范围已经提前预警，列明差距和运营需补材料，没有把残缺结果标为完成。
