## 1. 目标和边界

本阶段回答：

> 为了准备这篇文章，已有官网和本地资料中哪些部分可能有用，应该怎样取得和处理；没有覆盖的部分应该到哪里补充？

标题、关键词和大纲只用于确定资料需求和查找范围，不在本阶段审核大纲质量、逐条反驳文章主张或判断文章能否写。

本阶段不得输出：

- `可以写`、`有限度可写`或`暂不建议开始`；
- “文章写作放行确认”的人工选择；
- 完整文章事实审核；
- 自动生成文章正文；
- 将候选网页或初步扫描结果直接写入正式知识。

文章就绪审核必须等待运营完成候选资料收集，且必要资料已经处理为Work工作稿后再执行。

## 2. 输入

记录运营实际提供的信息：

- 文章ID；
- 标题、主关键词和相关关键词；
- 大纲或内容要求；
- 目标市场、语言和读者；
- 品牌写法、文章视角、篇幅、FAQ等交付要求；
- 不得编造的字段；
- 客户原始资料路径、Obsidian项目路径和现有资料索引。

这些内容是资料准备约束，不要把它们扩展成大纲质量评价。

外文大纲必须以“外文原文＋中文理解”展示：

- 保留原文措辞、顺序和层级；
- 中文只帮助内容运营理解，不替换外文原大纲；
- 明显因复制丢失换行时，只有层级关系确定才拆分；
- 无法确定的标题粘连、层级或含义必须标记并交运营确认，不能自行重写。

## 3. 定位已有资料

按以下顺序查找：

1. 已确认的正式知识；
2. 当前项目资料稿中已核验的项目资料块；
3. `00_项目管理/资料内容导航.md`中的文件内部页码、章节、语言、主题和型号关键词；
4. 资料索引及尚未建立完整导航的本地文件；
5. 客户官网的公司、产品、服务、案例、FAQ等页面；
6. 已保存的网页Markdown或历史研究资料。

先做结构扫描和相关性定位，不全文处理所有候选文件。

先把文章标题和大纲拆成可查找的资料需求：企业主体、产品系列、型号、参数字段、材质、应用、服务、认证、案例、FAQ、行业主题、目标语言和风险字段。使用项目术语表中的中英文名称、品牌、系列、型号及可靠同义词扩展检索；精确型号、标准号和公司名称优先精确匹配，再按主题和语义查找。

资料匹配必须标明真实状态：

- `现有知识可直接用`：正式知识或已核验项目资料块能够支持；
- `已定位，尚未提取`：内容导航已经找到具体页段，但不能当作已核验证据；
- `相关文件尚未完成内部扫描`：文件已登记但导航范围不足；
- `已扫描相关范围，未找到`：只有相关候选文件完成导航或定向结构扫描后才能使用；
- `需要外部资料或客户补充`：项目内部已完成必要查找仍无可靠来源。

不能仅根据文件名、前几页或轻量扫描结果宣布“项目资料没有”。导航已过期、文件指纹或版本变化时先更新导航。

定位结果必须尽量具体：

- PDF：页码；
- PPT：幻灯片编号；
- Word：默认使用人能看到的标题路径、起始标题、结束标题或开头文字；不要要求运营按程序段落号查找；
- Excel：Sheet和单元格范围；
- 视频：时间段；
- 官网：具体URL或明确页面类型；
- 仍无法定位：写`待结构扫描`，不要虚构页码。

Word自动分页会受页面布局、字体、分页设置和分节符影响。不得把段落编号写成`P43—52`之类的页码。必须使用页码时，先固定并保存渲染版本，再写`渲染页码X—Y`，同时保留渲染版本或日期。

程序段落号是解析工具按DOCX内部段落节点顺序生成的辅助编号。标题、正文和空段落可能被计入，具体取决于工具；文档一编辑，编号就可能变化。它不是Word界面中的可见编号。只有调试、复核提取结果或缺少更好定位时才记录，并单独写成`程序辅助定位：第X—Y个段落节点（非Word页码，仅供Codex复查）`，不能放在主要`内容位置`中。

每条资料必须同时包含：`资料ID｜资料显示名称｜原始文件名｜原始资料相对路径｜人能看懂的内容位置`。资料显示名称可以修复原文件名中明显缺失的括号、重复扩展名或不自然写法，但只用于展示，不自动重命名文件。原始文件名必须逐字保留；存在异常时单独备注。

Word内容位置优先写成：

- `可见标题：“Company Overview”`；
- `从可见标题“Sales Network and Distribution”至下一可见标题“Other services”之前`；
- 没有标题样式时使用`可见小标题＋开头句＋结束标志`。

## 4. 逐来源处理建议

每份候选资料至少判断：

| 字段 | 要求 |
| --- | --- |
| 资料或页面 | 资料ID、资料显示名称、原始文件名和原始资料相对路径；网页写页面名称和URL |
| 相关位置 | PDF页码、PPT幻灯片、DOCX可见标题起止范围/开头文字、Sheet与单元格、时间段或页面 |
| 程序辅助定位 | 默认不展示；需要调试时记录DOCX段落节点范围并注明非Word页码 |
| 格式和语言 | PDF/PPT/Word/Excel/网页/视频及原始语言 |
| 特殊结构 | 表格、扫描页、图表、带文字图片、大量纯图片、动态网页等 |
| 推荐方式 | Codex直接读取、定向提取、视觉核对、MinerU或OCR；视频由运营准备原始逐句稿/字幕稿；网页默认Codex提取，Web Clipper仅作必要备用 |
| 可访问性与限制 | Codex能否取得完整原文、预计是否满足顺序/层级/表格/逐字要求、失败范围和已尝试方法 |
| 运营动作 | 选择是否纳入本批、确认Codex新找到的外部链接、提交自有提取稿；无法达到要求时按具体范围补充原始可编辑文件、可搜索PDF、清晰页面、网页正文或逐句稿/字幕稿；批准外部工具或无需动作 |
| 预计输出 | 原文证据、网页来源稿、表格稿、翻译稿或暂不处理 |

建议必须基于资料格式、语言、提取质量和特殊结构，不只根据文章大纲给抽象建议。

只读扫描已经能够判断Codex无法达到要求时，必须在正文提取前预警；执行中才发现时立即停止受影响范围。说明当前结果与Skill要求的差距、可靠范围和运营需补材料，不得静默改为摘要、改写、猜测或把残缺结果标成完成。

遇到视频时，不由Codex直接判断并生成原始转写。资料卡应写清视频位置、时长、已有字幕/PPT、建议运营准备逐句稿还是字幕稿、需保留的时间码和提交目录。内容运营完成原始稿并初检后，Codex再提出后续处理范围和大纲。

本阶段先输出初步范围和处理建议，让运营选择材料。Codex新找到的外部链接先完成“外部候选来源选择”；运营再把自己已有的外部提取稿一起提交。材料收齐后读取[本批待处理材料总纲](batch-material-processing-outline.md)，生成“本批材料处理总纲确认”文件，至少包含：

- 资料ID、资料显示名称、原始文件名和原始位置；
- PDF页码、PPT幻灯片、DOCX可见标题范围、Sheet与单元格、时间段、URL或页面小节；
- 拟提取的主题、字段和顺序；
- 表格、图表、文字型图片和纯视觉图片的处理方式；
- 明确不处理的范围；
- 原始语言；
- 预计生成的文件名和目录。

内容运营明确确认后才生成提取稿。确认前只允许只读结构扫描、链接查找、提取质量判断和大纲设计，不得提前摘录正文。

资料推荐页的选材确认不等于上述“本批材料处理总纲确认”。没有收齐运营外部提取稿时，不急于为Codex待提取项单独开工；先提示运营把本批已有稿件一起交进来。

## 5. 图片筛选

扫描含大量图片的PDF、PPT、Word或网页时，先说明图片集中的页码、幻灯片、章节或页面区域，再决定是否处理。

按以下规则分类：

| 图片类型 | 默认处理 |
| --- | --- |
| 文字型图片 | 提取并核对文字，如扫描页、证书、标签、截图、图片表格 |
| 图文混合 | 只整理明确文字、标注、图例和数据，保留图片位置 |
| 纯视觉素材 | 不OCR、不生成AI描述、不整理为知识正文；只记录位置并标记`视觉素材，未整理` |

纯视觉素材包括产品展示图、展会图、工厂环境图、客户合影和普通场景图。它们可以留作未来配图，但不属于本轮文字知识整理。

图片很多时默认按连续范围汇总，不逐张描述，除非运营明确要求建立图片素材索引。

## 6. 官网资料获取

当文章要求已经包含客户官网、SPU、产品名称或明确页面类型时，Codex在本轮资料准备中自动查找官方直达链接并扫描可见结构，不等待运营批准开始查找。链接定位和结构扫描是对客户已有公开资料的只读查找，不属于需要审批的外部行业研究；Codex新找到的页面仍要先由运营确认是否纳入本批，随后才与其他材料一起进入总纲。

至少核对官网域名、SPU或产品标题、页面语言/地区版本。按以下结果输出：

- 页面能够核验和读取：直接给可点击链接、页面身份、日期、可支持内容、不能支持内容和建议取舍，状态为`待确认链接是否纳入`；
- 找到候选链接但Codex无法可靠读取正文：仍给链接和限制，状态为`待确认链接是否纳入；若纳入需运营提供页面内容`；
- 已实际尝试官网导航、站内搜索或搜索引擎仍没有可靠候选：记录尝试方式和原因，状态为`等待Codex继续查找`。

不得因为“这是资料准备阶段”就只列SPU而不查链接，也不得用尚未执行的查找动作填充反馈页面。

对每个目标页面按以下顺序选择方式：

### Codex直接提取为Markdown

这是默认方式。适合：

- 页面公开可访问；
- 内容结构清楚；
- 页面数量处于当前文章的批准范围；
- 需要定向取得公司、产品、服务或FAQ信息。

运营先确认页面是否纳入本批；Codex再把入选页面的提取范围、提取稿大纲、排除项和输出位置写入《本批待处理材料总纲》，获得“本批材料处理总纲确认”后才执行。来源稿保留页面标题、URL、获取日期、原始语言和原有内容顺序。动态字段、价格、库存等需标记获取时间。提取稿不得总结、润色、改写或补全；摘要和分析另存。

### 运营提供页面内容

仅在Codex不能可靠读取时使用。优先顺序：

1. 运营提供浏览器实际页面的下载文件、PDF或HTML；
2. 运营按页面原顺序复制可见原文并保留标题和URL；
3. 前两种都不可行时，才使用Obsidian Web Clipper。

运营提交后，把文件或精确路径交给Codex，原样放入项目级`01_资料处理/00_待核验提交/原始提交/`。运营负责初步核对完整性、顺序和是否存在工具改写；Codex记录提供者、提取方式和核验状态。未取得原页面或未完成必要复核前，不标记为逐字原文。标题和属性统一只在副本中进行，副本放入`01_资料处理/00_待核验提交/属性统一稿/`。

官网来源稿仍属于候选资料。不要因为来自客户官网就跳过版本、对象和公开范围核对。

链接选择阶段每个Codex新找到的页面必须给：

| 字段 | 要求 |
| --- | --- |
| 页面/SPU | 人能核对的页面名称、产品名称和编号 |
| 直接链接 | Codex已经打开或核验的目标页面，不给搜索结果页 |
| 页面身份与日期 | 发布主体、页面类型、语言/地区版本、发布/更新日期和获取日期 |
| 能支持 | 对当前文章或缺口能够支持的具体内容 |
| 不能支持 | 页面没有覆盖或不能外推的内容 |
| 建议 | 纳入本批 / 不纳入 / 仅作线索 |
| 运营动作 | 纳入本批 / 不纳入 / 继续查找 |

只有确认纳入后，才在《本批待处理材料总纲》中补齐拟提取内容、排除内容、提取稿大纲、建议文件名和输出目录。

如果Codex实际查找后仍未找到可靠直达链接，不得猜网址，也不得让运营从零搜索。面向运营改用：

- `当前状态：等待Codex继续查找`；
- `运营现在要做：无需操作`；
- `Codex已尝试：官网导航、站内搜索或搜索引擎及结果`；
- `没有确认的原因：页面下架、地区冲突、登录限制或未找到可靠候选`；
- `Codex下一步：说明下一种可行的查找或核验方式`；
- `完成标志：找到候选链接后生成来源选择卡，状态变为“待确认链接是否纳入”或“待确认链接是否纳入；若纳入需运营提供页面内容”`。

不要使用`暂不交运营保存`、`链接无法稳定核验`等需要运营猜测下一步的表达。

只有必须使用Web Clipper时，运营操作才保留五步：

1. 点击Codex给出的直接链接；
2. 核对页面SPU、标题和语言；
3. 点击浏览器中的Obsidian Web Clipper；
4. 把Codex给出的目录复制到Folder，确认Vault；
5. 点击`Add to Obsidian`。

默认不要求运营下载网页图片。Web Clipper只是末位备用；如实际模板配置会下载附件，先提醒运营核对，仍按“纯产品图等视觉素材不整理”的规则处理。

## 7. 缺失资料补充

现有官网和本地资料没有覆盖时，先读取[关键词知识缺口与受控在线研究](keyword-gap-and-research.md)，判断`现有资料待处理 / 客户专属事实 / 公开行业知识`，再标记`A写作前必须补齐 / B质量补充 / C月末观察`。

按缺失主题输出少量可执行建议：

| 字段 | 要求 |
| --- | --- |
| 缺失内容 | 当前需要补充什么，以及为什么需要 |
| 来源与紧急程度 | 三类来源之一和A/B/C等级 |
| 搜索关键词 | 2—5组可直接搜索的中英文关键词 |
| 推荐来源 | 官方机构、标准组织、行业协会、研究机构、专业媒体等 |
| 建议执行人 | 运营手动搜索 / Codex受控研究 / AI知识库专员判断 / 优化师或组长对客沟通 |
| 获取方式 | Codex提取 / 运营提供URL或页面文件 / 必要时Web Clipper / 客户文件或答复 |
| 保存位置 | 项目`01_资料处理/10_来源稿/`或`50_外部研究等待区/`；文章任务只保存链接和选择记录 |

只有运营选择“由Codex受控研究”后，才执行在线候选定位和来源质量审核。Codex先生成`GAP-Rxx_候选来源与提取方案.md`，等待运营确认哪些真实直达链接纳入本批；确认后的链接再与本地资料、运营外部提取稿一起进入《本批待处理材料总纲》。候选链接确认不等于批准正文提取。

客户专属事实不要只写“向客户索取”。先按关键词缺口规则判断是否真的必须询问，再一事一卡生成客户沟通卡。内容运营可以把卡片交AI知识库专员复核，或者把已经明确的问题交优化师/组长负责对客沟通；内容运营不需要自行编写客户话术。

Codex生成的研究Markdown记录研究问题、来源、URL、日期、支持范围、短引文或事实摘要及质量限制；不批量复制受版权保护的文章全文。

## 8. 输出页面结构

读取[文章资料准备反馈页面模板](article-material-output-template.md)并按其输出。该页面负责推荐和收集材料，默认顺序是：

1. 文章资料目标；
2. 外文原大纲与中文理解；
3. 运营现在要做什么；
4. 简短状态概览；
5. 一份一卡的本地资料及提取范围大纲；
6. 已完成自动定位的官网页面及来源选择卡；
7. 按客户沟通卡、公开研究和月末观察分组的知识缺口；
8. 可直接复制的选材和外部提取稿提交回复；
9. 选材完成后Codex将生成《本批待处理材料总纲》，以及本阶段未执行事项。

避免大宽表。表格只用于简短状态概览或字段固定、数量较少的页面比较；本地资料和知识缺口使用分节卡片。

## 9. 等待运营选择

资料推荐完成后，请运营逐项或按批次选择：

- 哪些资料和初步范围纳入本批；
- 哪些Codex新找到的官网和外部页面纳入本批；
- 哪些受限页面由运营提供下载文件、复制原文或必要时使用Web Clipper；
- 同时提交运营自己已经获得的外部提取稿、原始URL/文件、提取方法和初检结果；
- 哪些缺失内容由Codex在线研究；
- 哪些客户沟通卡交AI知识库专员判断，哪些交优化师/组长与客户沟通；
- 哪些资料本周暂不处理。

这些是资料准备和选材，不是“本批材料处理总纲确认”，也不是“文章写作放行确认”。只有涉及路径不明、客户资料外传或付费工具时，才分别进入“项目与路径确认”或“外部工具与数据上传确认”。

官网已有页面的只读查找和结构扫描不在等待范围内；Codex应先完成能够完成的定位。新找到的外部链接先等待“外部候选来源选择”；材料收齐后，把入选页面和其他材料的最终提取内容、大纲、方法和后续处理意向写入《本批待处理材料总纲》。正文提取必须等待“本批材料处理总纲确认”；实质层级整理、表格处理、翻译和项目资料稿还要在提取稿完成后等待“派生处理执行确认”。

## 10. 完成标准

至少交付：

1. 已有资料与文章需求的对应关系；
2. 每份候选资料的精确位置或`待结构扫描`状态；
3. 相关候选文件的内容导航覆盖范围，以及尚未导航的文件或页段；
4. 基于格式、语言、表格和图片情况的处理建议；
5. 已主动定位的官网页面、直达链接、核验状态、能支持和不能支持的内容；
6. 缺失内容的搜索关键词和建议来源；
7. 每个缺口的来源类型、A/B/C等级和首选动作；
8. 说明运营应先选择材料并提交自己已有的外部提取稿；
9. 只有必要时才提供Web Clipper的已核验直达链接、建议文件名、保存位置和五步操作；
10. 等待运营选材和提交材料的清单；
11. 明确声明本阶段尚未执行文章就绪审核。
