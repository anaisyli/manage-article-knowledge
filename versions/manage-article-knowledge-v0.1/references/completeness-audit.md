## 1. 审核目标

完备度审核回答：

> 企业知识库是否拥有足够、可靠、可定位且适合公开使用的资料，支持当前SEO内容运营？

本审核同时保留两个不能混为一谈的结论：

- **知识内容完备度**：公司、产品、案例、认证、行业等资料是否足够，使用本文件第2—8节的C/E/P评分；
- **项目级知识库质量**：知识是否找得到、用得上、信得过、能复用、能增长、能交接，使用本文件第9—11节的六维检查。

内容完备度高不代表项目易查找、易维护或易交接；项目结构清楚也不代表当前文章所需事实已经齐全。两个结论分别输出，不合并为一个总分。

不要把文件数量、字数、Markdown数量或文件夹是否齐全当成完备度。只有能定位到证据的内容才能记为“已有”。

知识库不收录没有文字或数据的照片，纯产品图、工厂图、展会图、团队照和客户合影不作为内容完备度检查项。原始资料中的文字型图片只检查实际提取的文字、标签、图例和数据。

公司正式标准优先于本文件的默认框架。采用公司标准时保留版本号、生效日期、权重和必选项，确保不同人员使用同一口径。

## 2. 默认检查框架

在公司清单尚未定稿时，使用以下MVP基线：

### A. 企业与品牌

- 公司法定名称、常用名称和品牌；
- 成立时间、所在地和发展历程；
- 主营业务、市场定位和目标客户；
- 企业优势及其证据；
- 官网、邮箱、电话、地址和社媒入口。

### B. 产品与服务

- 产品分类和产品关系；
- 产品名称、型号、规格、参数和单位；
- 功能、特点、差异和适用边界；
- 应用场景、选型方式和常见问题；
- 定制能力、交付方式、售后和服务流程；

### C. 解决方案与应用

- 客户或行业面临的问题；
- 推荐产品或方案；
- 方案实施流程和条件；
- 可验证的效果及限制；
- 不适用情况、风险和注意事项。

### D. 客户案例与信任证据

- 客户背景或匿名范围；
- 客户原始问题；
- 使用的产品、型号或方案；
- 实施过程；
- 量化或可验证结果；
- 客户原话、反馈、评价或复购证据；

### E. 生产、质量与资质

- 工厂、产线、设备和产能；
- 研发、检测和质量控制；
- 原材料与工艺；
- 认证、专利、标准和有效期；
- 包装、物流、交付能力；

### F. 行业、市场与竞品

- 行业术语、分类、原理和趋势；
- 目标市场、地区和客户画像；
- 主要竞争对手和替代方案；
- 可核实的竞品差异；
- 行业法规、标准、采购和选型因素。

### G. 内容与公开边界

- 官方术语和多语言名称；
- 可公开与不可公开的信息；
- 客户名称、价格和数据的公开范围；
- 已知冲突、过期项和待确认项；
- 常见销售、技术和售后FAQ。

## 3. 单项评分

每个检查项分别记录三个维度，均为0—4分：

### 覆盖度 C

| 分数 | 标准 |
| ---: | --- |
| 0 | 没有相关信息 |
| 1 | 只有零散线索，无法形成可用结论 |
| 2 | 有基础信息，但缺关键字段或场景 |
| 3 | 足以支持常规内容 |
| 4 | 信息完整，包含细节、边界、数据或多场景 |

### 证据质量 E

| 分数 | 标准 |
| ---: | --- |
| 0 | 没有来源或来源无法定位 |
| 1 | 来源模糊、疑似转述或冲突严重 |
| 2 | 有可定位来源，但版本、准确性或完整性待确认 |
| 3 | 来源可靠、可定位且无重大冲突 |
| 4 | 有客户原话、原始数据、多个相互印证来源或人工确认 |

### 公开可用性 P

| 分数 | 标准 |
| ---: | --- |
| 0 | 明确不能公开或公开会产生重大风险 |
| 1 | 公开权限不明 |
| 2 | 可概括使用，但名称或数字受限 |
| 3 | 可用于常规公开内容 |
| 4 | 已明确公开范围，并有可直接使用的原话、数据或素材 |

单项得分：

```text
C/4 × 40% + E/4 × 40% + P/4 × 20%
```

结果乘以该检查项在分类中的权重。不得让“资料很多但来源差”获得高分。

## 4. 分类权重与总分

默认分类权重：

| 分类 | 权重 |
| --- | ---: |
| 企业与品牌 | 10 |
| 产品与服务 | 25 |
| 解决方案与应用 | 15 |
| 客户案例与信任证据 | 15 |
| 生产、质量与资质 | 10 |
| 行业、市场与竞品 | 10 |
| 内容与公开边界 | 15 |
| 合计 | 100 |

分类内的检查项默认等权；公司标准可设置不同权重。报告必须记录：

- 评分标准版本；
- 权重版本；
- 审核日期；
- 审核范围；
- 未扫描范围；
- 证据链接。

默认解释：

| 总分 | 解释 |
| ---: | --- |
| 85—100 | 基线较完整，仍检查阻断项和具体关键词缺口 |
| 70—84 | 基本可运营，有明确短板需排期补充 |
| 50—69 | 知识不足，多类文章会受限 |
| 0—49 | 基础薄弱，应优先补库而不是扩大写作 |

这些阈值是MVP默认值，不得冒充公司最终绩效标准。

## 5. 阻断项

以下问题不被总分抵消：

- 公司或品牌身份不清；
- 当前目标产品名称、型号、核心参数或适用范围缺失；
- 高风险事实存在未解决冲突；
- 文章需要的客户案例、效果数据或公开授权缺失；
- 客户信息、价格或内部数据的公开范围不明；
- 关键原始资料无法打开或尚未完成可靠提取。

审核报告单独列出阻断项，不只给总分。

## 6. 审核流程

1. 确认项目、审核范围、标准版本和目标市场。
2. 读取知识地图、资料索引、正式知识、风险项和必要原始证据。
3. 为每个检查项定位实际证据；没有证据时不得根据文件名猜测。
4. 分别给出C、E、P分，并写一句评分依据。
5. 计算分类分和总分。
6. 检查阻断项。
7. 将缺口分为“客户资料或确认”“可在线研究”“内部确认”“资料待处理”。
8. 对客户资料或确认先判断是否必须询问，再一事一卡给出优先级、内部接收人、可直接转发的问题和可接受证据。

## 7. 缺口动作

### 需要客户资料或确认

- 企业自身能力、参数、价格、产能和服务承诺；
- 未公开的客户案例和反馈；
- 客户名称和数据的公开范围；
- 冲突版本的最终确认。

不要把上述项目按大类打包给客户。每个独立能力、参数、案例、授权或冲突分别建立客户沟通卡，并先排除已有证据、可改为行业建议、非必要主张和可以公开研究的内容。

内容运营负责转交卡片和记录状态；证据要求不清、涉及多篇文章或需要判断是否值得询问时先交AI知识库专员；问题已经明确且只有客户能证明时交优化师/组长对客沟通。

### 可以在线研究

- 行业原理、分类、标准和法规；
- 公开市场趋势；
- 竞争对手公开页面和公开产品事实；
- 通用选型、应用和问题背景。

在线研究不能替代客户确认企业事实。

## 8. 结果解释

报告必须同时展示：

- 已有且高质量；
- 已有但不完整；
- 有内容但证据差；
- 有内容但不适合公开；
- 完全缺失；
- 无法判断；
- 建议补充方式。

“无法判断”不能自动计为0分后隐藏，也不能自动计为已有；应显示未完成审核的原因和范围。

## 9. 项目级知识库质量

项目级质量回答：

> 该项目能否以合理成本，为当前和后续文章持续提供可靠、可追溯、可复用和可交接的知识？

项目级质量不是文件数量检查，也不要求为了审核全量整理历史资料。只读取项目控制文件、当前知识入口、近期文章任务、风险记录、使用记录和必要证据；没有被本轮检查的范围明确写“未检查”。

文章级知识就绪度仍按单篇文章独立审核。项目可以持续完善，但近期文章必须达到知识已就绪；反之，一篇文章可以写，也不能证明整个项目知识库质量良好。

## 10. 六维检查框架

### 找得到

- 项目ID、客户资料根路径和Obsidian项目路径真实有效；
- 项目说明、资料索引、资料内容导航、知识地图和风险入口能够定位；
- 每个正式知识主题有稳定入口，当前文件与历史版本区分清楚；
- 关键来源链接、相对链接和外部原文件路径可解析；
- 迁移后没有把已失效旧路径当成当前路径。

### 用得上

- 近期文章的项目资料稿、文章资料选择表、就绪结论和文章写作资料包状态清楚；
- 当前文章核心知识已经准备，未覆盖内容和限制可见；
- 已处理知识可以直接进入映射或写作准备，不必重新解析原文件；
- 不用项目资料总量代替文章级就绪判断。

### 信得过

- 企业事实、参数、案例和认证有可定位来源与核验状态；
- 冲突、过期、待确认和客户禁用内容有明确记录；
- 原文、翻译、结构稿、总结和推断类型分开；
- 内容核验状态与Codex技术访问状态分别记录；
- 高风险事实没有因总分较高而被忽略。

### 能复用

- 可复用知识按稳定主题维护，不依赖单篇文章大纲；
- 同一事实尽量只有一个权威维护位置；
- 知识块有稳定ID，文章映射和实际使用能够在有记录时追踪；
- 已审核知识能够被后续文章直接引用或映射；
- 没有为了新文章反复提取同一未变化资料。

### 能增长

- 企业自身新知识、外部行业知识等待项和知识缺口分别处理；
- 新知识优先更新现有主题文件，并同步知识地图和更新日志；
- 重复、过期和被拒绝内容不会持续堆积成多个相似“当前稿”；
- 等待区有明确状态，未来源化的AI内容不进入可用知识；
- 新增文件有独立主题或更新周期，不因模板要求机械扩张结构。

### 能交接

- 项目负责人、内容运营、知识库专员和客户沟通负责人状态清楚；
- 新负责人能够从项目说明和控制文件确认资料位置、当前任务、风险、待确认项和最近变更；
- 当前入口唯一，历史文件有后继关系；
- 同步、共享快照、最近审核和未解决冲突按项目实际能力记录；
- 交接不依赖原负责人记忆才能继续近期文章工作。

### 合理成本检查

合理成本不是第七个质量分，而是六维审核的约束。至少检查：

- 是否重复解析已有可靠知识；
- 是否存在多个相似当前文件、重复正文或重复计数；
- 是否为形式完整创建大量空目录、空文件或碎片化知识；
- 是否为了月度审核扩大到全部历史资料；
- 是否存在长期无人处理的等待区、冲突或无效临时稿；
- 本轮建议动作的收益、文章影响、复用价值和获取成本是否匹配。

## 11. 项目质量结论与月度使用

每个维度使用以下状态，不强制换算为数字：

- **通过**：当前证据表明该维度能够稳定支持工作；
- **关注**：存在问题，但未阻断近期文章或项目接管；
- **阻断**：近期文章、事实可靠性或项目交接会受到实质影响；
- **未检查**：本轮没有足够范围或访问条件判断。

项目质量报告必须给出六维状态、证据位置、影响和处理建议，并单列合理成本风险、阻断项和未检查范围。不得用内容完备度总分替代六维结论，也不得把一次本地扫描称为公司全量质量结论。

六维项目质量不是月度维护简报的固定栏目。路径迁移、项目交接、核心资料更新、重大冲突、当前入口混乱或其他月度异常触发专项审核时，只重新检查受影响维度并另存项目质量报告；没有触发依据时不为月报完整而重做六维检查。

## 12. 月度知识引用率KPI

月度维护简报单列知识引用率KPI。内容运营为当月全部正式完成文章逐篇输入引用率，Codex按文章等权计算算术平均值；`≥15%`为达标，`<15%`为未达标，指标方向为越高越好。任何纳入文章缺少引用率、文章ID或最终版本时，KPI状态为`数据不完整，暂不判定`；不得只统计已录入的高值文章。

引用率KPI、六维项目质量和知识内容完备度是三个独立结论。高引用率不能把`关注`或`阻断`自动改为`通过`，也不能覆盖事实可靠性、来源冲突、公开权限和文章级就绪问题。详细字段、计算和异常处理读取[知识库治理与文章引用指标边界](governance-and-citation-metrics.md)。
