## 1. 只记住这一句话

不知道该从哪一步开始时，直接说：

```text
使用企业知识库Skill处理【项目、文章或材料】。
请按默认流程推进，只在必须由我决定时，用简单选项一次问我。
```

项目已经在当前对话中明确时，也可以只说：

```text
请继续处理这个项目，只在需要我确认时告诉我现在要选什么。
```

不需要说步骤编号，不需要使用`G6`、`G7`等内部代码，也不需要判断应该退回哪一步。

## 2. 需要提供什么

不同任务只提供最少信息：

| 任务 | 最少需要 |
| --- | --- |
| 新建项目 | 客户名称、客户资料路径、Obsidian目标路径 |
| 登记新材料 | 企业项目、新材料完整路径 |
| 准备文章 | 企业项目、文章标题/关键词/大纲 |
| 审核文章 | 企业项目、文章ID或文章路径 |
| 沉淀知识 | 企业项目、本批项目资料稿或处理范围 |
| 审核知识库 | 企业项目名称或路径 |

其他信息知道就说，不知道可以写“不确定”。Codex负责扫描后说明，不把判断工作推回运营。

## 3. 最常用的操作口令

以下文字可以直接复制，不必逐字一致。

### 新建企业知识库项目

```text
请使用企业知识库Skill初始化【客户名称】项目。
客户资料在【完整路径】，Obsidian项目放在【完整路径】。
请先确认路径，再按默认结构建立项目。
```

Codex会检查路径、建立最小目录和控制文件，并生成唯一的`资料索引.md`与`资料内容导航.md`。前者说明有哪些文件，后者说明公司信息、产品、型号等内容在文件的哪些页段。运营只确认项目与写入位置。

Obsidian项目根目录只保留五层：`00_项目管理`、`01_资料处理`、`02_正式知识`、`03_文章任务`、`04_归档`。文章目录只保留四层：`00_任务与确认`、`10_文章资料`、`20_审核与问题`、`30_写作后记录`。原文证据、翻译和项目资料稿都放项目级`01_资料处理`，不在每篇文章里重复一套。

### 登记客户新材料

```text
客户给【项目名称】补充了新材料，文件在【完整路径】。
请先登记、判断是否重复或属于新版本，不要覆盖旧资料，再告诉我需要确认什么。
```

不知道材料是否替代旧版、影响哪篇文章时不用判断。Codex负责更新资料索引和文件内部内容导航、说明影响和返回步骤；如果PDF、图片或其他文件无法可靠扫描，会提前告诉运营需要补什么，不会默默当作“没有相关内容”。

### 为一篇或多篇文章准备资料

```text
请为【项目名称】准备这批文章的知识资料：
【粘贴文章标题、关键词或大纲】。
请先检查现有正式知识、项目资料和官网，再告诉我哪些资料可以直接用、哪些需要处理、哪些还缺。
风险内容请保留并标记，不要因为公开待确认、来源冲突、信息动态或适用范围有限而自动排除；只说明使用前需要核对什么。
```

一次可以提交多篇文章。共用资料只处理一次，文章之间分别记录使用范围。

### 审核文章是否可以开始写

```text
请审核【文章ID或文章路径】的文章知识就绪度。
知识库没有覆盖的内容不等于不能写，请区分现有知识可用、文章专用资料可用、作者可以正常分析、必须补证据和不能写的内容。
```

Codex会给出`可以写 / 有限度可写 / 暂不建议开始`，并用自然语言说明原因。运营只决定是否按限制开始、补资料、改大纲或暂停。

### 提交正式文章终稿

```text
这是【项目名称】的正式文章终稿：
【文章完整路径】。
请按写作后流程处理。
```

Codex默认在文章的`30_写作后记录/[文章ID]_文章引用清单.md`生成或更新单篇引用明细，并把有可靠证据的知识块累计指标同步到项目`00_项目管理/知识地图.md`，不需要运营另行提出。确实无法对应来源的具体内容标记“未追踪”，不会省略整份清单或猜测来源。

### 处理测试文章并真正沉淀知识

```text
这篇是测试稿，不做阻断式发布审查。
引用和未追踪内容只做轻量登记；请把主要工作转为项目级知识回收。
以项目资料稿和原文证据为准，列出本批应沉淀内容；我确认后实际更新正式知识、知识地图和更新日志，并填写沉淀回执。
除客户明确禁止、无法取得可靠正文、摘要、推断和无来源AI说法外，经过核验的内容尽量沉淀；公开待确认、冲突、动态信息和外部研究用风险标签保留。
```

文章里的新说法不能反向成为知识来源。企业自身信息不以文章是否使用为入库条件。

### 直接整理本批正式知识

```text
请对【项目名称】进行本批正式知识沉淀。
以当前项目资料稿为主要入口，回到原文证据核对，按主题去重生成沉淀清单。
请把可以批量批准的低风险内容放在一起，高风险内容单列；我确认“批准并写入”后继续完成实际写入和回执。
```

只生成候选清单不算沉淀完成。

### 审核整个项目知识库

```text
请审核【项目名称或路径】的项目知识库。
分别检查内容完备度和六维项目质量，列出阻断项、关注项、未审核范围和建议处理顺序。先不要修改文件。
```

普通“审核”默认只读，不自动修改或删除。

### 检查刚完成的知识沉淀

```text
请检查这个项目刚完成的知识沉淀是否真的完成。
只检查本次新增和修改范围，包括正式知识文件、来源关系、知识地图、更新日志和沉淀回执。
```

### 做月度维护

内容运营只需逐篇录入或提供整月表格；Codex会同步对应文章引用清单，并把当月数据汇出为项目`04_归档/月度维护/YYYY-MM/YYYY-MM_引用率原始输入.csv`，再在同目录生成`YYYY-MM_企业知识库月度维护简报.md`，不要求人工重复录入。

```text
请对【项目名称】做【月份】企业知识库月度维护简报。
固定检查运行与规范、七个标准模块的源文件覆盖、本月提取与知识沉淀、月度引用率、问题闭环；不要默认重做全面评分。发现几项问题和下月行动就记录几项。
```

### 按审核报告处理问题

```text
请按刚才的审核报告处理已经明确的低风险问题。
涉及正式知识修改、冲突采用哪个版本、删除内容或公开范围时，再用简单选项让我确认。
```

## 4. Codex什么时候会问你

通常只有以下事情必须由人决定：

1. 项目和长期资料路径是否正确；
2. 本批处理哪些文件、页面或章节；
3. 提取后怎样翻译、整理表格和汇入项目资料稿；
4. 文章是否按当前范围和限制开始写；
5. 哪些候选正式写入知识库；
6. 冲突采用哪个版本、敏感内容能否公开、是否删除或归档。

Codex提问时必须说明“现在要选什么、各选项有什么影响”。运营不需要理解内部闸门代码。

希望一次看完所有问题时可以说：

```text
请把当前必须由我确认的事情合并列出，每项给出推荐选项和影响，不要讲内部步骤。
```

## 5. 四种审核不要混

| 你怎么说 | Codex做什么 |
| --- | --- |
| 审核这篇文章 | 判断文章能否写，以及写作范围和风险 |
| 审核这个项目知识库 | 检查内容完备度和项目整体质量 |
| 检查刚才的沉淀 | 验收本次正式知识是否真的写完 |
| 做本月维护 | 重点检查异常项目和少量正常抽查 |

需要重新核对全部原始资料时，明确说：

```text
请做完整知识库审核，并重新核对原始资料和原文证据。
```

这比普通项目审核耗时更多。

## 6. 什么才算完成

| 任务 | 完成标志 |
| --- | --- |
| 资料登记 | 长期资料位置已确认，资料索引已更新 |
| 项目资料处理 | 原文已核验，批准的派生处理已完成，项目资料稿已更新 |
| 文章准备 | 资料范围已确认，文章就绪审核和人工放行已完成 |
| 正式知识沉淀 | 正式知识文件、知识地图、更新日志和沉淀回执均已更新 |
| 项目审核 | 报告写清审核范围、问题、证据、影响和未审核范围 |

看到`候选`、`待确认`、`已批准待写入`或`部分完成`时，都不等于正式知识已经沉淀完成。

## 7. 遇到不会处理的文件

Codex无法可靠读取PDF、网页或任何文件，或者结果明显达不到Skill要求时，必须提前说明：

- 哪个文件或范围处理不了；
- 已经尝试了什么；
- 当前结果与要求差在哪里；
- 运营需要提供下载文件、复制原文、页面文件、人工核验或其他什么材料；
- 哪些不受影响的工作仍可继续。

运营可以直接说：

```text
如果有任何文件无法可靠提取，请立即告诉我具体文件、失败范围和我需要提供什么，不要用不完整结果继续假装完成。
```

## 8. 运营不需要做什么

运营不需要：

- 手工建立资料ID或知识块ID；
- 手工修改资料索引、知识地图和更新日志；
- 判断新材料应该返回哪个内部步骤；
- 为了去重阅读全文；
- 把客户纠正直接覆盖旧证据；
- 从文章正文反向整理企业事实；
- 记住完整流程或内部确认编号。

只需要提供任务对象、必要路径和业务决定，其余流程由Codex执行并留痕。
