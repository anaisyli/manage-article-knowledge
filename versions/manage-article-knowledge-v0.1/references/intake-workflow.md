## 1. 目标与边界

v0.1中的“入库”是：

> 确认客户文件的长期原始位置，保持原文件不变，在Obsidian中完成去重、版本判断、轻量扫描和索引。

它不等于：

- 全文提取；
- OCR全部页面；
- 整理成正式知识；
- 翻译；
- 自动写入正式知识层。

原始资料入库完成后，文件可以处于“已登记、未深度处理”状态。原始文件默认不复制进Obsidian；客户资料路径和Obsidian项目路径是两个不同位置。

本 Skill 在内容运营明确发起“扫描待登记”或“登记这个路径”的任务时运行，不默认后台持续监控文件夹。需要定时自动扫描时应另行配置自动化，并保留相同的安全和去重规则。

## 2. 两种接收入口

### 稳定资料位置中的待登记文件夹

内容运营把文件放入：

```text
project_id_客户名称_原始资料/00_待登记/
```

登记成功后：

- 默认原位登记，不自动移动；
- 只有用户明确授权整理稳定资料目录时，才移动到等效的`10_客户原始资料/`；
- 无法打开、归属不明或需要人工判断的文件先留在原位并记录；
- 不为了整理制造重复副本。

项目已有其他目录规范时使用等效目录，不强制改名。

### 用户提供任意外部路径

用户可以提供一个文件、多个文件或一个精确文件夹路径。

- 只扫描用户明确提供的范围。
- 路径已经是客户长期资料位置时，默认原位登记，不移动、不删除、不修改。
- 路径位于下载、桌面或临时目录时，只读扫描并触发人工确认长期资料位置。
- 未确认长期位置时标记`待确认存储`，不能标记`已登记`。
- 用户明确要求复制到公司公共资料位置时，显示来源和目标并确认后复制；仍不删除来源。
- 无法确认是否属于该客户时，不登记为已登记；记录为待确认。
- 访问外部路径需要权限时，只请求该路径所需权限，不扩大范围。

不要默认扫描整个“下载”“桌面”、磁盘根目录或来源文件夹的父目录。

## 3. 安全检查

执行文件操作前：

1. 解析并显示客户资料绝对路径；
2. 解析并显示目标Obsidian库及企业项目绝对路径；
3. 确认两者属于同一客户项目；
4. 判断客户资料路径是长期位置还是临时位置；
5. 确认不会移动、删除或覆盖已有文件；
6. 只处理普通文件，不跟随指向范围外的快捷方式、符号链接或重解析点；
7. 保留外部来源原文件。

跳过并记录尚未下载完成或明显属于临时文件的内容，例如：

- `.crdownload`；
- `.part`；
- `.tmp`；
- Office锁定文件 `~$...`；
- 0字节且无法确认用途的文件。

压缩包默认作为原始文件登记，不自动解压。只有用户要求检查压缩包内容时才在独立临时位置解压，并防止路径越界。

## 4. 去重与版本判断

优先使用本地文件信息缩小比较范围：

1. 文件大小；
2. 文件名；
3. 修改时间；
4. SHA-256或等效内容指纹。

文件指纹通过本地命令计算，不让模型阅读全文判断重复。

按以下规则处理：

| 情况 | 动作 |
| --- | --- |
| 内容指纹相同 | 视为完全重复，不再复制；记录已存在文件路径 |
| 文件名相同、内容指纹不同 | 视为疑似新版本；保留两个文件，不覆盖 |
| 文件名不同、内容指纹相同 | 视为重复副本；保留项目内已有权威副本 |
| 大小和名称相近但无法计算指纹 | 标记待确认，不擅自覆盖 |

同名不同内容必须安全改名时：

- 尽量保留原文件名主体和扩展名；
- 添加登记日期或明确版本后缀；
- 在资料索引中保留原始文件名；
- 不自行判断哪个版本作废。

示例：

```text
产品手册_20260725_待确认版本.pdf
```

## 5. 轻量扫描

轻量扫描用于判断“这是什么、是否能读、后续是否值得处理”，不追求理解全部正文。

按资料类型获取：

| 类型 | 轻量扫描内容 |
| --- | --- |
| 通用 | 文件名、扩展名、大小、修改时间、内容指纹 |
| PDF | 页数、是否有文本层、是否像扫描件、标题或前几页结构 |
| PPT | 幻灯片数量、主要章节标题、是否含大量图表 |
| Word | 标题或大纲、文档长度、是否含表格和图片 |
| Excel | Sheet名称、使用区域大小、表头概况、是否有多层表头 |
| 图片 | 数量、尺寸、格式、是否可能需要OCR |
| 视频/音频 | 时长、格式、是否已有字幕或逐字稿 |
| 压缩包 | 文件名、大小和类型；默认不展开内容 |

不为了轻量扫描：

- 全文OCR；
- 读取所有页；
- 要求运营转写完整视频；
- 翻译；
- 生成完整Markdown副本；
- 总结全部内容。

如果连轻量扫描也会明显增加成本，例如大量扫描PDF或长视频，只登记文件信息并标记“待按需扫描”。

## 5A. 文档内容导航扫描

轻量扫描只回答“这是什么文件、能不能读”；内容导航扫描回答“文件内部哪里有什么”。首次登记完成后，对未来可能支持公司、产品、服务、认证、案例、FAQ或文章写作的可读文件建立页段/章节级导航，不只读取标题和前几页。

导航扫描属于只读结构定位，不生成正文提取稿、不翻译、不总结成企业事实，也不表示内容已核验。能够通过本地文本层或格式解析低成本完成时，默认在登记后分批执行；需要全文OCR、外部API、付费工具、大量逐页视觉判断或运营补充材料时，先说明文件、范围、成本或限制并请求确认。

按格式建立导航：

- PDF：扫描全部可读页，记录连续页码范围、标题、语言、公司/产品/服务/认证/案例/FAQ等主题、产品系列或型号关键词、表格和图片集中范围；扫描件记录需OCR页码；
- PPT：扫描全部幻灯片标题和可读文字，按连续幻灯片范围归类；
- Word：扫描全部可见标题和章节；无标题时使用开头文字与结束标志建立范围，不把程序段落号当页码；
- Excel：扫描全部Sheet名称、表头、使用区域和主要对象/型号，不为了导航读取或复制全部单元格正文；
- 图片型目录：先记录图片范围和可见标签；型号或参数只能通过OCR/视觉核对取得时标记限制；
- 视频和音频：只有现成字幕、逐句稿或清晰章节信息时建立时间段导航，否则标记需要运营材料。

项目级当前文件固定为`00_项目管理/资料内容导航.md`。默认一份主表；项目过大时主表链接到`00_项目管理/资料内容导航/[资料ID]_内容导航.md`，同一页段明细只维护一处。

每份资料至少记录：

| 字段 | 内容 |
| --- | --- |
| 资料ID与文件 | 显示名称、原始文件名和权威路径 |
| 文件与资料类型 | PDF/PPT/Word等；公司画册/产品目录/证书等 |
| 语言 | 主要语言及混合语言范围 |
| 导航范围 | 已扫描页码、章节、Sheet、幻灯片或时间段 |
| 内容位置 | 连续范围及其公司、产品、服务、认证、案例、FAQ等主题 |
| 关键对象 | 品牌、产品系列、型号、标准号或其他可检索词 |
| 特殊结构 | 表格、图表、文字型图片、扫描页或纯图片 |
| 导航状态 | 未建立导航 / 部分导航 / 已建立导航 / 需OCR或人工材料 / 已深度处理 |
| 未扫描与限制 | 明确范围、原因和需要的材料 |
| 更新时间 | 本次扫描日期 |

完成导航后同步`00_项目管理/资料索引.md`中的主要语言、资料类型、扫描/处理状态、导航链接和已扫描范围。文件已经登记但内部导航未覆盖相关范围时，不得据此判断“项目资料没有该内容”。

## 6. 登记原始资料并写入Obsidian索引

- 二进制原始文件保留在已确认的客户资料位置，不放入正式知识目录。
- Obsidian只使用`00_项目管理/资料索引.md`作为当前文件级索引，并用`00_项目管理/资料内容导航.md`定位文件内部内容；不再建立`资料地图.md`或并行的`01_原始资料索引/`。
- 单次登记报告按日期保存到`04_归档/资料登记记录/`，不与当前资料索引并行维护。
- 保持文件内容和原目录不变。
- 记录绝对原始路径；已有公司共享路径或稳定URL时同时记录，后续同步方案确定后再统一。
- 需要在Work中生成原文证据、OCR、翻译或整理稿时，写入临时处理层或文章任务目录。
- 只有可靠、已确认且具有长期价值的内容才进入正式知识。

文件量较大时分批登记。每批完成索引后再处理下一批，避免索引显示全部完成但实际只处理一部分。

## 7. 更新资料索引

每个成功接收或被判定为重复的文件至少记录：

| 字段 | 内容 |
| --- | --- |
| 资料ID | 项目内稳定编号 |
| 资料显示名称 | 供运营阅读的自然名称；不自动改名 |
| 当前路径 | 权威原始绝对路径 |
| 共享路径或URL | 如已有公司公共位置则记录 |
| 原始文件名 | 接收前名称 |
| 外部来源路径 | 如适合保留；涉及隐私时只记录来源说明 |
| 文件类型 | PDF、PPT、Word、Excel、图片、视频等 |
| 主要语言 | 文件主要语言；混合语言范围写入内容导航 |
| 资料类型 | 公司画册、产品目录、说明书、证书、案例、FAQ、行业资料或其他 |
| 文件大小 | 原始大小 |
| 内容指纹 | SHA-256或等效指纹 |
| 登记日期 | 写入索引的日期 |
| 修改日期 | 原文件修改时间 |
| 登记状态 | 待确认存储、已登记、完全重复、疑似新版本、异常待确认 |
| 扫描状态 | 未扫描、轻量扫描、部分导航、已建立导航、部分处理、已深度处理、需OCR或人工材料 |
| 内容导航 | `00_项目管理/资料内容导航.md`中的位置或详细导航文件 |
| 已扫描范围 | 页码、章节、Sheet、幻灯片或时间段 |
| 内容概况 | 轻量扫描能够可靠确认的简短信息 |
| 关联版本 | 已知旧版或新版资料ID |
| 备注 | 权限、损坏、敏感或其他问题 |

登记状态和内容处理状态必须分开。“已登记”不等于“已整理”或“已进入正式知识”。

原始文件名存在括号缺失、重复扩展名或其他明显异常时，资料显示名称可以整理为自然写法，同时在备注中说明异常；原始文件名和路径仍逐字保留，不自动重命名。

## 8. 中途收到客户新材料

客户在项目处理中途补充文件、纠正表达或提交新版资料时，继续使用原企业项目，不新建第二个项目，也不要求内容运营手工修改资料索引、项目资料稿或文章资料选择表。

### 内容运营需要提供什么

必填信息只有：

- 企业项目；
- 新材料的文件或文件夹完整路径。

知道时再补充：

- 普通补充、纠正旧说法或替代旧版本；
- 可能影响的文章或章节；
- 客户已经说明的公开限制。

内容运营不确定新旧关系或影响范围时可以不判断，由Codex扫描后说明。材料在下载、桌面或其他临时位置时，先确认长期保存位置。

可以直接发送：

```text
客户刚补充了一批资料，属于【项目名称】，文件在【完整路径】。
这是【普通补充 / 纠正旧资料 / 替代旧版本 / 不确定】，可能影响【文章或章节 / 不确定】。
客户说明的公开限制是【具体限制 / 暂未说明】。
请先登记并判断与旧资料的关系和影响范围，不要覆盖旧资料，再告诉我需要确认什么。
```

### Codex怎样接入

1. 按本文件完成路径确认、去重、版本判断、轻量扫描、必要的内容导航和资料索引更新；
2. 把客户纠正或新版本作为新证据登记，不覆盖旧证据，不自行宣布旧版本作废；
3. 说明新材料与已有文件、项目资料稿、正式知识和当前文章的关系；
4. 列出本次需要处理的精确范围，以及内容运营当前需要确认的事项；
5. 只返回受影响步骤，不要求整条流程从头重做。

### 不同进度怎样返回

| 收到材料时的进度 | 处理方式 | 内容运营需要确认 |
| --- | --- | --- |
| 尚未开始正文提取 | 把新材料加入当前《本批待处理材料总纲》 | 只确认新增或受影响的处理范围 |
| 已有项目资料稿，尚未进行文章就绪审核 | 登记、提取、核验和派生处理后更新受影响资料块；涉及当前文章时更新资料选择表 | 新材料处理范围、派生处理方式，以及更新后的文章资料选择 |
| 已完成文章就绪审核或已经生成资料包 | 旧结论标记`needs-rereview`，旧资料包转历史，放行状态恢复`pending`；处理新材料后重新审核 | 更新后的资料选择和新的文章放行结果 |
| 新材料与当前文章无关 | 更新项目资料稿和正式知识候选，不退回当前文章 | 需要时确认派生处理和正式知识沉淀 |
| 新材料纠正或替代旧资料 | 保留新旧证据和版本关系，先判断影响、冲突与公开范围 | 确认采用版本；影响文章时重新审核 |
| 文章已经完成或发布 | 不自动改写文章；先记录影响并更新知识处理结果 | 是否另开文章修订任务 |

只影响单个资料块或章节时，重新审核受影响范围及其直接相关的冲突和风险；改变公司关键事实、产品参数、公开范围、中心主张或多个章节时，重新运行整篇文章就绪审核。

内容运营可能依次收到的确认只有：

1. 临时路径转为长期路径的确认（适用时）；
2. 本批新增材料处理范围确认；
3. 原文提取后的派生处理确认；
4. 更新后的项目资料稿和文章资料选择确认（影响文章时）；
5. 重新审核后的文章写作放行确认（文章已经审核或放行时）。

完全重复、无法读取或确认与当前文章无关时，不制造不必要的后续确认。

## 9. 完成状态

资料登记结束时输出：

- 成功登记文件；
- 完全重复、未复制文件；
- 疑似新版本；
- 异常待确认；
- 跳过的临时或未下载完成文件；
- 客户资料路径和Obsidian索引路径；
- 是否读取正文；
- 建议优先处理的文件；
- 本次未执行的深度处理。

只有文件位于已确认的长期资料路径且资料索引已更新后，才能标记“已登记”。

## 10. Token 控制

按三阶段控制：

### 阶段A：本地登记

列目录、复制、计算文件指纹、记录大小和日期。尽量不把正文送入模型上下文，Token消耗最低。

### 阶段B：轻量扫描

只读取结构、标题、Sheet名、页数或少量代表页面。根据文件数量和复杂度决定是否分批。

### 阶段B2：内容导航

扫描全部可读结构单元，但只保存页段、章节、语言、主题、型号关键词和限制，不保存全文。可搜索文件默认分批建立导航；全文OCR、大量逐页视觉判断或外部工具另行确认。

### 阶段C：深度处理

全文提取、OCR、整理和翻译，以及运营提交视频逐句稿/字幕稿后的处理。只有文章任务或明确知识缺口需要时才触发；原始视频转写由内容运营按视频资料规则负责。

资料登记默认执行阶段A、必要的阶段B，并为未来可能支持企业知识或文章的可读文件分批执行阶段B2。无法完成阶段B2时明确标记未导航范围，不能把它误写成“资料中没有”。

## 11. 异常处理

以下情况不自动标记“已登记”：

- 文件无法读取；
- 文件仍在下载；
- 客户归属不明确；
- 与已有资料同名但版本关系无法判断；
- 来源路径超出授权范围；
- 文件包含疑似敏感信息且公开范围不清；
- 压缩包内容需要密码；
- 复制或索引只完成了一部分。

把异常文件放入项目异常目录或保留在外部原位，并记录：

1. 文件名称；
2. 来源路径；
3. 问题；
4. 已完成动作；
5. 是否已经复制；
6. 需要人工决定什么。

不要因为单个异常文件阻止其他独立文件完成接收。
