## 1. 使用原则

- 优先使用原文件的文本层和格式专用读取能力，不为统一工具重复转换。
- 客户保密资料优先本地处理；使用线上API前确认上传授权、数据保留、训练使用、地区和访问控制。
- 工具输出是派生结果，不是独立事实来源。
- 任何工具都不能免除来源定位、内容指纹、样例验证和人工抽查。
- 不把一个工具写成所有文件的唯一方法。根据文件类型、版面复杂度、保密要求、硬件和准确率选择。
- 不在未评估许可证和公司合规要求前进行公司级部署。

## 2. 文档与Office资料

### 格式原生读取

适合：

- DOCX标题、段落和表格；
- PPTX幻灯片、文本框和备注；
- XLSX Sheet、单元格、公式和表头；
- 带可靠文本层的PDF。

优点是少一次转换，便于保留结构和精确位置。复杂版面、扫描页、图表和嵌入图片仍需视觉或OCR核验。

### MarkItDown

官方项目：[microsoft/markitdown](https://github.com/microsoft/markitdown)

候选用途：

- 对PDF、Word、PowerPoint、Excel、HTML和多种文本格式做轻量Markdown转换；
- 资料结构扫描或低复杂度文件的初步提取。

官方说明强调其输出面向文本分析，不是面向人工交付的高保真格式转换。因此：

- 不把其Markdown外观当成原文件完全还原；
- 参数表、复杂页、扫描页和客户原话仍需回原文件核验；
- 只授予处理任务需要的最小文件访问范围。

### MinerU

官方项目：[opendatalab/MinerU](https://github.com/opendatalab/MinerU)

候选用途：

- 复杂PDF、图片及Office资料转Markdown或JSON；
- 多栏阅读顺序、公式、表格、扫描PDF和OCR；
- 需要本地CLI、API、WebUI或结构化中间结果的批量任务。

使用前：

- 用客户常见文件做代表性试验；
- 核对其许可证与公司使用方式；
- 对页码、表格、跨页内容和OCR结果做抽样；
- 记录后端、版本和参数，避免同一文件重复处理结果不一致。

### Docling

官方项目：[docling-project/docling](https://github.com/docling-project/docling)

候选用途：

- PDF版面、阅读顺序、表格、公式和图片结构；
- PDF、DOCX、PPTX、XLSX、HTML、图片、音频等多格式解析；
- 需要Markdown、HTML或结构化JSON；
- 保密资料的本地或隔离环境处理；
- 后续通过CLI、MCP或自建API服务接入。

“lossless JSON”表示其文档结构表达能力，不等于任何输入都能逐字无误。仍按原文证据规则核验。

## 3. OCR与扫描资料

### PaddleOCR

官方项目：[PaddlePaddle/PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR)

候选用途：

- 扫描PDF和图片文字识别；
- 需要文本或表格坐标的结构化提取；
- 表格、公式、印章、复杂拍照文档等样例评估。

OCR结果一律先标记为`ocr-verbatim`。低质量扫描、罕见型号、数字、单位、印章和手写内容必须抽查，不能因工具输出为Markdown或JSON就自动视为准确。

### 工具组合

复杂资料可以采用：

```text
原生文本层
→ 版面解析
→ 仅对缺失区域OCR
→ 页面视觉核验
```

不要对已有可靠文本层的全部页面重复OCR，以免引入新错误。

## 4. 音视频

### Whisper

官方项目：[openai/whisper](https://github.com/openai/whisper)

本工具只作为内容运营准备原始逐句稿的候选方法，不是本Skill默认由Codex自动执行的步骤。是否使用、使用哪个工具、转写哪些时间范围，由内容运营结合公司数据规定决定。

候选用途：

- 多语言语音识别；
- 视频和音频的初步转写；
- 为原文证据提供时间段定位。

转写结果属于识别稿。内容运营负责保存原始输出、记录工具和范围，并初步核对产品型号、人名、数字、单位、专业术语和重叠说话。需要处理媒体文件时同时评估FFmpeg等音视频依赖；需要上传外部服务时先执行G2。

已有官方字幕或逐字稿时，由内容运营优先利用并与音频抽样核对，不重复全量转写。运营交回原始逐句稿或字幕稿后，Codex才按资料处理规则建立清理版、翻译或原文证据。

## 5. 在线研究与关键词数据

在线研究可能需要三类接口：

| 接口类型 | 用途 | 必须确认 |
| --- | --- | --- |
| 搜索接口 | 查找官方、标准、论文和行业来源 | 覆盖地区、排序、使用条款、结果可追溯性 |
| 网页读取 | 获取指定页面正文和元数据 | robots、版权、登录权限、发布日期 |
| SEO关键词数据 | 搜索量、趋势、难度、SERP和排名 | 数据提供商、地区、日期、字段定义、额度 |

在公司确定数据供应商前，不把任何模型搜索结果当作正式关键词数据，也不虚构搜索量。接口输出必须保留提供商、查询、地区、语言、日期和原始字段。

Deep Research类能力适合形成研究候选，不应绕过来源质量评分和正式知识准入。

公开行业研究可包含免费报告和付费报告的免费公开摘要页。只使用页面公开展示的摘要、日期、市场范围和数据，不声称已读取付费正文，也不绕过登录或付费墙。市场、趋势、竞争和消费者偏好默认优先最近24个月的资料；旧资料只有作为仍有效的法规/标准、权威基础研究或历史背景时才例外，并明确标记。

## 6. 同步工具

Obsidian官方列出的常见路线包括：

- [Obsidian Sync](https://obsidian.md/help/sync)：官方同步服务，可使用远程库、共享库、选择性同步和版本历史；
- [OneDrive等第三方云盘](https://obsidian.md/help/sync-notes)：Windows/macOS可用，但要让库始终保留在本地，避免文件按需下载造成缺失；
- Git：有清晰版本历史，普通使用通常需要提交、推送和拉取，自动化需另行建设；
- Syncthing等本地同步：需要自行负责设备在线、冲突、权限、备份和公司审计入口。

不要同时用两种同步服务处理同一个库。同步不等于备份；仍需独立的恢复策略。

具体方案必须通过多人并发、离线修改、大文件、误删恢复、权限隔离和审计快照测试后再推广。

## 7. 选型试验

不要先全公司安装。建立包含以下样例的小测试集：

- 带文本层的普通PDF；
- 扫描PDF；
- 多栏PDF；
- 简单表格和多层表头；
- 大型Excel；
- 图表、流程图和产品图片；
- 中英文混合、型号和单位；
- 视频或音频；
- 一个损坏、缺页或异常文件。

对候选工具记录：

| 项目 | 内容 |
| --- | --- |
| 工具与版本 | 实际版本和运行方式 |
| 文件类型 | 测试样例 |
| 原文准确性 | 漏字、错字、乱序 |
| 定位能力 | 页码、坐标、单元格、时间段 |
| 结构保留 | 标题、表格、图表、图片 |
| 运行成本 | 时间、Token、CPU/GPU、API费用 |
| 数据边界 | 本地或外传 |
| 人工复核量 | 需要核对的比例和高风险项 |
| 结论 | 推荐、条件使用或淘汰 |

只有通过代表性样例的工具组合才进入正式处理流程。
