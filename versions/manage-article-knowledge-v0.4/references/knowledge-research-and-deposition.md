# 调研与知识沉淀

## 目录

1. 固定检索优先级
2. 真正缺口判断
3. 自动外部调研
4. 来源质量与事实边界
5. 知识沉淀矩阵
6. 行业知识来源分区

## 1. 固定检索优先级

每篇文章按以下顺序查找：

1. 正式知识中的`CLAIM`登记，用于检索相关稳定事实、规则、范围和证据定位；
2. 客户源文件与客户官网中尚未提取的相关部分；
3. 已有但未正式沉淀的外部调研；
4. 新的外部调研。

客户源文件与客户官网同属可信的客户一手来源，二者并列，官网没有更高的默认优先级。按内容相关性、版本日期、详细程度和适用场景选用；发生冲突时并列记录依据、日期和差异，不自动用官网覆盖源文件。来源可信性与内容公开权限分开判断。

前一层能够满足需求时，不为同一事实重复处理下一层。已有外部调研再次使用前检查来源、日期、适用范围和与客户资料的冲突。

## 2. 真正缺口判断

以下情况不是知识缺失：

- 相关客户文件尚未处理；
- Codex尚未完成可靠提取，或必要的运营提交稿尚未提供；
- 已定位页面尚未按确认范围提取；
- 已有外部调研尚未重新核验。

只有本地候选完成必要处理后仍不能支持文章主张，才标记真实缺口。把缺口区分为：

- 客户专属事实：只能向客户源文件、客户官网或客户确认获取；
- 公开行业知识：可以外部调研；
- 可删除或改写的文章主张：不必为了大纲形式强行补知识。

## 3. 自动外部调研

节点4先记录条件式外部调研决定。真实缺口出现后，主Agent核对该决定；只有决定为`开展`或当前问题处于`仅研究指定问题`的批准范围内时，才按文章或批次向用户发送一次可见的非阻塞通知，至少说明：

- 哪些大纲主张仍有真实缺口；
- 为什么正式知识、客户资料、客户官网和已有外部调研不能覆盖；
- 调研Agent准备回答的问题、优先来源类型和时间范围；
- 调研结果只支持公开行业知识，不能替代客户来源证明企业事实。

通知后在已批准问题范围内开展公开调研，不需要用户逐链接批准。节点4决定为`不开展`时保留缺口并进入文章前审核；没有决定或新问题超出已批准范围时，只补充确认新增调研问题。调研实质改变大纲、涉及企业专属事实、需要登录/付费授权、权威来源冲突、来源可靠性不足或公开边界不明时，仍暂停受影响部分请求决定。

随后由调研Agent：

1. 搜索原始机构、官方标准、政府、研究机构、权威行业组织、原始企业页面或可靠专业媒体；
2. 打开真实直达页面；
3. 记录页面身份、发布/更新日期、访问日期和能支持的具体内容；
4. 自动提取依法且在当前授权下可取得的可见正文；
5. 分别保存原文证据稿和研究整理稿，禁止只保存Codex总结；
6. 对动态信息标记数据日期；
7. 把相关结果纳入文章前知识审核。

不要求内容运营逐链接选择是否纳入。公开页面先用Codex原生语义网页读取保存主内容，脚本交互或视觉状态再用浏览器核验；不得把整页DOM压平文本保存为原文证据。登录、付费墙、反爬、脚本渲染失败、页面损坏或正文无法可靠取得时，请运营优先提交其有权取得的HTML/PDF固定件或复制可见主正文；只有登录态、关键交互状态或其他方式不适用时才使用Web Clipper，并给出明确提交位置。所有取得方式均须通过同一网页质量闸门。

每个调研来源按稳定调研ID保存两层文件：

```text
04_资料与证据/50_外部调研/[调研ID]/
├── 10_网页或文章原文.md
└── 20_调研整理与核验.md
```

`10_网页或文章原文.md`至少记录页面标题、发布机构、直达URL、发布/更新日期、访问日期与时间、获取方式、语言、访问限制、内容指纹、已取得可见正文和未取得范围。正文按来源顺序原样保存，不在该文件内清理、翻译、总结或补齐。只能取得摘要或片段时标记`原文不完整`，不得把摘要扩展为全文结论。

`20_调研整理与核验.md`记录来源可支持和不能支持的主张、数据日期、冲突、使用限制、清理/翻译/结构化过程及最终去向。整理稿中的每项结论必须定位到原文证据；原文证据缺失时只能保留为未核验候选，不能进入写作输入或正式知识。

## 4. 来源质量与事实边界

- 来源优先顺序通常为：原始官方页面或文件；政府、标准机构、研究机构；权威行业组织；能够定位作者、日期和原始依据的专业媒体。后一层不能无说明地替代可取得的前一层。
- 每个实质性来源记录页面或文件名称、发布机构、发布或更新日期、直达URL、访问日期、它能够支持的结论和不能支持的范围。
- 网页或文章原文证据与Codex整理稿必须分开保存；链接、标题或摘要不能替代取得的正文证据。
- 搜索结果页、聚合页、无署名转载、AI回答和无法定位原文的摘要不能作为正式知识来源。
- 不绕过登录或付费限制；只能取得公开摘要时，明确记录信息不完整，不把摘要扩写成全文结论。
- 对价格、市场规模、政策、法规、趋势等动态信息优先使用较新来源；使用较旧材料时记录原因和数据日期。
- 高相关但被排除的候选来源，如果会影响审核判断，应记录排除原因，避免后续重复调查。
- 外部来源可以支持行业背景，不能证明客户自身能力、参数、案例、认证、价格或承诺。
- 与企业自身有关但没有客户来源的主张，不得写成企业知识。
- 无可靠来源或只是AI推断的内容不沉淀。
- 权威来源冲突时并列记录来源、日期和差异，不自行合并成一个确定事实。
- 动态数据可以进入带日期的数据快照，但默认不进入稳定正式知识；确需长期维护的动态政策使用单一当前文件、数据日期和复核条件。

## 5. 知识沉淀矩阵

| 内容 | 整理与核验完成后的处理 |
|---|---|
| 客户来源、可追溯、脱离当前文章仍可复用的企业知识 | 按稳定业务对象或稳定主题自动进入对应正式模块 |
| 已有正式知识被文章再次使用 | 只更新集中使用数据，不重复创建或复制正文 |
| 产品稳定属性 | 按SPU/型号固定知识ID，更新产品主数据或既有重点产品卡 |
| 本篇文章临时选品组合或对比角度 | 留在文章任务，不按文章主题建立正式产品文件 |
| 价格、库存、阶梯价、国家化预计送达时间 | 进入带日期的动态数据快照，不进入稳定产品正文 |
| 配送、退货、税务等动态政策 | 更新按适用范围组织的单一当前政策文件，旧版进入历史 |
| 企业提供的行业知识 | 自动进入`行业知识与洞察/10_企业提供/` |
| 来源可靠、原文证据完整、已核验且可复用的外部行业知识 | 无论文章是否使用，自动进入`行业知识与洞察/20_Codex外部调研/` |
| 外部调研未被文章使用，但已经达到正式知识准入条件 | 正常沉淀，只保持累计使用次数为0 |
| 只服务当前文章、复用价值低 | 留在文章任务及其来源记录 |
| 无可靠来源或只有AI推断 | 不沉淀 |
| 文章新增但无客户来源的企业事实 | 进入`05_数据与审核/30_异常与待决定/10_企业知识异常待处理/`，不沉淀 |
| 客户明确禁止使用的内容 | 不进入知识正文，只记录不含敏感正文的排除状态 |

## 6. 行业知识来源分区

企业提供和外部调研的行业知识不能混在同一文件。文件名和元数据都标明来源类型：

```text
02_正式知识/50_行业知识与洞察/
├── 10_企业提供/
│   └── 欧洲时尚零售与消费者偏好（企业资料）.md
└── 20_Codex外部调研/
    └── 欧洲时尚零售与消费者偏好（外部调研）.md
```

正式知识中的外部调研文件至少记录：

```yaml
source_type: Codex外部调研
source_urls:
data_date:
research_date:
verification_status:
last_updated:
```

结论旁保留来源和日期，不能只在文件顶部放一组无法对应到正文的链接。

正式知识文件是结构化核验登记层，不替代`04_资料与证据/50_外部调研/`中的原文证据和调研整理稿；沉淀后仍需保留逐块回链。普通链接不会自动加载被链接正文，因此新大纲命中正式知识后必须沿每个`CLAIM`的来源和精确位置回到证据层，选取包含条件、例外、表格或公式的完整语义块，不能把`CLAIM`短句直接扩写成文章材料。

## 7. 文章前审核后的自动沉淀执行

`05_数据与审核/10_知识沉淀与分流/10_知识候选分流.md`是唯一知识就绪队列。每完成一个当前清理稿、官网页面核验或外部调研整理与核验稿，立即把其中所有可独立判断的知识候选登记到该队列，不等待文章终稿。候选状态只使用：

- `待核验`：已提取或清理，但尚未通过来源、范围和限制核验；
- `可自动沉淀`：全部正式知识字段和来源定位合格；
- `部分可沉淀`：部分CLAIM合格，部分CLAIM存在异常；
- `异常待处理`：来源冲突、证据不足、无法验证或适用范围不明；
- `已沉淀`：正式文件、目录、总览和集中记录均已同步并通过校验；
- `不沉淀`：重复、动态快照、只服务当前文章或没有复用价值。

就绪候选分别来自：客户文件的当前源语言`清理与字段统一稿`及其`核验状态`；客户官网的当前页面原文证据、人工确认范围、交互状态与页面处理核验结果；外部调研的`20_调研整理与核验.md`及其对应`10_网页或文章原文.md`。每个候选还必须登记范围确认文件、范围版本、批准范围ID、原文证据状态、网页交互覆盖、表格完整性、源语言清理状态和独立审核状态。源文件登记、内容导航、URL清单、尚未核验的抓取结果或只有整理文件名而没有来源映射的内容，不视为可自动沉淀。

满足规则时，不再询问内容运营“是否沉淀”或“放在哪里”。Codex自动：

1. 把原文或结构稿拆成最小可独立判断的知识候选，并逐条写入`知识候选分流`；
2. 将候选标记为`待核验`，逐块核验直接来源、精确位置、适用范围、不可外推、数据日期和使用前复核；
3. 确定唯一知识ID、稳定实体/主题键、知识类型和唯一允许路径；产品按单个SPU/型号建键，不得使用文章选品组合；
4. 按稳定键查找同主题正式知识，判断新增、补充、冲突、动态数据或历史版本；
5. 把满足条件的候选标记`可自动沉淀`；存在部分异常时拆成合格与异常CLAIM并标记`部分可沉淀`，不得用一个异常阻断同实体的其他合格CLAIM；
6. 验证候选引用的节点4确认确由真实人工作出，批准范围ID存在，直接证据完整，网页交互与复杂表格已闭合，源语言清理和独立审核通过；任一失败时停止该块写入；
7. 在`02_正式知识/`之外生成或更新`CLAIM`草稿，每块填齐已核验事实/规则、适用范围、不可外推、直接来源、精确位置、数据日期和使用前复核；
8. 对草稿执行正式知识专项校验。内容字段、来源映射、实体键或预定路径不合格时，把对应CLAIM标记`异常待处理`并停止该块写入；
9. 专项校验通过后保留CLAIM草稿和事务计划，等待`20_文章前知识审核.md`完成；审核发现来源级/CLAIM级问题时，只退回受影响CLAIM修正并复核，其他合格CLAIM不受阻塞；
10. 文章前知识审核完成且受影响CLAIM已处理后，在事务暂存区准备正式文件、目录、总览、项目资料稿和集中记录，不提前修改当前状态；文章是否已经达到可写状态不作为沉淀条件；
11. 全部暂存结果通过校验后串行原子替换硬映射路径及集中记录；此事务不修改文章引用清单或使用次数，也不把写作输入作为事实来源。审核结论允许进入写作时，唯一写作输入在同一提交阶段另行生成；
12. 运行全项目校验，检查所有已核验整理结果是否均已分流、路径、`CLAIM`字段、来源逐块映射、总览矛盾、重复知识ID、断链、上游门禁和集中记录状态；
13. 全项目校验通过后才把候选标记`已沉淀`并把事件状态写为`completed`。任一步失败均恢复事务前状态，不得留下“文件没落位但状态已完成”或部分集中记录已更新的半事务结果。

`知识沉淀就绪`与`英语写作就绪`分开判断。前者要求人工范围确认、完整直接证据、源语言清理和来源审核通过；后者还要求非英语来源的英语忠实翻译通过。普通源语言知识不因英语翻译尚未完成而失去沉淀资格；正式知识若写入英语翻译版本，则已核验翻译是该翻译CLAIM的必要来源。

文章前知识审核“已完成且受影响CLAIM已处理”是正式写入的流程门禁，但文章是否已经达到可写状态不是沉淀条件。文章终稿和文章实际使用也不是沉淀触发器或企业事实来源。知识正文必须回溯到客户材料、客户官网或可靠外部原始来源。

文章写作输入、文章摘要、AI总结和最终文章都不是正式知识正文来源。企业提供行业知识回到客户源文件或源文件级清理稿；产品事实回到具体客户官网产品页；Codex外部调研回到独立保存的原文证据。正式知识按稳定主题组织，可以包含多份来源的`CLAIM`，但每一块独立映射来源与精确位置。完整原文、上下文、表格和公式留在证据层；正式知识既不得机械复制整份清理稿，也不得只保留一段无法判断条件和来源的摘要。

候选尚未实际写入、来源映射未完成或集中数据尚未同步时，不得标记为`已沉淀`。正常沉淀不再为每个知识块创建单独回执文件；只有沉淀失败、来源冲突或需要人工决定时才生成独立处理文件。

正式写入完成后运行项目校验。发现模块根目录误放、内容类型与子目录不符、`CLAIM`字段缺失、来源未逐块定位、总览与实际文件矛盾、重复知识ID、正式知识引用文章写作输入/最终文章、企业提供与外部调研混目录、断链、模板变量或重复当前清理稿时，沉淀状态保持`未完成`并返回对应处理步骤。

## 8. 异常与待决定

正常知识自动沉淀，只把以下项目留给人工：

- 企业事实没有客户来源；
- 权威来源互相冲突且会改变文章结论；
- 外部来源可靠性不足；
- 动态数据已经过期或日期不明；
- 客户公开权限不明；
- 证据不足，尚不能形成带适用范围、限制和精确来源的可核验`CLAIM`。

异常外部知识保留到月度维护，由知识库专员处理。是否被文章使用不属于异常条件；达到正式知识准入条件的外部调研必须自动沉淀。不得因为异常处理而删除原始调研或阻止已通过文章前审核的当前文章使用。
