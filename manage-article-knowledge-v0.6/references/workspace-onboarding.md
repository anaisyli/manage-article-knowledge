# 首次工作区盘点与批量建库

本流程用于“多个客户原始资料和写作文件已经存在，但尚未建立 v0.6 Obsidian 知识库”的首次接入。它不替代单项目初始化；只增加一个受限的发现和范围选择入口。

## 1. 统一配置与接入范围

内容运营固定使用下面这一段，不需要自己组织建库指令：

```text
请使用 manage-article-knowledge 盘点并批量建立知识库项目。

工作区扫描范围：
Obsidian知识库统一根目录：
Faithfulness结果统一根目录：
默认内容运营负责人：
接入范围：单个项目 / 指定项目 / 全部可识别项目
指定项目：仅选择“单个项目”或“指定项目”时填写
本次初始化上限：可选
```

`工作区扫描范围`必须是人工明确指定的一个或多个目录，不能是整台磁盘。`Obsidian知识库统一根目录`只用于新建知识库项目；它不等于客户原始资料目录，也不等于写作 Skill 的工作目录。Faithfulness 结果根目录可以被多个项目共用，项目、文章和版本子目录由知识库按合同自动创建。

接入范围的语义固定如下：

| 范围 | 行为 |
|---|---|
| `单个项目` | 只盘点并初始化人工指定的一个项目。 |
| `指定项目` | 只盘点并初始化人工列出的项目；其他候选只记录为未接入。 |
| `全部可识别项目` | 先完成轻量盘点和人工确认，再按确认结果分批初始化；不一次性读取所有资料。 |

可选的“本次初始化上限”只限制本次写入的项目数量，不改变候选识别结果。未达到上限的项目保留为`待处理`。

## 2. 只读盘点阶段

执行`scripts/discover_workspace.py`，只读取工作区范围内的目录、文件名、扩展名、少量文本网址和已有写作/审核目录标记。盘点阶段不得访问官网、解析全部PDF、建立Obsidian目录或修改客户原始资料。

`全部可识别项目`模式下，工作区扫描范围的每个直接子目录默认代表一个项目边界。内部资料、写作、终稿、已有知识库和临时目录只作为该项目的内部证据，不再重复列为项目。只有人工明确选择`单个项目`或`指定项目`时，才允许把人工点名的更深目录作为独立项目入口。

盘点完成后不得输出项目总表或两列候选表。必须按项目逐个生成“项目卡片”，每个项目固定检查五项建库信息和三项写作接入信息：

    ## P-001｜项目名称

    - 识别结论：已识别 / 待Codex进一步核对 / 未识别
    - 项目根目录：<绝对路径>

    ### 五项建库信息

    1. 项目名称：<值>｜已确定 / 由Codex整理命名 / 需人工补充
    2. 官网：<网址和发现来源>｜已确定 / Codex继续核对 / 需人工补充
    3. 客户原始资料路径：<绝对路径>｜已确定 / Codex继续核对 / 需人工补充
    4. Obsidian知识库统一根目录：<绝对路径>｜已由本次批量配置确定
       建库后Obsidian项目路径：由Codex按`[项目ID]_[企业中文名称]知识库`生成并登记；历史`_v0.6`目录继续兼容
    5. 内容运营负责人：<姓名>｜已由统一配置确定 / 需人工补充

    ### 三项写作接入信息

    6. 写作任务入口：<绝对路径>｜已确定 / Codex继续核对 / 待建立入口（确认后自动创建） / 暂不接入
    7. 终稿入口：<绝对路径>｜已确定 / Codex继续核对 / 待建立入口（确认后自动创建） / 暂不接入
    8. Faithfulness结果入口：<统一根目录及项目子目录规则>｜已确定，子目录自动建立

    ### Codex还会自动处理

    - <项目名称清理、内部目录归属、临时目录排除、任务字段和版本规则等；无则写“无额外处理”>

    ### 只需要你补充或决定

    - <只列Codex完成核对后仍不能决定的业务问题；没有则写“无”>

    - 本次状态：可以直接建库 / 补充后建库 / 本次暂不接入

项目卡片必须展示完整绝对路径，不能只写“资料位于某目录”。同一项目内有多个候选路径时，Codex先根据目录包含关系、文件内容线索和实际写作记录继续判断；只有仍无法唯一确定时才放进“只需要你补充或决定”。任务唯一键、字段映射、文章ID、版本目录和内部模板由Codex处理，不交给内容运营判断。

**卡片展示固定规则：**不要把写作任务或终稿概括成“未发现”。写作任务入口首次接入默认按重建展示，卡片主字段直接显示`待建立入口（确认后自动创建）`及拟建立的完整绝对路径；如果扫描到旧写作目录，只在“Codex备注”中列为旧候选，不把它当作本次已确认入口。终稿入口如果发现一个或多个候选，必须直接列出完整绝对路径并标记“待人工选择”或“由Codex继续判断”，只有确实没有候选时才显示`待建立入口（确认后自动创建）`。卡片中不再另写“写作任务/终稿：未发现”这一行替代上述字段。

临时渲染目录、LibreOffice profile、缓存、`.article-build`等只在所有项目卡片之后汇总为“已自动排除，不建库”，不要求人工逐项确认。最后只输出一份总摘要：可以直接建库、补充后建库和本次暂不接入各有多少个。二十个项目中若十八个没有问题，人工只确认整组，不逐项目确认十八次。

## 3. 人工确认阶段

Codex先完成目录归属和网址关系核对，只把仍无法唯一确定的问题交给人工：

- 官网未发现：要求人工提供官网；
- 多个原始资料目录：要求人工指出哪个属于该项目；
- 多个项目候选可能是同一客户：要求人工确认是否合并；
- 未发现写作任务或终稿：标记为“待建立入口（确认后自动创建）”，询问是否暂不接入写作；
- 待建立入口：说明绝对路径；批量授权后自动创建，不再另行索要一次确认。

官网缺失时，该项目不得执行官网画像或外部网站检索；可以保留为待补充项目，但不能用猜测的网址初始化正式官网字段。一个项目的歧义不阻塞其他已确认项目。

如果所有项目卡片都没有需要人工选择的终稿候选，内容运营只回复：

```text
确认所有标记为“可以直接建库”的项目；同时建立卡片中缺失的写作任务和终稿入口。
```

如果只处理其中一部分、需要补充信息，或卡片列出了多个终稿候选，使用同一短回执：

```text
确认所有标记为“可以直接建库”的项目。
补充/修正：<P-002：官网为……；P-006：使用资料目录……>
终稿候选选择：<仅在某项目有多个候选时填写；否则删除本行>
```

这两句是批量建库的授权口令。确认建库同时授权：对没有可复用候选的项目，在卡片拟定位置自动建立写作任务入口和终稿入口；写作任务入口不再另行确认。收到前只允许盘点，不得创建知识库或外部目录；收到后不再逐项目重复索要`确认建库`。如果终稿有多个候选，只有该项目的终稿入口需要人工选择；选择前不影响其他项目继续初始化和接入。若人工明确写“暂不接入写作”，才不建立该项目的外部写作入口。

## 4. 批量初始化阶段

收到上述授权口令后，运行`scripts/onboard_workspace.py --report <盘点报告> --confirm-batch`，只对接入范围内且已确认的项目建立标准骨架并同步第一轮接入。脚本返回`initialization_complete=false`和`must_continue=true`时必须继续以下步骤，不得把脚本成功退出解释为完整初始化完成：

1. 使用现有`initialize_project.py`为每个项目创建标准 Obsidian 目录和模板；`--project`使用统一根目录下由Codex生成的`Obsidian项目路径`，不把Obsidian知识库统一根目录本身当作`Obsidian项目路径`；
2. 官网已知时在同一次连续运行中尝试官网画像，并按[官网画像与初始化状态回写](website-profile-state.md)调用`record_website_profile.py`；若官网暂时不可访问，记录失败层级、重试条件和运行事件，但继续本项目后续本地建库步骤；
3. 原始资料留在原位置，知识库建立来源台账和机器索引，不复制或移动原件；
4. 将统一的 Faithfulness 结果根目录写入项目接入配置；
5. 对已存在的写作任务、终稿和审核结果候选执行三入口接入确认；没有可复用写作任务候选时，在卡片拟定位置自动建立空的写作任务入口并登记；没有样例的入口登记为`部分接入`，待真实文件出现后由启动检查校验；
6. 终稿只有一个候选时直接登记；没有候选时在卡片拟定位置自动建立终稿入口并登记；有多个候选时只暂停该项目的终稿入口，等待人工选择，不阻塞其他项目；
7. 自动建立的外部写作目录只建立空目录并登记，不改变写作 Skill 的原有规则或文件；批量授权后的这一步就是第二阶段接入，不再要求人工另发“确认接入”；
8. 来源索引、覆盖视图和项目校验完成后调用`record_website_profile.py --status reconcile --local-build-status complete`；画像成功时关闭初始化待办，画像失败时保留不阻塞本地建库的“官网画像待重试”，但不得把已完成的本地建库步骤报为失败；
9. 单个项目失败只记录该项目的错误，不回滚或阻塞其他项目。

知识库内部目录可以由初始化流程自动建立。初始化完成后，项目实际路径会写入`01_工作台/10_项目基础信息.md`和接入配置；不会在一个已经生成的项目目录里面再套一层同名知识库目录。外部写作任务、终稿和图片目录不能被移动、重命名或覆盖。由本批量授权自动建立的入口必须在项目接入配置中登记；多个终稿候选未选择前，不得把任一候选标为已确认。

## 5. 低 token 和分批运行

盘点和初始化必须分开运行。盘点只输出候选映射，不读取全部资料；初始化只处理人工选择的项目。可以在同一工作区重复运行：

```text
本次只初始化：客户A、客户C
其余项目保持待处理
```

后续运行继续使用同一份盘点结果，只处理新增或尚未初始化的项目。已建立的 v0.6 项目不重新初始化，转入既有项目启动检查和三入口接入流程。

## 6. 与单项目流程的关系

如果人工已经明确提供一个项目的五项信息，直接使用`SKILL.md`的单项目首轮门禁，不要求先运行工作区盘点。工作区盘点只是减少重复填写和手动建目录的批量入口；它不能放宽`确认建库`、官网缺失、路径不唯一或外部入口未确认时的暂停条件。

单项目和批量入口在确认后都必须调用同一个`initialize_project.py`，生成同一套固定v0.6项目目录和模板。批量模式只能改变“怎样发现、选择和逐批执行项目”，不得产生简化版目录、缩减模板或第二套初始化文件。新建目录不再附加Skill版本号；已有`_v0.6`目录原地兼容。
