# v0.6目录、命名与模板合同

本合同适用于所有新建v0.6项目以及明确接入v0.6的既有知识库项目。它解决“同一Skill生成不同页面和文件夹”的问题；接入既有项目不等于改造外部写作目录，既有差异只由校验器提示，不在没有用户明确要求时自动改名或迁移。

Skill运行期间不得为单个项目临时复制或改写本合同、项目模板或脚本。项目发现偏差时默认在项目级处理并记录；通用模板只有在人工明确同意Skill变更后才更新。

## 1. Obsidian知识库项目目录

新建Obsidian知识库项目目录统一命名为：

`[项目ID]_[企业中文名称]知识库`

历史兼容：已经存在的`[项目ID]_[企业中文名称]知识库_v0.6`目录继续视为合法项目，不要求改名、迁移或复制。项目使用的Skill版本以`01_工作台/30_版本与变更入口.md`中的当前Skill、SHA-256、目录结构和模板/schema为准，不以目录后缀判断。Skill升级时在原项目目录内执行版本检测和迁移记录，禁止仅因Skill版本变化把目录改成`_v0.7`或其他版本后缀。

项目ID必须是项目内稳定唯一键；企业中文名称使用项目基础信息中的正式名称。名称中不得使用空格、括号、临时日期、文章标题或“最新/最终”等状态词。项目ID中的日期和批次已经足够表达建立时间，不在文件夹名重复追加日期。

```text
03_正式知识/

    50_行业知识与洞察/10_企业提供/
    60_FAQ/
    70_其他/
  20_外部公共知识/
    50_行业知识与洞察/
04_文章任务/
  10_进行中/
  20_等待终稿/
  30_等待Faithfulness/
  40_已完成/
  90_归档/
    10_文章历史版本/
    20_已取消任务/
05_数据与审核/
  10_Faithfulness/
  20_知识库覆盖与缺口/
  30_异常与待决定/10_待客户补充/
  30_异常与待决定/20_源资料处理/
  30_异常与待决定/30_源文与事实异常/
  30_异常与待决定/40_Skill运行反馈/
  40_月度与交接/
  50_运行记录/
  60_版本归档/

    20_控制文件迁移历史/
    30_机器文件迁移快照/
    40_源资料版本记录/
```

`20_MinerU按需提取`可以为空，但目录必须存在。`04_文章任务`的状态目录必须存在；文章任务只放在与当前状态一致的一个目录中，完成状态变化时移动目录，不复制同一任务。

`90_归档`和`60_版本归档`只保存历史，不是第二套当前数据。文章内容发生实质变化时，修改前完整快照进入`04_文章任务/90_归档/10_文章历史版本/[文章ID]/`；正式知识、控制文件和机器schema的历史按对象进入`05_数据与审核/60_版本归档/`。每个历史包必须有`00_版本说明.md`和文件SHA-256，具体规则见[当前版本与历史归档合同](version-and-archive-contract.md)。

SQLite运行产生的`source-index.sqlite-wal`和`source-index.sqlite-shm`是临时文件，不是知识库受管文件；关闭连接后应清理或排除，不得出现在交接清单或人工导航中。

`source-index-exclusions.json`是来源正文排除的唯一机器入口。每条排除记录必须同时保存资料ID、源资料相对路径、SHA-256、`exclude_body: true`、通俗原因和记录日期；不得只在Markdown台账中写“正文已排除”。索引刷新必须复用该清单，指纹变化时停在待重新确认并保持正文未索引。

## 3. 固定文件名

### 工作台

```text
01_工作台/10_项目基础信息.md
01_工作台/20_当前待办.md
01_工作台/30_版本与变更入口.md
01_工作台/40_写作与Faithfulness接入配置.md
```

项目基础信息固定字段顺序为：项目ID、项目中文名称、项目英文名称、运营组、内容运营负责人、建立日期、官网、行业、行业填写方式、行业判断依据、主要业务与产品、目标市场与语言、公开限制、竞品信息限制、竞品限制继承规则、项目根目录、客户原始资料路径、Obsidian项目路径、第三方技术解析授权、已批准解析服务、当前资料时间范围、最近路径核验时间、当前Skill、AI知识库专员。`项目根目录`指外部运营项目文件夹，`Obsidian项目路径`指本知识库目录，两者不得混用；不得把“目标市场”和“目标语言”拆成另一套字段名。

其中`竞品信息限制`固定写为“禁止搜索、保存或沉淀具体竞品品牌、型号、特殊产品、参数、价格、案例、排名和比较结论；仅允许保留去品牌化通用行业知识、一般原理、方法说明和公开标准”，`竞品限制继承规则`固定写为“文章只能继承或进一步收紧，不得放宽”。该限制适用于外部调研、RES证据、正式公共Claim、文章`30/35`、覆盖页、月报和交接文件。

项目基础信息固定包含`## 官网初步画像`、`## 内容运营提交的其他企业相关网站`、`## 人工接触节点`和`## 七个业务模块入口`四个小节。官网画像缺失时由校验器提示；官网失败可写入同一小节的失败与重试字段，不另建项目级官网状态文件。其他企业相关网站只在内容运营明确提交后登记，不得与Codex外部调研来源混合。

当前待办固定使用表头：

`对象ID | 人能看懂的事项 | 当前阶段 | 是否阻塞 | 下一步由谁做 | 直达链接 | 更新/重开条件 | 最近更新`

版本入口固定使用`## 项目级变更`和`## 相关入口`两个小节；不得把它改成“项目级变更历史”或把入口散落到其他文件。

接入配置固定包含`写作任务接入 / 终稿接入 / Faithfulness接入 / 首次确认记录 / 自动运行与调度`五个小节。项目可以保留各组自己的外部路径和字段名，但配置必须明确外部任务唯一键、终稿绝对路径或任务映射、文章身份规则（写作方回传时优先沿用；缺失时由知识库按本合同补齐），以及文章版本专属Faithfulness结果目录。不得另建第二份同义接入配置。

### 源资料与正式知识

```text
02_源资料/源资料与可检索性台账.md
02_源资料/源资料搜索索引说明.md
02_源资料/source-index.sqlite
02_源资料/source-index-exclusions.json
02_源资料/50_外部调研证据/
03_正式知识/00_正式知识目录.md
03_正式知识/10_客户知识/00_客户知识目录.md
03_正式知识/20_外部公共知识/00_外部公共知识目录.md
```

正式知识文件命名为`[稳定实体或主题中文名].md`，不得用文章标题、文章ID、抓取日期、Claim ID或“读取/临时/最新”作为唯一命名依据。没有合格Claim时只更新目录，不创建空正式知识文件。

外部调研记录使用`02_源资料/50_外部调研证据/[RES-ID]_[稳定主题]/`，固定包含`10_来源原文证据.md`和`20_调研核验记录.md`。普通来源在两份文件中只保留最小必要内容；动态、高风险、冲突、关键或难恢复来源把`10_来源原文证据.md`作为可靠固定件。RES-ID不得按文章标题重复创建；同一稳定公共问题优先复用已有记录并按来源版本追加核验。

### 文章任务

文章ID固定为`[项目短码]-ART-[YYYYMMDD]-[三位流水]`，例如`TDDL-ART-20260820-001`。任务目录命名为`[文章ID]_[首次提交标题的简短可读名]`，可读名去除Windows非法字符并在创建后保持稳定；文章后来改标题时，只更新`10`和`40`中的标题，不随意改任务目录。文章不增加周/月文件夹层级，由文章ID日期和项目级月度审核完成时间管理。每个任务目录固定使用：

```text
10_文章知识需求.md
15_检索与知识准备记录.md
20_文章前知识审核.md
30_本篇知识库资料.md
35_写作素材来源索引.md
40_最终文章.md                 # 收到终稿后才有
50_文章知识使用与Faithfulness记录.md # 收到终稿时立即创建，导入结果后更新
```

`30_本篇知识库资料.md`是唯一写作事实输入；`35_写作素材来源索引.md`只保存明确“证据正文”行到Formal Claim的轻量追溯映射，不交给写作模型；`50_文章知识使用与Faithfulness记录.md`是写后唯一人读入口。三者不得改名、互换职责或合并。随文事实文件必须先进入来源、Claim和当前`30/35`，不得平行绕过。禁止使用v0.4旧名`01_文章要求与大纲.md`、`30_文章写作输入.md`、`40_最终文章与引用率.md`，也禁止继续新建已废弃的`25_文章证据与审核包.md`和`50_Faithfulness结果.md`作为当前文件。一个项目内同一文章ID只能有一个当前任务目录。

### 数据与审核

固定人工入口为：

```text
05_数据与审核/01_数据说明.md
05_数据与审核/30_异常与待决定/10_待客户补充/01_待客户补充事项.md
05_数据与审核/30_异常与待决定/20_源资料处理/01_源资料处理台账.md
05_数据与审核/30_异常与待决定/30_源文与事实异常/01_源文与事实异常台账.md
05_数据与审核/30_异常与待决定/40_Skill运行反馈/01_Skill反馈台账.md
```

机器文件名称固定为：

```text
05_数据与审核/10_Faithfulness/10_文章Faithfulness明细.csv
05_数据与审核/10_Faithfulness/20_Claim文章支撑记录.csv
05_数据与审核/10_Faithfulness/30_Claim文章支撑总表.md
05_数据与审核/50_运行记录/项目运行账本.jsonl
05_数据与审核/50_运行记录/10_写作任务接入记录.csv
05_数据与审核/50_运行记录/token_usage.jsonl（可选；默认停用）
```

Faithfulness CSV可以在没有外部结果时为空但保留标准表头。`项目运行账本.jsonl`在首次项目事务时由脚本创建；`token_usage.jsonl`默认不创建，只有项目负责人明确启用且供应商返回精确用量时才生成。不得另建“模型调用记录”“文章引用率总表”或按文章复制token账本。

`10_写作任务接入记录.csv`只保存外部任务唯一键到文章ID的防重复映射，不保存周计划全文，也不代替`10_文章知识需求.md`或当前待办。统一使用UTF-8 with BOM。

`05_数据与审核/20_知识库覆盖与缺口/01_知识库覆盖与缺口.md`是自动生成的当前视图，不是逐Claim沉淀台账。它递归扫描标准模块子目录，按模块汇总已有正式知识、已覆盖来源、相关MAT、已登记缺口和通过`35`确定性关联的文章；不复制Claim正文，不要求人工双写，也不得把全部文章机械重复到每一行。正式知识新增、更新、失效和文章状态事务以`05_数据与审核/50_运行记录/项目运行账本.jsonl`为机器留痕；月度可读的阶段性报告固定放在`05_数据与审核/40_月度与交接/`并链接当前视图。这样编号稳定，且正式知识、Claim文章支撑、当前覆盖视图和月度历史报告各有一个职责入口。

月度审核和交接审核分别使用`YYYY-MM_月度知识库审核.md`和`YYYY-MM-DD_项目交接审核.md`，只保留当前月份/当前交接记录的规范文件名。两者同目录存放但职责不同：月度审核呈现来源覆盖、知识缺口、当月处理和闭环；交接审核核对负责人、入口、环境、任务状态和未解决事项，不复制整份月度覆盖表。

## 4. 统一模板原则

- 同一个固定文件只允许一套标题、字段名、表头和状态枚举；项目可以在固定小节内追加事实记录，但不得另起同义字段或平行入口。
- 当前目录只保留一个现行版本；不得在当前目录创建`旧版`、`最终版2`、`backup`或按日期复制的平行文件。需要历史时使用固定归档路径和版本说明。
- 业务内容文件可以按稳定主题新增，但必须落入固定目录并遵循文件级模板；初始化不得预生成空Claim文件。
- 机器文件、临时文件和缓存不属于人工模板；只能由脚本维护，并在`01_数据说明.md`登记用途、编码、更新触发和查看方式。
- 既有项目的差异先在校验报告和项目运行账本中列出；改名、迁移、合并或删除必须单独获得用户指令并保留映射记录。
