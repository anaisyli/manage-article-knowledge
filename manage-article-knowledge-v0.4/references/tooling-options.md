## 1. 使用原则

- 优先使用原文件可靠文本层和格式专用读取能力。
- 工具输出是派生结果，不是独立事实来源。
- 任何工具都不能免除来源定位、内容指纹、样例验证和高风险抽查。
- 不把一个工具设为所有文件的永久唯一方法。
- 记录工具、版本、参数、输入范围、输出格式和已知限制。
- 工具或服务能力、许可证和价格可能变化，实施前重新核对官方说明。

## 2. 文档、Office资料与压缩包

### Office容器只读检查

在读取DOCX、PPTX、XLSX的可见正文前，运行：

```powershell
python scripts/inspect_office_container.py "资料文件.docx"
```

脚本只列出Office ZIP容器中的嵌入对象、媒体、图表、关系、候选原文件名、载荷签名和未识别对象，不写出或修改文件。它不是普通ZIP的通用递归清单器；普通ZIP、RAR和7z必须另行列出全部条目。`unresolved_embedded_object_count`不为0时，必须登记`MAT`并继续人工/工具核验；`ready_for_content_processing`只表示扫描器没有未识别Office嵌入项，不代表内容准确、完整或已获准处理。

### 压缩包只读清单与安全解压

- ZIP使用支持逐条读取元数据和校验路径的工具；RAR/7z只使用本机已有、获准且能只读列目录的7-Zip或兼容工具，不为单个项目静默安装软件。
- 解压前检查加密、损坏、文件数量、声明解压大小、压缩率、目录深度和嵌套层数；异常时停止并建立`MAT`，不靠试错无限展开。
- 只在系统临时目录解压明确需要处理的子文件；拒绝绝对路径、盘符路径、`..`路径穿越、符号链接/重解析点越界及写出临时根目录的目标。
- 不执行包内可执行文件、脚本、宏或安装程序；不把全量解压目录写回客户源文件路径或Obsidian。
- 缺少RAR/7z工具、密码或权限时由AI知识库专员决定处理方式；不得破解密码。确需客户提供密码或重新打包时先关联`CUS`，密码不写入项目正文、日志或运行账本。

### 原生读取

优先用于：

- DOCX标题、段落和表格；
- PPTX幻灯片、文本框和备注；
- XLSX工作表、单元格、公式和表头；
- 带可靠文本层的PDF。

复杂版面、扫描页、图表、流程图、复杂表格和关键嵌入图片仍需视觉或OCR核验；纯装饰图不进入正文，但不得以“无连续文字”跳过关键视觉关系。

### MinerU等可选解析工具

MinerU是PDF/PPT Markdown稿的首选自动解析工具。新电脑首次部署或更换Token时，API负责人双击`scripts/initialize_mineru.cmd`，隐藏输入Token和到期日；初始化器自动寻找Codex自带或系统Python，把凭证写入当前Windows用户环境变量，配置可访问的本机状态目录，并依次运行`probe`和`health-check`。只有无敏感信息测试PDF完成Token验证、上传、解析和下载才显示部署成功。脚本不在Skill、项目、日志或命令行中保存、显示或回传Token。部署成功并完全重启Codex后，内容运营不再运行脚本、配置路径或接触Token。

日常由Codex使用`scripts/run_mineru.py probe`检查当前进程能否读取MinerU凭证、到期日和本月检查状态，使用`health-check`验证完整链路，使用`extract`处理单份资料。底层脚本从Windows用户环境变量`MINERU_API_TOKEN`读取凭证，从`MINERU_API_EXPIRES_ON`读取`YYYY-MM-DD`到期日，从`MANAGE_ARTICLE_KNOWLEDGE_STATE_DIR`读取管理员初始化器配置的状态目录，并直接调用MinerU官方`v4` API；不依赖MinerU桌面版、Python CLI、`uvx`或MCP。Token过期时重新双击初始化器更换，不修改Skill。

新项目首次需要MinerU、新电脑、新Windows用户、Token新建或更换、每月首次维护和负责人交接时先运行`probe`。新环境、Token变化、当月没有成功状态或出现鉴权疑问时运行`health-check`；同一Windows用户、同一Token的当月成功结果跨客户项目及重复初始化复用。临时网络或服务失败写入`last_online_failure`，不得覆盖`last_online_check`中的最近真实成功记录；首次检查只有临时失败时标记在线验证待自动重试，不把本机部署、Token或运营流程判为失败。状态优先保存到初始化器配置的用户级状态目录；未配置时使用系统临时目录，并把`%LOCALAPPDATA%/manage-article-knowledge/`作为兼容回退。所有状态位置都不可读写时只失去月度复用与提醒去重，不得阻断MinerU调用。状态不进入客户项目，只含到期日、提醒状态、非可逆Token标识摘要和最近在线检查结果，不含Token、客户文件或解析结果。

距到期7天时提醒API负责人一次，距到期1天时再次提醒；不做提前30天提醒。过期后停止自动提交。Token缺失、过期或鉴权失败转API负责人；429转额度/频率检查；SSL提前断开、连接重置、超时、429和5xx在健康检查及安全GET请求层自动重试最多2次，间隔2秒和5秒，连续失败后再分流。正式文件创建任务的POST不盲目自动重试，避免重复任务和额度消耗；失败后先查询或由Codex判断是否可安全重提。`WinError 10013`、套接字访问被拒绝或沙箱禁止联网单独归为`codex-network-permission`，Codex立即用`run_mineru.py`最小命令前缀申请沙箱外重试，不登记为MinerU失败、不消耗普通网络重试次数，也不要求内容运营手工处理；管理员只需在首次弹窗核对并保存同类调用授权。上传403检查预签名地址、脚本和系统时间；单文件失败检查格式、大小、页数和损坏；仅输出质量不合格或单文件重试后仍无法处理时，才请内容运营补交Codex点名资料。API异常只阻断依赖相应PDF/PPT的提取，不阻断立项、网页处理或其他知识工作。

临时网络重试覆盖健康检查、安全GET、同一预签名地址PUT上传和结果下载，最多重试2次，间隔2秒和5秒。同一上传地址只重复PUT同一文件，不重新创建解析批次；正式文件创建任务的POST仍不盲目自动重试，避免重复任务和额度消耗。

调用流程固定为：请求预签名上传地址、上传原文件、轮询任务、下载结果ZIP、在系统临时目录安全解压、选择主Markdown、检查可读正文和本地图片引用、把本地图片引用替换为回看原PDF/PPT的定位提示、只归档最终主Markdown。默认使用`vlm`、中文语言、表格与公式识别；扫描件由Codex显式启用OCR。脚本只记录API版本、非敏感参数、任务ID和结果指纹，不记录Token、授权头、预签名上传地址或结果下载地址。

MinerU输出先进入系统临时目录。脚本只选择主Markdown，检查非空内容和本地图片引用，发布前移除或替换本地图片引用，只将主Markdown归入`Codex提取`；MinerU图片目录、调试文件和中间JSON不进入Obsidian。确需长期保存的视觉证据必须从原PDF/PPT单独选取最小截图并由证据页登记，不能批量复制MinerU assets。脚本通过只代表完成基础技术检查，Codex仍须结合原文件对页数、顺序、数字、表格、公式、图示和异常页段做证据核验。

自动调用不可用或结果不合格时，再请内容运营运行MinerU并把生成的`.md`原样发给Codex；运营不改名、不归档、不登记。Codex核对后归入`运营提交`。两种来源都不形成独立MinerU目录。PPT必要时可先固定为PDF。实际使用时记录：

- MinerU API版本、模型和非敏感参数；
- 原文件版本；
- 覆盖页数；
- 页码映射；
- 表格和跨页内容情况；
- OCR或阅读顺序异常；
- 稿件归属（Codex提取或运营提交）以及对应核验状态。

MinerU用于降低重复解析成本，不代表原文件已被完整、逐字、结构无误地还原。重要数字、图表、型号和页面关系仍回看原文件。

### 本地项目运行账本

使用`scripts/record_project_run.py`把关键运行追加到项目唯一的`90_归档/20_项目运行历史/项目运行账本.jsonl`。JSONL表示“一行是一条JSON记录”，所以运行增加时只增加一行，不会按运行生成新文件。MinerU脚本会自动调用它；其他流程在完成以下具有返工或审计价值的动作时调用：批量资料处理、正式知识首次沉淀或结构迁移、文章写作输入生成、终稿闭环、Skill迁移，以及导致流程中止或需要人工介入的失败。

普通阅读、搜索、打开文件和没有改变结果的细小检查不单独记账。每条只记录输入和实际读取文件的路径/指纹、Skill版本/指纹、开始与结束时间、工具及版本/参数、输出、重试、失败位置和人工介入原因；不把客户正文、密钥、访问令牌或完整命令中的敏感值写入账本。模型、Token和成本取得到真实值才写，取得不到保持`null`，不估算。账本由Codex和校验器维护，内容运营无需查看或编辑。

### 其他候选

根据环境和授权，可评估格式原生解析、MarkItDown、Docling或其他本地工具。轻量Markdown转换适合结构扫描和普通文本，不等于高保真版式还原；结构化JSON也不等于逐字无误。

## 3. OCR与扫描资料

可以使用PaddleOCR或环境中经过验证的OCR能力。复杂资料优先：

```text
可靠文本层
→ 版面解析
→ 只对缺失区域OCR
→ 页面视觉核验
```

不要对已有可靠文本层的全部页面重复OCR。OCR结果先标记`ocr-verbatim`；低质量扫描、数字、型号、单位、印章、手写和罕见术语必须抽查。

## 4. 音视频

内容运营不负责选择或执行字幕提取、音轨提取和转写。AI知识库专员根据`MAT`决定是否处理、使用已有字幕、提取音轨后转写、增加关键画面/屏幕文字核验或暂不处理。可以使用Whisper或其他获准工具，但必须记录：

- 工具和版本；
- 文件与时间范围；
- 是否上传外部服务；
- 语言；
- 时间码；
- AI知识库专员处理决定和审核状态；
- 产品型号、人名、数字、单位、术语和重叠说话异常。

已有疑似字幕/文字稿时先双向关联资料ID并标记`疑似配套稿，待核验`，不得凭文件名直接确认。知识库专员至少抽查开头、中段、结尾和高风险术语/数字；已有官方字幕且确认匹配时优先使用，不重复全量转写。Codex收到任何现成稿件后先原样保存，再建立清理、翻译或证据稿。

## 5. 网页与外部调研

- 已知客户官网页面时自动定位和提取，不让运营从零搜索。
- 公开网页优先记录直达URL、页面身份、发布/更新日期和获取日期。
- 登录、付费墙、反爬或正文不完整时，不绕过限制；请求Web Clipper稿、下载文件或可见正文。
- 外部调研的网页/文章必须保存可取得的原文证据文件和独立整理文件，不能只留下链接或Codex摘要。
- 搜索结果、AI回答和聚合摘要只能用于找来源，不能作为正式知识。
- 关键词或SEO数据必须记录供应商、地区、语言、查询日期和字段定义；没有确定数据源时不虚构搜索量。
- 动态市场、趋势和消费者数据优先使用较新资料；旧资料只在标准、法规、基础研究或历史背景仍有效时使用，并明确日期。

## 6. 保密与外传

所有项目默认继承团队对批准第三方技术解析服务的组织级授权；当前默认批准范围包括本Skill配置的MinerU官方API。该授权只覆盖完成技术解析所需的最小文件范围，不等于允许公开、训练、任意转发或将企业事实用于其他目的。只有项目明确禁止、服务不在批准清单或授权条件变化时才暂停升级，不逐项目重复询问。

新增或更换线上API、外部平台时，由维护负责人一次确认：

- 是否允许上传；
- 数据保留和训练使用；
- 服务地区；
- 访问控制；
- 账号和下载权限；
- 输出能否长期保存和审计。

没有组织级授权或项目明确禁止时使用本地工具或请运营在合规环境生成提取稿。只授予任务所需最小文件范围。

## 7. 代表性样例验证

工具投入正式流程前，用小测试集验证：

- 普通文本PDF；
- 扫描PDF；
- 多栏或跨页PDF；
- 简单表格和多层表头；
- 大型Excel；
- 带文字的图表、流程图和图片；
- 中英文混合、型号和单位；
- 视频或音频；
- 损坏、缺页或异常文件。

记录：

| 项目 | 内容 |
|---|---|
| 工具与版本 | 实际版本、参数和运行方式 |
| 文件类型 | 测试样例 |
| 原文准确性 | 漏字、错字、乱序 |
| 定位能力 | 页码、坐标、单元格、时间码 |
| 结构保留 | 标题、表格、图表、含文字图片 |
| 运行成本 | 时间、Token、CPU/GPU、API费用 |
| 数据边界 | 本地或外传 |
| 人工复核量 | 比例和高风险项 |
| 结论 | 推荐、条件使用或淘汰 |

只有通过代表性样例的工具组合才进入正式处理。
