# 内部运行清单

本文件只供Skill运行时按阶段读取，不复制到客户Obsidian项目，不生成新的运营表单，也不要求操作人员查看或填写。它只负责把现有规则变成稳定的执行顺序；业务规则、字段和模板仍以`SKILL.md`及其专项参考文件为准。

## 1. 每一阶段都执行的内部规则

1. 先识别当前项目、文章ID、当前节点和本次允许处理的范围，再读取本阶段对应的专项规则；不得凭上一次任务的记忆继续。
2. 开始前检查输入、版本、路径、证据和上一步状态；结束前检查产物、状态、链接、集中记录和下一步是否一致。
3. 能由现有证据和固定规则唯一判断的结构、命名、链接、编码、状态同步、可复算字段和确定性提取错误，由Codex自动修复并重新校验，不提交人工确认。
4. 不得自动补写事实、继承人工授权或替人工作业务选择。只有现有节点要求的范围、公开边界、客户事实、冲突解释或其他无法由证据唯一判断的事项，才进入相应人工节点。
5. 主Agent自动调度现有资料处理Agent、调研Agent和审核Agent；不为清单新增Agent，也不询问操作人员是否需要调用Agent。
6. 同一机器错误修复后立即重跑对应检查；仍失败时先缩小到具体文件、字段或CLAIM，只有缺少材料、授权或业务决定时才向人工提出一个具体问题。
7. 准备推进节点或声明完成前，运行项目校验并执行反馈信号检查。存在`ERROR`时自动修复可修项并重检；不得带错迁移状态。
8. 不建立逐次运行清单文件。需要追溯的关键运行只追加到项目既有运行账本，避免给操作人员增加维护对象。

## 2. 打开已有项目或初始化

**触发**：首次进入项目、初始化、版本变化、负责人交接或控制结构异常。

- 主Agent读取实际运行Skill版本和指纹；已有项目先核对版本入口、当前待办、固定目录、控制文件和未关闭SKFB。
- 初始化只读扫描客户目录；版本迁移先预览差异并保护业务正文和证据。
- 有Office容器、压缩包、媒体或图片时，按来源扫描规则自动分类；只有无法可靠处理或需要业务判断的部分建立MAT。
- 初始化导航必须实际读取可读文件的最小结构和语义摘要；“不全量提取正文”不等于“不读取内容”。完成前检查内容位置表没有通用占位语句或未替换变量。
- 完成条件：项目结构、入口、版本、当前状态和必要台账一致，项目校验无`ERROR`；没有新增人工确认节点。

读取：`project-and-knowledge-structure.md`、`source-processing-rules.md`、`obsidian-governance-details.md`；版本变化时再读`version-migration-and-skill-maintenance.md`。

## 3. 接收文章需求与资料路由

**触发**：收到一篇或多篇文章的关键词、标题、大纲或其他要求。

- 主Agent为每篇文章建立独立ID和任务目录，按`正式知识 → 客户源文件/官网 → 已有外部调研 → 新外部调研`检索。
- 复用正式知识时沿CLAIM回到证据层；不得把正式知识摘要直接当写作正文。
- 多篇文章共享来源处理结果，但不合并文章范围、审核、写作输入或终稿记录。
- 完成条件：每篇文章都有明确需求、当前节点、资料命中、预计缺口和下一步。

读取：`article-workflow.md`、`knowledge-research-and-deposition.md`。

## 4. 资料就绪检查

**触发**：文章已有需求，需要确认实际输入是否可处理。

- 主Agent自动复用合格稿，自动调用已批准的解析能力，并核对原文件、版本、页数、顺序和基础质量。
- 全部就绪时后台继续，不展示新的确认口；自动取得失败或质量不合格时，只点名缺少的具体材料及最短操作方法。
- 资料处理Agent只在有新来源或已有稿需要处理时执行；不为“形式完整”重复处理同一版本。
- 完成条件：所需输入合格，或具体失败项已经挂起且不影响其他独立范围继续。

读取：`tooling-options.md`、`source-processing-rules.md`、`verbatim-evidence-rules.md`。

## 5. 范围与样本确认

**触发**：资料已就绪，准备正式提取正文。

- 资料处理Agent依据真实文档结构生成范围、复杂结构代表样本、网页交互状态、排除项、预计缺口和条件式调研范围。
- 主Agent检查对象是否明确到文章ID、范围版本、范围ID和样本组ID，再进入既有节点4人工确认。
- 通用“继续”、其他节点回复或Agent结论不得替代本次范围确认；新增材料或新结构只重开受影响范围。
- 完成条件：真实人工确认记录完整，且后续处理严格限制在批准范围内。

读取：`article-workflow.md`、`verbatim-evidence-rules.md`、`task-and-output-templates.md`。

## 6. 提取、清理、翻译与候选准备

**触发**：节点4范围与样本已经确认。

- 资料处理Agent按源语言提取和清理；来源不是英语时另建英语忠实翻译稿，已有英文保持原样。
- 自动完成表格、结构、来源映射、项目资料稿和候选分流；确定性提取错误自动纠正，事实风险只挂起受影响CLAIM。
- 审核Agent独立核对原文件、网页状态、复杂结构、语义漂移、静默改动和反例；主Agent不把自审当独立审核。
- 主Agent只准备CLAIM草稿、门禁记录和原子事务计划，不在文章前审核完成前写入正式知识。
- 完成条件：来源证据、源语言清理、必要翻译、候选门禁和独立审核状态明确。

读取：`derived-materials-and-translation.md`、`verbatim-evidence-rules.md`、`multi-agent-orchestration.md`、`knowledge-research-and-deposition.md`。

## 7. 条件式外部调研

**触发**：本地相关资料处理后仍存在真实公开知识缺口。

- 主Agent先核对节点4的调研决定；已覆盖的问题发送一次非阻塞通知后自动调度调研Agent。
- 决定不开展时保留缺口；新问题超出批准范围时只补充确认新增范围。
- 调研Agent保存可取得的公开原文证据和独立整理稿，不用公开资料修复客户企业事实。
- 完成条件：每项已批准问题都有证据、限制或明确失败说明；未批准问题没有被静默扩大。

读取：`knowledge-research-and-deposition.md`、`multi-agent-orchestration.md`。

## 8. 文章前审核、正式沉淀与写作输入

**触发**：本地处理和必要调研已经完成。

- 审核Agent独立检查大纲覆盖、来源、冲突、公开风险、遗漏、反例和受影响CLAIM；主Agent生成文章前审核。
- 审核完成后先修正并复核受影响CLAIM，再原子沉淀全部来源合格CLAIM。文章是否达到可写状态、最终是否采用，不作为沉淀门禁。
- 只有审核结论允许进入写作时才生成唯一写作输入；审核Agent逐来源块完成保真复核。
- 写入正式知识前、生成写作输入草稿前和交付前运行项目校验；机器可修复问题自动修复并重检。
- 完成条件：沉淀事务完整提交或完整回滚；写作输入仅在就绪时生成，且两类产物互不作为事实来源。

读取：`readiness-and-maintenance.md`、`knowledge-research-and-deposition.md`、`article-workflow.md`、`multi-agent-orchestration.md`。

## 9. 写作后闭环、维护与反馈

**触发**：收到最终文章，或进入月度维护、负责人交接、版本迁移和Skill反馈维护。

- 主Agent按CLAIM核对文章实际使用，记录正式提供的引用率并同步唯一集中数据；不从文章反向沉淀企业事实。
- 月度和交接只汇总现状、异常、MAT、未关闭反馈和运行环境，不新增评分或确认节点。
- 用户纠正、规则冲突、重复绕行或校验漏报出现时，自动登记SKFB；能由现行规则唯一判断的执行性问题自动进入维护和回归。
- 完成条件：文章状态、总览、当前待办、集中数据、运行账本和版本事件一致，项目校验无`ERROR`，反馈信号检查完成。

读取：`governance-and-citation-metrics.md`、`readiness-and-maintenance.md`、`version-migration-and-skill-maintenance.md`。

## 10. 自动恢复与人工边界速查

| 情况 | 默认动作 |
|---|---|
| 断链、表头、编码、状态同步、合法值或固定入口错误 | Codex自动修复并重跑校验 |
| 可由同一来源唯一纠正的提取/OCR错误 | 自动纠正提取结果，保留原始证据与修正记录 |
| 外部网络或服务临时失败 | 按现有脚本重试或降级，不要求内容运营判断技术原因 |
| 缺少明确文件、权限或登录正文 | 点名缺项和最短补充方法，只挂起受影响范围 |
| 范围扩大、新结构、新调研问题 | 只回到现有节点4确认受影响部分 |
| 客户事实、公开边界、来源冲突或多种合理解释 | 进入现有文章前审核或对应人工岗位决定 |
| 项目校验仍有`ERROR` | 不推进状态；继续自动修复可修项，剩余项精确报告 |
