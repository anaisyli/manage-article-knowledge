# 外部调研执行与沉淀合同

本合同只约束 Codex 外部公共知识调研。它不恢复 v0.4 的固定人工节点、逐链接批准或强制多Agent。外部调研仍按一个具体公共知识问题执行，不能替代客户来源证明企业专属事实。

## 0. 竞品信息排除门禁

项目级竞品限制默认开启，文章只能继承或进一步收紧，不能放宽。检索词、检索目标和来源筛选不得指向具体竞品品牌、型号、特殊产品、价格、案例、排名或比较页。偶然命中的竞品页面或含竞品特定表达的内容不得保存为RES证据、正式Claim、`30/35`或报告；只在调研核验记录或项目运行记录中写“竞品特定信息，未采用”及类别，不保留可识别名称、链接或原文。

普通行业来源若顺带出现具体品牌/型号，只有不依赖该特定对象、脱离后仍能独立支持通用结论的连续原文才可保留；应排除涉及特定对象的句子，并在核验记录中说明“已去品牌化，通用结论独立成立”。不得把竞品宣传、产品页或对比表改写成通用行业事实，也不得通过来源标题、URL或引用片段间接保留其身份。

## 1. 调研触发与队列消费

外部调研有两个发现入口，但只有一个触发门槛：先完成已有正式Claim、客户源资料索引、客户官网、客户关联网站和已有外部公共Claim五层检索；仍存在的稳定公共知识问题必须先登记`gap_key`和文章，再根据规则得到`观察中`或`待外部调研`。只有状态已经是`待外部调研`且适用任务没有禁止新外部调研时，才消费队列。`允许`只代表权限，不是触发器；不得据此研究`观察中`缺口。

- **写作前入口**：标题、主问题或一级/二级主要大纲发现缺口后先登记；达到门槛的，在同一文章知识准备事务中、生成`20/30`前立即调研。开始前在`15_检索与知识准备记录.md`写明`gap_key`、问题、范围和`已开展`。
- **写作后入口**：Faithfulness的unsupported完成归组、前五层复查和缺口登记后，新增`待外部调研`项在导入完成后作为独立知识维护事务执行；更新关联`50`中的治理状态/回链、缺口记录和项目运行账本，但不得改变原Faithfulness判断、分数、哈希或当前`15/20/30/40`内容。
- **维护入口**：此前因禁止、失败或其他真实阻塞未完成的`待外部调研`项，在后续相关文章准备、维护处理或月度行动时继续消费；`观察中`只累计不同文章次数，不进入调研。
- **知识重整入口**：`outline_refresh`只从当前标题、大纲和本轮五层检索重新建立问题清单。归档`50`、旧GAP和旧版知识文件不读取、不作为问题提示或当前状态来源；本轮确认具体问题后，才查询当前缺口台账去重并决定是否调研。每项都在`15`记录本轮问题、当前大纲关系和本轮证据；仍相关时，在本轮开展调研并形成RES原文、核验记录和正式外部Claim。完成后重新生成`15/20/30/35`，不得复制历史文件或继承旧结论。

禁止新调研时保持缺口状态并记录限制，不伪造已研究结果。写作Agent自行联网搜索没有`gap_key`、`RES-ID`、原文证据和核验记录，不属于本Skill外部调研，也不得事后补记成写作前证据。

模板结构与汇总计数属于可确定的格式问题，可以修复后复验。收口器不得补写本轮研究结论、沿用旧复核行、继承旧缺口状态或把阻塞改成通过；本轮待调研清单不完整就报告缺项，研究证据未形成就保持阻塞。只有外部来源确实不可访问、工具或权限失败、权威来源冲突、证据无法可靠取得或事实范围不能唯一确定时，才记录调研失败并按本合同的失败路径处理。

## 2. 外部来源选择顺序与一方来源权重

以下顺序只适用于“新的外部调研”内部选择外部来源，不是客户源文件与客户官网之间的可信度排序：

1. 原始官方页面或文件；
2. 政府、标准机构或研究机构；
3. 权威行业组织；
4. 能定位作者、日期和原始依据的专业媒体。

后一层不能无说明地替代仍可取得的前一层。搜索结果页、聚合页、无署名转载、AI回答和无法定位原文的摘要不是正式来源。

客户原始文件、客户主官网、关系已确认的客户关联网站和客户明确确认属于同等的一方证据。官网不自动高于客户文件，客户文件也不自动高于官网。认证、交期、性能、规格和其他数字在一方来源之间冲突时，必须并列保存来源、日期、适用范围和差异，进入ANM或人工核验；未解决前不得合并、选边、建立可用Claim或写入`30/35`。竞品信息排除是独立的项目公开限制：一方来源中出现竞品特定名称或数据时仍须隔离，不因来源身份放行。

## 3. 证据记录形态

每次调研使用一个`RES-ID`目录，把原文证据和调研结论分开保存。普通来源的两份文件都只保留最小必要内容，不为每个普通网页建立厚重档案；动态、高风险、冲突、关键或难恢复来源才扩展原文证据文件为可靠固定件。

```text
02_源资料/50_外部调研证据/[RES-ID]_[稳定主题]/
  10_来源原文证据.md
  20_调研核验记录.md
```

`10_来源原文证据.md`只保存来源身份、原文证据和取得范围，不写AI结论、翻译或补齐内容。动态、高风险、关键、来源冲突、难以恢复或普通页面无法稳定复现时，使用可靠固定件并记录内容指纹；只能取得摘要或片段时必须标记`原文不完整`，不得扩展成完整结论。

该文件中的“来源身份”表是`SRC-EXT-*`的正式登记入口。项目校验器从当前RES目录的这些文件读取完整来源ID；外部来源不进入只管理客户来源的`source-index.sqlite`。引用外部来源的正式知识、文章资料和历史归档必须能回查到这里的有效登记，不能只凭编号前缀视为存在。

## 4. 失败路径

登录、付费墙、反爬、脚本渲染失败、页面损坏或正文无法可靠取得时，记录失败URL、失败层级、时间、已取得范围和原因；不绕过限制，不把搜索摘要当证据。优先请求有权取得的HTML、PDF或可见主正文；只有关键登录态或交互状态不能用其他材料替代时才使用Web Clipper。失败来源不能形成可用Claim，状态保持`失败待补材料`或进入对应异常事项。

## 5. 形成正式知识的门禁

外部调研满足以下条件后，立即进入正式知识沉淀，不等待文章终稿或Faithfulness：

- 回答一个具体且可复用的公共知识问题；
- 原文证据已取得并可精确定位；
- 已明确来源支持什么、不能支持什么、适用范围、数据日期和使用前复核条件；
- 没有把外部知识外推为客户专属规格、产能、认证、案例、MOQ、价格或承诺；
- 已通过竞品信息排除门禁：Claim和证据不含可识别竞品品牌、型号、特殊产品、参数、价格、案例、排名或比较结论，且通用结论不依赖被排除的特定对象；
- `20_文章前知识审核.md`已完成，Formal Claim和项目校验通过。

沉淀到：

```text
03_正式知识/20_外部公共知识/50_行业知识与洞察/[稳定主题].md
```

正式知识只保存可复用的Claim、最小原文证据和边界，并回链`RES-ID`的`10_来源原文证据.md`与`20_调研核验记录.md`；完整来源原文仍留在`02_源资料/50_外部调研证据/`。Claim形成后，逐项对照GAP登记的整个问题范围：完整覆盖且无剩余范围才标`已解决`；只回答部分时标`部分解决`并写具体剩余范围；未取得有效证据时保持`待外部调研`。不得因有一个Claim就关闭整个GAP。在`related_governance_ref`保留全部关联`RES-ID`和正式Claim，并在项目运行账本记录沉淀事务。

### GAP、RES与Claim统一关联（GR-1）

两种发现入口及后续维护都复用同一GAP ID，不按文章或发现阶段新建同题缺口。先用`record_knowledge_gap.py --gap-key auto`登记：已有同题返回原ID，新题按项目短码和已占用末段最大流水分配，例如`GAP-P005-028`。历史GAP与RES目录保持原名；新RES目录使用`RES-ID_稳定中文主题`，不以“刷新”“v3”“本轮回读”代替主题。已有记录首次复用时，由知识库回源核验后补表，不要求人工逐条补录，也不批量迁移历史记录。

新建或当前复用的`20_调研核验记录.md`使用上面的GR-1字段和固定关联表。一行只写一个GAP ID；一份RES可有多行GAP，同一个GAP可由多份RES逐次回答。`关联缺口`顶部字段列出所有GAP ID；纯既有Claim回源复核写`无（仅复核既有Claim）`，表中GAP写`无`、主题写具体复核问题、处理结果写`仅复核`，不得伪造一个已解决GAP。已有缺口时，缺口主题取台账原题；已回答范围、尚缺范围由本轮证据判断，不能从标题猜测。Claim列优先写真实`CLM-EXT-*`编号，脚本解析其正式文件入口；未形成Claim写`无`。管道字符须在表格中转义为`\|`。

知识库生成RES来源和正式Claim之后，使用受管登记器维护每项关联（重复运行覆盖同一RES内同一GAP行，保留其他GAP及CSV已有关联）：

```text
python scripts/external_research_links.py --project <项目路径> --record <RES目录/20_调研核验记录.md> --gap-key <已有GAP ID> --answered <本次证据确实回答的范围> --remaining <具体剩余范围或无> --claims <已沉淀Claim ID列表或无> --result <待外部调研/部分解决/已解决>
```

仅复核使用`--gap-key 无 --topic <具体复核问题> --result 仅复核`，同样填写范围和Claim。登记器只记录知识库已核验的结论，不自动作事实判断或关闭GAP；它同步20顶部字段、固定表、配对10的关联缺口导航字段、CSV的RES/Claim回链并重建覆盖页；不改来源原文。随后知识库用`record_knowledge_gap.py`按整个缺口范围更新生命周期（解决状态须传`--resolution-scope`），继续项目原有运行留痕和校验。先保留可用证据，再决定整个GAP的状态；覆盖页按RES分别显示范围，不把多份研究自动合并成已解决。

覆盖页自动读取20固定关联表、CSV稳定ID和正式Claim文件，显示直达RES/正式知识、已回答范围及尚缺范围。旧无表记录只按顶部GAP或CSV明确RES引用建立导航，显示“未分项登记”，不推断解决范围。新表字段、GAP存在性、RES回链、Claim真实入口及剩余范围由项目校验器检查；历史缺少新表不阻塞现有项目，未知协议不自动降级。

外部公共Claim统一使用`CLM-EXT-[项目]-[主题]-NNN`编号；客户Claim使用`CLM-[项目]-[主题]-NNN`编号，两个命名空间分别计数。新增外部Claim只在同一`CLM-EXT-[项目]-[主题]-`前缀下取下一个连续编号，不得读取客户Claim编号，也不得跳号。每条外部Claim必须在自身区块内写出`### 最小原文证据`连续引用块；缺少该区块即使有`RES-ID`回链也不能形成正式知识。

## 6. 动态、冲突与不采用

- 价格、市场规模、政策、法规和趋势等动态事实必须写数据日期；旧来源须说明原因；需要长期复核的内容写复核条件，不当作无期限稳定事实。
- 外部来源之间或一方来源之间发生冲突时并列记录来源、日期和差异，不自动合并；会改变文章结论时进入ANM/人工处理或保持缺口未解决。不得把官网默认当作比客户文件更权威，也不得反向默认客户文件更权威。
- 高相关但被排除的来源记录排除原因，避免下次重复调查。
- 只有当前文章有用、来源不可靠、原文不完整、无法确定适用范围或只是AI推断的内容，不沉淀为正式知识。
